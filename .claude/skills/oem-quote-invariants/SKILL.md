# กฎเหล็ก — ระบบใบเสนอราคา/เอกสารภาษี OEM

ทุกข้อมาจากบั๊กหรือช่องโหว่ที่**เกิดขึ้นจริง**ในโปรเจกต์นี้

---

## 1. 🔴 ห้ามต้นทุน / margin / ราคารับซื้อคืน หลุดถึงลูกค้า

เอกสารที่ออกจากระบบนี้**ส่งออกนอกร้าน** สิ่งที่ห้ามโผล่:
`cost_piece` · margin ทุกตัว · `nre_cost` (ราคาค่าแบบแสดงได้ แต่**ต้นทุน**ค่าแบบห้าม) · floors/MOQ/เกณฑ์ภายใน · `approval_note` (เหตุผลที่ยอม margin ต่ำ) · `lost_reason` · `calc`/`rate_snapshot` ดิบ · ค่าแรงแยกขั้นตอน · ข้อมูลแฟลสก์ · **`buy_per_baht`/`kilo_buy` (ราคารับซื้อคืน)**

**⚠️ ต้นทุนเงินแท่ง = ราคารับซื้อคืน เป๊ะโดยนิยาม** (0079) แปลว่าตัวเลขรับซื้อคืน**อยู่ใน `cost_piece` แน่นอน** ปล่อย cost หลุด = เปิดส่วนต่างซื้อ-ขายให้ลูกค้าเห็น

**กันด้วยโครงสร้าง ไม่ใช่ด้วยวินัย:**
- หน้าพิมพ์รับเฉพาะ `PrintableQuote` / `PrintableReceipt` — **ห้ามรับ `OemQuoteRow` หรือ row ดิบจาก view**
- type พวกนี้**ประกอบทีละ field ห้าม spread** เพื่อไม่ให้ field ใหม่ในอนาคตหลุดตามมาฟรีๆ
- ห้าม import component ที่แสดงต้นทุน (เช่น `OemCalcBreakdown`) เข้าหน้าพิมพ์เด็ดขาด
- คอมเมนต์เตือนไม่ใช่ด่าน — **ด่านคือ type boundary**

**วิธีตรวจว่าหลุดไหม:** ยิงหน้า print จริงออกมา แล้วหา**ตัวเลขต้นทุนจริงจาก DB** ในผลลัพธ์ (ทั้งส่วนที่ตาเห็นและ payload ที่ streamed ไป client) ไม่ใช่แค่ grep คำว่า cost ในซอร์ส

---

## 2. ห้ามคำนวณเลขเงินใน client

ทุกตัวเลขมาจาก `oem_price_calc` / `oem_quote_save` / view ฝั่ง DB — หน้าจอแค่แสดงผล

เหตุผลที่ไม่ใช่แค่ความสวยงาม: การหารครึ่งของ 31,172.93 ได้ 15,586.47 + 15,586.46 (ต่างกัน 1 สตางค์)
ถ้า client คำนวณเอง เลขที่ผู้ใช้เห็นจะ**ไม่ตรงกับที่ DB บันทึก** แล้วเอกสารกับรายงานจะเถียงกันเอง

ข้อยกเว้นเดียวที่มี: `aggregateQuotePreview` ที่**บวกเลขที่ DB คำนวณมาแล้ว**เพื่อ preview สด — ไม่ได้คิดสูตรใหม่

---

## 3. ปัดเศษ: คำนวณตัวหนึ่ง แล้วอีกตัวเป็น "เศษที่เหลือ"

```sql
vat_base   = round(grand_total / (1 + vat_rate), 2)
vat_amount = grand_total - vat_base        -- ✅ เศษที่เหลือ
-- ❌ ห้าม: vat_amount = round(vat_base * vat_rate, 2)
```

ปัดสองตัวอิสระกันแล้วบางยอดจะคลาด 1 สตางค์ → **เอกสารที่ส่งลูกค้าบวกไม่ลง** ฝ่ายบัญชีลูกค้าตีกลับ

ใช้หลักเดียวกันกับ: มัดจำ/ยอดคงเหลือ · งวดชำระ (งวดปิดใช้ยอดคงค้าง ไม่ใช่คิด % ซ้ำ)
**invariant ที่ต้องจริงเสมอ:** ผลรวมของส่วนย่อย = ยอดเต็ม เป๊ะ ทุกยอด รวมยอดคี่

---

## 4. ราคาเงินแท่งไม่เป็นเส้นตรงตามน้ำหนัก

แท่ง 1 บาท 1,455 × 10 = 14,550 แต่**แท่ง 10 บาทจริง 13,718** (ต่าง 6%)
คูณราคาต่อกรัม/ต่อบาท = เสนอลูกค้าแพงเกินจริง แล้วลูกค้าเปิดเว็บร้านเทียบเจอทันที

**ต้องอ่านราคาแยกตามขนาด** จาก `silver_price_daily` (`bar_0_5_baht`/`bar_1_baht`/.../`kilo_sell_vat`)
และ **ห้ามใช้ `sell_per_baht`** — เป็น null ได้ตั้งแต่ 0074

ส่วนต่างจริงก็ไม่เท่ากันทุกขนาด: แท่งเล็ก 20-27% แต่ **1 กก. แค่ 8.4%** อย่าสมมติว่า margin เท่ากันทั้งกลุ่ม

---

## 5. ราคาไม่สด = ออกใบไม่ได้ ห้ามใช้ของเมื่อวานเงียบๆ

ราคาเงินแท่งดึงจากหน้าเว็บร้านวันละ 3 รอบ (09/13/20 เวลาไทย)
ถ้าวันนี้ยังไม่มีราคา → เข้า `missing[]` → ออกใบสถานะ quoted ไม่ได้

**ยอมให้ทำงานไม่ได้ ดีกว่าเสนอราคาผิดโดยไม่มีใครรู้** — ห้ามใส่ fallback ไปหยิบราคาวันก่อน

---

## 6. ด่านราย item กับด่านรวมทั้งใบ ทำหน้าที่ต่างกัน — อย่าสับสน

- **ด่านรายชิ้น** (`margin_charged` ต่อ item) = คุ้มครองงานผลิต **ห้ามผ่อนเด็ดขาด**
- **ด่านรวมทั้งใบ** = คุ้มครองจากส่วนลด ทำงานเมื่อมีส่วนลดจริง

**บทเรียนที่เจ็บมาแล้ว:** เคยผูกด่านรวมไว้กับ "ใบนี้มีงานผลิตไหม" ผลคือเติมของชิ้นละ 50 บาทเข้าไปใบเดียว
ก็ปลดล็อกใบมูลค่าเจ็ดหมื่นให้ไม่ต้องมีเหตุผลบันทึกไว้ได้
→ **เงื่อนไขต้องผูกกับคุณสมบัติที่เป็นเหตุผลจริง** (เช่น "มีรายการที่ตรวจ margin รายชิ้นไม่ได้ไหม") ไม่ใช่ตัวแทนที่หลวมกว่า
และ**อย่าผูกกับชื่อวัสดุตรงๆ** — สินค้าประเภทใหม่ในอนาคตจะถูกคุ้มครองเองโดยไม่ต้องมีใครจำมาแก้

**ด่านที่ไม่มีข้อยกเว้นเลย:** margin รวมติดลบ (ขายต่ำกว่าต้นทุนตัวเอง) — ปฏิเสธเสมอ ไม่ปลดล็อกด้วยเหตุผล

---

## 7. เอกสารภาษี — ข้อบังคับตามกฎหมาย ไม่ใช่ตัวเลือกดีไซน์

- **ใบกำกับภาษีต้องแยกจำนวน VAT ออกจากมูลค่าให้ชัดแจ้ง** เขียนแค่ "ราคารวม VAT แล้ว" ไม่พอ
- **ยังไม่จดทะเบียน VAT ห้ามเขียนคำว่าภาษีมูลค่าเพิ่มบนเอกสารเด็ดขาด** — ตัดสินจาก `seller_vat_registered` ตัวเดียว กันทั้งฝั่ง DB และฝั่งจอ
- **เอกสารที่ออกแล้วห้ามแก้** แก้ได้ทางเดียวคือยกเลิกแล้วออกใหม่
- **เลขที่เอกสารห้ามข้าม** ยกเลิกแล้วเลขเดิมต้องไม่ถูกใช้ซ้ำ
- ต้องมีครบ: ชื่อ+ที่อยู่+เลขผู้เสียภาษี+สาขา **ของทั้งผู้ขายและผู้ซื้อ**
- **snapshot ข้อมูลผู้ขาย/ผู้ซื้อ/อัตราภาษี ติดไว้กับเอกสาร** — พิมพ์ซ้ำอีก 5 ปีต้องได้เหมือนเดิมเป๊ะ ห้ามให้ view ไปดึงค่าปัจจุบันมาคำนวณสด
- ข้อมูลร้านไม่ครบ = พิมพ์ไม่ได้ (กันเอกสารไม่มีเลขผู้เสียภาษีหลุดถึงลูกค้า)

---

## 8. ตัวเลขที่บวกไม่ลง ห้ามหลุดถึงลูกค้า

ยอดคงเหลือติดลบ (มัดจำมากกว่ายอดสุทธิ) เกิดได้จริงเมื่อตั้งมัดจำเป็นยอดเงินแล้วยอดใบลดลงทีหลัง
DB **จงใจปล่อยให้ติดลบ** เพื่อไม่ซ่อนปัญหา — แต่ **หน้าพิมพ์ต้องบล็อก** ไม่ใช่แค่เตือน

และข้อความเตือนที่พูดกับพนักงาน ("ตรวจสอบก่อนส่งลูกค้า") ต้องมี `print:hidden` เสมอ
**เคยหลุดไปบนกระดาษที่ส่งลูกค้ามาแล้ว**

---

## 9. อย่าเดาข้อมูลที่ไม่มี

catalog 301 SKU มี `silver_weight_g` เป็น null ทั้งหมด → ตัวเลือก SKU **จึงเป็นแค่การติดป้ายชื่อ** ไม่ใช่ทางลัดกรอกราคา
เดาน้ำหนักจากชื่อ SKU = ราคาที่เสนอลูกค้าเพี้ยนโดยไม่มีใครรู้ตัว **แย่กว่าไม่เดา**

หลักเดียวกัน: ตัวเลข `unit_cost`/`list_price` ใน catalog ล้าสมัยหนัก (บางตัว "ต้นทุน" สูงกว่าราคาขายจริงวันนี้)
ใช้ได้เฉพาะ `margin_pct` ที่เป็นอัตราส่วน — **ห้ามเอาไปคิดราคา**
