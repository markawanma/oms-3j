# Content Workflow — UI Brief (สำหรับส่งให้ทีม/เครื่องมือออกแบบ UI ภายนอก)

> **ฉบับ 1.2 · 6 ต.ค. 2569** (1.2: ข้อความ LINE/สตอรี่กด "โพสต์แล้ว" ได้ไม่ต้องมีลิงก์ · คำตอบเจ้าของ §14) · (1.1 แก้จากฉบับ 1: อนุมัติก่อนถ่าย · "โพสต์แล้ว" ต้องมีลิงก์ · หยิบสัญญาณได้ทุกเวลา · เลขขั้นห้ามขึ้นจอ — ดู §4) · ร้านเครื่องประดับเงิน 3J · ระบบหลังบ้านชื่อ "3J Insight" (เว็บแอป ใช้บนมือถือเป็นหลัก)
> ไฟล์นี้คือ **workflow + โครงหน้าจอ + กติกา** ให้ผู้ออกแบบ UI สร้างหน้าจอชุดใหม่ของ "สายงาน content/แคมเปญ" ให้ครบวงจร
> **ไม่ใช่สเปกเทคนิค** — ไม่ต้องสนใจ database หรือ API · ข้อมูลตัวอย่างทั้งหมดในไฟล์นี้ **เป็นข้อมูลสมมติ**

## 0. บริบทสั้นที่สุดที่ผู้ออกแบบต้องรู้

- **ร้านขายเครื่องประดับเงิน 925 และเงินแท่ง** ผ่าน TikTok เป็นหลัก (มี LINE OA, Instagram, Facebook รอง)
- **ยอดขายส่วนใหญ่มาจากไลฟ์สดทุกคืน** (ช่วงค่ำ เวลาเริ่มไม่ตายตัว) ⇒ โพสต์/คลิปสั้น **ไม่ได้มีหน้าที่ขายตรง** มีหน้าที่ 3 อย่าง: **พาคนเข้าห้องไลฟ์คืนนั้น · ให้ความรู้ · รักษาลูกค้าเก่า**
- **ทีมจริงเล็กมาก**: เจ้าของ (ตัดสินใจทุกอย่าง เวลาน้อย) · คนไลฟ์ · ช่างในโรงงาน · งานร่าง/วิเคราะห์ที่เหลือทำโดย **AI ผู้ช่วย** (ร่างไอเดีย ร่างสคริปต์ ตรวจข้อเท็จจริง สรุปผลรายสัปดาห์)
- **ไม่ยิงแอด** ทุกอย่าง organic · TikTok **ไม่ให้ข้อมูลคู่แข่ง** ผ่านระบบ ⇒ ข้อมูลคลิปคู่แข่งต้องมาจาก **คนแปะลิงก์ + พิมพ์ตัวเลขที่เห็นบนจอ** หรือ AI สรุปจากเว็บ
- ภาษาในแอป: **ไทย** · เงิน: **บาท (THB)** · เวลา: **เวลาไทย**

### ปัญหาที่เจ้าของรู้สึก (ต้นเหตุของงานนี้)
1. ปฏิทิน/แคมเปญ **ดูแล้วใช้งานยาก**
2. **ไม่มีที่ดู research** ว่าคู่แข่งทำอะไร คลิปไหนดัง hook ไหนดี ช่วงนี้คอนเทนต์อะไรมา — และ **ไม่มีทางเอามาปรับใช้กับของเรา**
3. ไม่รู้ว่า **เริ่มที่ไหน ต่อที่ไหน**

## 1. หลักการออกแบบ (ใช้ตัดสินทุกจุดที่ไฟล์นี้ไม่ได้ระบุ)

| # | หลัก | หมายความว่า |
|---|---|---|
| P1 | **เปิดแอปแล้วรู้ทันทีว่าต้องทำอะไร** | หน้าแรกคือ "งานที่รอฉัน" ไม่ใช่ปฏิทิน · ปฏิทินเป็นหน้ารอง |
| P2 | **กดจบในที่เดียว** | การ์ดงานใน inbox ต้องตัดสิน/อนุมัติ/ตอบได้จากการ์ดเลย ไม่ต้องกระโดดหลายหน้า |
| P3 | **ของ 1 ชิ้นมีบ้านเดียว** | ชิ้นงานหนึ่งชิ้นแก้ได้ที่ "หน้าชิ้นงาน" ที่เดียว · หน้าอื่น (ปฏิทิน · บอร์ด · inbox) แสดงได้ และกด action สั้นๆ ได้ แต่ **ต้องใช้สถานะชุดเดียวกันเป๊ะ** |
| P4 | **ข้อมูลต้องไม่หล่นระหว่างขั้น** | หยิบคลิปคู่แข่ง → ไอเดีย → ชิ้นงาน → โพสต์ → ผลลัพธ์ ทุกขั้นพา **ลิงก์อ้างอิง เหตุผล hook ประเภทงาน** ติดไปด้วยอัตโนมัติ และย้อนกลับไปดูต้นทางได้เสมอ |
| P5 | **วงจรต้องปิด** | ผลลัพธ์ของโพสต์ต้องเดินกลับไปบอกว่า hook/รูปแบบไหนชนะ แล้วป้อนเข้าคลัง research |
| P6 | **AI ร่าง คนตัดสิน** | ทุกอย่างที่ AI ทำติดป้าย "AI ร่าง" · การอนุมัติต้องเป็นคนกด · ห้ามมีทางลัดข้ามขั้นอนุมัติ |
| P7 | **กรอกเร็ว** | ฟอร์มที่คนต้องกรอกบ่อย (แปะลิงก์ · บันทึกหลังไลฟ์ · กรอกยอด) ต้องเสร็จใน 1–2 นาทีบนมือถือ มือเดียว |
| P8 | **ตัวเลขที่ถูกต้องสำคัญกว่าตัวเลขที่ดูดี** | ยอดวิว **ห้ามเป็นตัวเลขใหญ่สุดบนจอ** · "ยังสรุปไม่ได้" คือสถานะปกติ แสดงแบบสงบ ไม่ใช่ error |
| P9 | **mobile-first, desktop-better** | ใช้ได้ครบบนมือถือ (ปุ่ม ≥44px) · บน desktop ใช้พื้นที่เป็น 2–3 คอลัมน์ (รายการซ้าย รายละเอียดขวา) |

## 2. "ของ" ในระบบ (Object model)

ผู้ออกแบบควรมองระบบเป็นวัตถุเหล่านี้ — **ทุกหน้าจอคือการแสดง/แก้วัตถุพวกนี้**

```
          ┌──────────────┐        ┌──────────────┐
          │  สัญญาณ       │◄──────►│  Hook         │
          │  (Signal)    │  ถอดโครง │  (คลัง hook)   │
          └──────┬───────┘        └──────┬───────┘
                 │ หยิบมาเป็น              │ ใช้ใน
                 ▼                        ▼
          ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
          │  ไอเดีย        │──────►│  ชิ้นงาน       │──────►│  โพสต์          │
          │  (Idea)      │ อนุมัติ  │  (Piece)     │ โพสต์แล้ว│  (Post)       │
          └──────┬───────┘        └──────┬───────┘        └──────┬───────┘
                 │ อยู่ใต้                  │ อยู่ใต้                  │ วัดผล
                 ▼                        ▼                        ▼
          ┌──────────────────────────────────┐        ┌──────────────┐
          │  แคมเปญ (Campaign) — มีสมมติฐาน    │◄───────│  ผลลัพธ์ +     │
          └──────────────────────────────────┘ verdict │  บทเรียน        │
                                                      └──────┬───────┘
          ┌──────────────┐                                   │
          │ บันทึกหลังไลฟ์   │──── คำถามซ้ำจากลูกค้า ──────────────┘──► กลับเป็นสัญญาณ
          │ (Live log)   │──── โฮสต์คืนนั้น (ใช้กำกับการอ่านผล)
          └──────────────┘
```

| วัตถุ | คืออะไร | ฟิลด์หลักที่ต้องแสดง |
|---|---|---|
| **สัญญาณ (Signal)** | วัตถุดิบทุกชนิดที่อาจกลายเป็นคอนเทนต์ · มี 5 ชนิด: **คลิปอ้างอิง** (ของคู่แข่ง/คนอื่น) · **เทรนด์** (จาก AI เรดาร์รายวัน) · **คำถามจากไลฟ์** · **โมเมนต์ช่าง** (ของแปลกในโรงงาน) · **บทเรียน** (จากผลลัพธ์ของเราเอง) | ชนิด · แหล่ง (ใครเห็น) · วันที่ · ลิงก์ · สรุป 1 บรรทัด · สถานะ (ใหม่ / หยิบแล้ว / ไม่ใช้ / เก็บไว้ก่อน + เหตุผล) |
| **คลิปอ้างอิง** (สัญญาณชนิดหนึ่ง) | คลิปของคนอื่นที่น่าสนใจ | ลิงก์ · บัญชี · แพลตฟอร์ม · ยอดที่เห็น (วิว/ไลก์/คอมเมนต์/บันทึก/แชร์ — รับค่าย่อเช่น "16K") · ผู้ติดตามของบัญชี · **ประโยค hook แรก** · ประเภท hook · รูปแบบคลิป · ความยาว · **ป้าย mass** (ดู §6) · "ทำไมเวิร์ก" · **ใช้กับเราได้ไหม + ติดกฎแบรนด์ข้อไหน** |
| **Hook** | ประโยค/ภาพ 1–2 วินาทีแรก จัดเป็น 8 ประเภท (ดู §6.3) | ข้อความ · ประเภท · มาจากคลิปอ้างอิงไหน · ใช้ในโพสต์ไหนแล้ว · ผลสะสม |
| **ไอเดีย (Idea)** | สัญญาณที่ถูกเสนอให้ทำในสัปดาห์นี้ | ชื่อ · ประเภทคอนเทนต์ (5 สี) · กลุ่มลูกค้า (เครื่องประดับ 925 **หรือ** เงินแท่ง — ห้ามปนในชิ้นเดียว) · ช่องทาง · **สมมติฐาน 1 บรรทัด** · ตัวชี้วัด · **ค่าฐาน ณ วันตั้ง** · **เกณฑ์ผ่าน** · hook ตั้งต้น 2 ประเภท · ต้องถ่ายอะไร · สัญญาณต้นทาง |
| **แคมเปญ (Campaign)** | กลุ่มชิ้นงานที่มีเป้าหมาย/สมมติฐานเดียวกัน (เช่น "คลิปดันไลฟ์" · "ช่วงเงินเดือนออก" · "ทักลูกค้าเก่า") | ชื่อ · ช่วงวันที่ · สมมติฐาน + ตัวชี้วัด + ฐาน + เกณฑ์ · ชิ้นงานทั้งหมดและสถานะ · ผลลัพธ์ · **คำตัดสิน** (ได้ผล / ไม่ได้ผล / ยังสรุปไม่ได้ / วัดไม่ได้) |
| **ชิ้นงาน (Piece)** | งาน 1 ชิ้นที่จะออกสู่สาธารณะ: คลิปสั้น · คลิปตัดจากไลฟ์ · โพสต์ IG/FB · ข้อความ LINE · สตอรี่ | ชนิด · วัน/ช่วงเวลา (เช่น "ก่อนเริ่มไลฟ์คืนนั้น") · ช่องทาง · ประเภทคอนเทนต์ (สี) · **สถานะ (ชุดเดียว §3)** · storyboard (ช็อต/วินาที/บทพูด) · **hook A / hook B** · แคปชัน · CTA · shot list · ผลตรวจ 3 ด่าน · ลิงก์ไฟล์คลิป · ธงที่ต้องยืนยัน · โพสต์ที่ผูก · ผลลัพธ์ |
| **โพสต์ (Post)** | สิ่งที่ขึ้นจริงแล้ว 1 ลิงก์ | ลิงก์ · ช่องทาง · วันโพสต์ · **hook ที่ใช้จริง** · ชิ้นงานต้นทาง (หรือป้าย "นอกแผน") · ยอดที่กรอกแต่ละรอบ |
| **ยอดโพสต์ (Metric snapshot)** | ตัวเลขที่คนกรอกตามรอบ (วันที่ 1–2 / 3–4 / 5–9 หลังโพสต์) | วิว · ไลก์ · คอมเมนต์ · **บันทึก** · แชร์ · วันที่กรอก |
| **บันทึกหลังไลฟ์ (Live log)** | 1 บรรทัดต่อคืน | เวลาเริ่ม–เลิก · คนดูสูงสุด · **โฮสต์คืนนั้น** · ของประมูล · **คำถามที่ลูกค้าถามซ้ำ** |
| **ผลลัพธ์ + บทเรียน** | ผลอ่านแล้ว 4 ระดับ: ต่อโพสต์ · ต่อประเภท hook · ต่อแคมเปญ · ต่อเดือน | ป้าย เหนือปกติ / ปกติ / ต่ำ · ระดับความมั่นใจ · บทเรียน 1 บรรทัด → กลายเป็นสัญญาณใหม่ |
| **ข้อเสนอ/คำถามจาก AI** | สิ่งที่ AI ขอให้เจ้าของตัดสินหรือตอบ (จากสรุปรายสัปดาห์) | หัวข้อ · รายละเอียด · ใช้เวลากี่นาที · ค่าเริ่มต้นถ้าไม่ตอบภายในวันที่ X · ปุ่มตอบ |

## 3. สถานะ — ชุดเดียวทั้งระบบ (สำคัญที่สุดของไฟล์นี้)

ระบบเดิมมีปัญหา: งานเดียวกันแสดง 3 ที่และแต่ละที่เปลี่ยนสถานะคนละแบบ (กดยกเลิก "เสร็จ" ที่หนึ่งแล้วงานที่อนุมัติแล้วตกกลับเป็นร่าง · อีกที่กด "เสร็จ" ข้ามการอนุมัติได้) ⇒ **ชุดใหม่ต้องเป็นชุดเดียว และทุกหน้าใช้กติกาเดียวกัน**

### 3.1 ชิ้นงาน (Piece)

```
 ไอเดีย ─► วางแผนแล้ว ─► AI ร่าง ─► รอตรวจ ─► อนุมัติแล้ว ─► ผลิตแล้ว ─► โพสต์แล้ว ─► กำลังวัดผล ─► วัดผลแล้ว
                              ▲        │                                              (วันที่ 1–9)      (มีป้ายผล)
                              └─ ส่งกลับแก้ ┘
 สถานะข้าง:  ⏸ รอเงื่อนไข (ระบุว่ารออะไร)   ↷ เลื่อน (ระบุวันใหม่)   ✕ ยกเลิก (ระบุเหตุผล)
```

| เปลี่ยนจาก → เป็น | ใครกดได้ | กติกา |
|---|---|---|
| ไอเดีย → วางแผนแล้ว | เจ้าของ (ตอนคัดไอเดีย) | ต้องมีสมมติฐาน + ฐาน + เกณฑ์ |
| วางแผนแล้ว → AI ร่าง | AI / ระบบ | — |
| AI ร่าง → รอตรวจ | AI / ระบบ | ต้องมี hook ≥2 ประเภท + shot list |
| รอตรวจ → อนุมัติแล้ว | **เจ้าของเท่านั้น** | ต้องผ่าน 3 ด่าน (§5) ครบ · AI กดแทนไม่ได้ |
| รอตรวจ → ส่งกลับแก้ | เจ้าของ | ต้องใส่เหตุผล 1 บรรทัด |
| อนุมัติแล้ว → ผลิตแล้ว | เจ้าของ / คนถ่าย | แนบลิงก์ไฟล์ได้ (ไม่บังคับ) |
| ผลิตแล้ว → โพสต์แล้ว | เจ้าของ / ผู้ช่วย | **ปุ่มเดียว "โพสต์แล้ว"**: วางลิงก์ + เลือก hook ที่ใช้จริง (A/B) |
| อนุมัติแล้ว → โพสต์แล้ว (ชิ้นที่ไม่ต้องถ่าย: ข้อความ LINE · สตอรี่) | เจ้าของ | กด "โพสต์แล้ว" **ไม่ต้องมีลิงก์** · ชิ้นแบบนี้ไม่มีการวัดผลรายชิ้น (ไม่เข้าคิวกรอกยอด) |
| โพสต์แล้ว → กำลังวัดผล → วัดผลแล้ว | ระบบ (ตามวันที่ + ยอดที่กรอก) | วัดผลแล้ว = มียอดรอบวันที่ 5–9 · ไม่มี = "ตกรอบวัด" แสดงเหตุผล |
| ย้อนสถานะ | เจ้าของ | ย้อนได้ทีละขั้นเท่านั้น · **ห้ามมีปุ่มที่ทำให้ "อนุมัติแล้ว" หลุดกลับเป็นร่างโดยไม่ตั้งใจ** · ต้องมี undo หรือยืนยัน |

### 3.2 สัญญาณ
`ใหม่` → `หยิบแล้ว` (กลายเป็นไอเดีย — ลิงก์ถึงกันสองทาง) / `ไม่ใช้` (+เหตุผล — เหตุผลคือข้อมูล ไม่ใช่ขยะ) / `เก็บไว้ก่อน` (+วันทบทวน)

### 3.3 แคมเปญ
`ร่าง` → `กำลังทำ` → `รออ่านผล` → `ปิดแล้ว` (+คำตัดสิน: ได้ผล / ไม่ได้ผล / ยังสรุปไม่ได้ / วัดไม่ได้ — **เจ้าของเป็นคนยืนยันคำตัดสิน**)

### 3.4 ข้อเสนอ/คำถามจาก AI
`รอตอบ` → `ตอบแล้ว` / `ปฏิเสธ` (+เหตุผล) / `หมดเวลา` (ใช้ค่าเริ่มต้นที่ประกาศไว้ — แสดงว่าใช้ค่าอะไร)

## 4. Workflow 8 ขั้น — เริ่มที่ไหน ต่อที่ไหน

```
 ① จับสัญญาณ ──► ② คัดไอเดีย + ตั้งสมมติฐาน ──► ③ วางปฏิทิน ──► ④ ร่าง brief/storyboard
     ▲              (จันทร์ · เจ้าของ ✓/✗)                          (AI ร่าง · hook A/B)
     │                                                                    │
     │                                                                    ▼
 ⑧ อ่านผล + บทเรียน ◄── ⑦ โพสต์ + บันทึกหลังไลฟ์ ◄── ⑥ ถ่าย/ผลิต ◄── ⑤ ตรวจ 3 ด่าน + อนุมัติ
   (รายสัปดาห์)          (ทุกวัน)                (ถ่ายรวมสัปดาห์ละครั้ง)   (เจ้าของ ชุดเดียว/สัปดาห์)
```

**จังหวะสัปดาห์ (ตัวอย่าง)**: จันทร์ = อ่านสรุป + คัดไอเดีย · อังคาร = AI ร่างทั้งชุด · พุธ = เจ้าของอนุมัติทั้งชุด · พฤ/ศ = ถ่ายรวม · ทุกวัน = โพสต์ + บันทึกหลังไลฟ์ + กรอกยอด
**เวลาเจ้าของรวม ≈ 1.5–2 ชั่วโมง/สัปดาห์** (ก้อนใหญ่สุดคือถ่าย) — UI ต้องช่วยให้ส่วนอื่นเร็วที่สุด

| ขั้น | เป้าหมาย | ใครทำ | เกิดที่หน้าจอ | รับเข้า → ส่งออก | ของที่ต้อง "ติดไป" ขั้นถัดไป | เวลาคน |
|---|---|---|---|---|---|---|
| **① จับสัญญาณ** | รวมวัตถุดิบไว้กล่องเดียว · **เก็บอย่างเดียว ยังไม่ตัดสิน** | AI เรดาร์ (ทุกเช้า) · เจ้าของ/คนไลฟ์ (แปะลิงก์เมื่อเจอ) · คนไลฟ์ (คำถามซ้ำหลังไลฟ์) · ระบบ (บทเรียนจาก ⑧) | ปุ่มลอย "แปะลิงก์" ทุกหน้า · คลัง Research · ฟอร์มหลังไลฟ์ | ลิงก์/ข่าว/คำถาม → สัญญาณ 1 รายการ | ลิงก์ · แหล่ง · วันที่ · hook text · ป้าย mass · ใช้กับเราได้ไหม | 1–2 นาที/ลิงก์ |
| **② คัดไอเดีย** | เลือกว่าสัปดาห์นี้ทำอะไร ไม่เกินโควตา + ตั้งสมมติฐานที่วัดได้ | AI เสนอ (โควตา +2 ตัวเลือก) → **เจ้าของ** ✓ / ✗ / เลื่อน | หน้า "คัดไอเดียประจำสัปดาห์" (เข้าจาก inbox) | สัญญาณ 7 วัน + ผลสัปดาห์ก่อน + คลัง hook → ไอเดียที่อนุมัติ | **สัญญาณต้นทาง** · สมมติฐาน · ฐาน · เกณฑ์ · hook ตั้งต้น · ต้องถ่ายอะไร | 5–10 นาที |
| **③ วางปฏิทิน** | ลงวัน/ช่องทาง โดยแผนประจำมาก่อนเสมอ | AI วาง → เจ้าของดูภาพรวม | ปฏิทิน (สัปดาห์/เดือน) | ไอเดีย → ชิ้นงาน (สถานะ "วางแผนแล้ว") ผูกแคมเปญ | ทุกอย่างจาก ② + วัน/ช่วงเวลา + ธง "ต้องถ่าย" / "มีภาพแล้ว" + โฮสต์ที่คาด | 5 นาที/สัปดาห์ |
| **④ ร่าง brief** | storyboard พร้อมถ่าย + hook 2 แบบคนละประเภท | AI | หน้าชิ้นงาน (สถานะ "AI ร่าง" → "รอตรวจ") | ชิ้นงาน + คลัง hook + คลิปอ้างอิง → storyboard · hook A/B · แคปชัน · shot list ≤15 นาที | ทุกอย่าง + ลิงก์กลับไปคลิปอ้างอิงที่ใช้ถอดโครง | 0 |
| **⑤ ตรวจ + อนุมัติ** | ผ่าน 3 ด่าน แล้วเจ้าของกดเอง **ก่อนถ่าย** | AI ตรวจ 3 ด่าน → **เจ้าของ** อนุมัติ / แก้ / ส่งกลับ | inbox กอง "รออนุมัติ" (อนุมัติจากการ์ดได้เลย) + หน้าชิ้นงาน | ร่าง (storyboard + แคปชัน + hook) → ฉบับอนุมัติ พร้อมถ่ายและพร้อมโพสต์ (คัดลอกทั้งก้อนได้) | ฉบับสุดท้าย · ผลตรวจ 3 ด่าน · ใครอนุมัติ เมื่อไหร่ | 2–3 นาที/ชิ้น |
| **⑥ ถ่าย/ผลิต** | ถ่ายรวมสัปดาห์ละครั้ง หลายชิ้นในรอบเดียว | เจ้าของ / คนไลฟ์ · ช่างเป็นตัวแบบ | หน้า "รอบถ่ายสัปดาห์นี้" (รวม shot list **เฉพาะชิ้นที่อนุมัติแล้ว**) | shot list → ไฟล์คลิป | ลิงก์ไฟล์ · จดว่าต่างจาก storyboard ตรงไหน | 30–60 นาที |
| **⑦ โพสต์ + บันทึก** | โพสต์ตามฉบับอนุมัติ + ผูกลิงก์ทันที + จดหลังไลฟ์ | เจ้าของ / ผู้ช่วย · คนไลฟ์ | inbox กอง "วันนี้ต้องโพสต์" · ฟอร์มหลังไลฟ์ | ฉบับอนุมัติ → โพสต์ (ลิงก์ + hook ที่ใช้จริง) · คืนไลฟ์ → บันทึก | ลิงก์โพสต์ · hook ที่ใช้ · โฮสต์คืนนั้น · คำถามซ้ำ (→ กลับไป ①) | 3 นาที/โพสต์ · 1 นาที/คืน |
| **⑧ อ่านผล + บทเรียน** | รู้ว่าอะไรได้ผล แล้วป้อนกลับ | ผู้ช่วยกรอกยอดตามคิว · AI สรุปรายสัปดาห์ · **เจ้าของยืนยันคำตัดสิน** | คิวกรอกยอด · หน้าผลลัพธ์ · หน้าแคมเปญ | ยอด + บันทึกไลฟ์ + สมมติฐาน → ป้ายผลต่อโพสต์ / ต่อ hook / ต่อแคมเปญ / สัดส่วนเดือนหน้า | บทเรียน → เป็นสัญญาณใหม่ใน ① · อัปเดตผลสะสมของ hook | 5 นาที/สัปดาห์ + กรอกยอด ≤3 นาที/วัน |

**กติกาที่ต้องสะท้อนใน UI**
- **ลำดับคือ อนุมัติก่อน แล้วค่อยถ่าย** (อนุมัติ storyboard + แคปชัน + hook วันพุธ → ถ่าย พฤ/ศ) · ชิ้นที่ยัง "รอตรวจ" ต้องไม่โผล่ในรอบถ่าย · ย้ายเป็น "ผลิตแล้ว" ได้เฉพาะชิ้นที่ "อนุมัติแล้ว"
- ขั้น ① **ห้ามไหลเข้าปฏิทินเอง** · **คนหยิบสัญญาณเป็นไอเดียได้ทุกเวลา** (ไม่ต้องรอวันจันทร์) แต่ไอเดียที่หยิบนอกรอบไปรอในหน้าคัดไอเดีย และต้องมีสมมติฐาน + ฐาน + เกณฑ์ก่อนเป็น "วางแผนแล้ว"
- ถ้าคิว "รออนุมัติ" เกิน 10 ชิ้น → AI หยุดเสนอไอเดียใหม่ (แสดงให้เห็นใน inbox)
- ถ่ายไม่ได้ → **เลื่อนชิ้นงาน** ห้ามใช้ภาพ AI แทน (ปุ่ม "เลื่อน" ต้องหาง่าย)
- **"โพสต์แล้ว" = วางลิงก์แล้วเท่านั้น** สำหรับชิ้นที่มีลิงก์ (คลิป · โพสต์ IG/FB) — ยกเว้นข้อความ LINE/สตอรี่ที่กด "โพสต์แล้ว" ได้เลย (ไม่มีสถานะ "โพสต์แล้วแต่ยังไม่มีลิงก์") · ชิ้นที่ "ผลิตแล้ว" และเลยวันโพสต์ตามแผน → inbox เตือน "ถึงเวลาโพสต์แล้ว · ยังไม่วางลิงก์" (ไม่วางลิงก์ = หายจากการวัดผลถาวร) · กรอกยอดได้เฉพาะโพสต์ที่มีลิงก์
- **เลข ①–⑧ ใช้ในเอกสารนี้เท่านั้น ห้ามขึ้นจอ** — บนจอใช้ชื่อสถานะ (§3) ซึ่งเป็นคนละระบบกับขั้นตอน
- เปรียบเทียบผลต้องแสดง **"โฮสต์คืนนั้น"** กำกับเสมอ — คืนที่โฮสต์ต่างกันห้ามเทียบตรงๆ (โฮสต์บางคนมีแฟนคลับ ทำยอดต่างกันมาก)

## 5. ด่านตรวจ 3 ด่านก่อนอนุมัติ (แสดงในหน้าชิ้นงาน + การ์ดอนุมัติ)

| ด่าน | ตรวจอะไร | ใครตรวจ | UI |
|---|---|---|---|
| **ข้อเท็จจริง** | ตัวเลข มาตรฐาน คุณสมบัติวัสดุ มีแหล่งอ้างอิงไหม | AI | ✅ ผ่าน / ⚠️ ติด + ลิงก์แหล่ง + ข้อความที่ติด |
| **กฎแบรนด์** | เรื่องราคา การเทียบราคา คำเด็ดขาด เคลมที่ยืนยันไม่ได้ | AI | ✅ / ⚠️ + กฎข้อที่ชน |
| **ความเสี่ยง** | ภาษี · สุขภาพ/ผิวหนัง · การลงทุน | **เจ้าของตอบเท่านั้น** | ถ้ามีประเด็น → กลายเป็น "คำถามถึงเจ้าของ" ใน inbox (AI ห้ามตอบเอง) |

- ข้อความที่มี **`[ต้องยืนยัน: …]`** (ค่าที่ AI ไม่รู้ เช่น ราคา/โปร/ข้อเท็จจริงร้าน) ต้อง **ไฮไลต์เด่น** และ **บล็อกปุ่มอนุมัติ** จนกว่าจะแก้ครบ
- แสดง "เวลาที่ใช้ตรวจ" เล็กๆ บนการ์ด (ถ้าอนุมัติทั้งชุดใน <1 นาที ให้เห็นว่าอาจกดผ่านโดยไม่ได้อ่าน — แค่แสดง ไม่บล็อก)

## 6. Research คู่แข่ง · คลิป mass · คลัง hook

### 6.1 ฟอร์ม "แปะลิงก์ที่เจอ" (quick capture) — ต้องเสร็จใน ≤2 นาทีบนมือถือ
- **บังคับ 4 ช่อง**: ลิงก์ · วันที่เห็น (ค่าเริ่มต้นวันนี้) · ประโยค hook แรก · ใครเห็น
- **ไม่บังคับ** (กรอกทีหลังได้ / AI ช่วยเติมได้): บัญชี · ผู้ติดตาม · วิว · ไลก์ · คอมเมนต์ · บันทึก · แชร์ · วันที่โพสต์ · รูปแบบ · ความยาว · ประเภท hook · กลุ่มลูกค้า · ทำไมเวิร์ก · ใช้กับเราได้ไหม
- ช่องตัวเลข **รับค่าย่อ** ("16K", "1.2M") และติดป้าย "ประมาณ" อัตโนมัติ
- ลิงก์ซ้ำ → เตือนและพาไปรายการเดิม
- เข้าได้จาก **ปุ่มลอยทุกหน้าในสายการตลาด** และควรเปิดจากลิงก์ตรงได้ (ให้คนไลฟ์ใช้โดยไม่ต้องเข้าเมนู)

### 6.2 ป้าย "mass"
- **คลิป mass = วิว ÷ ผู้ติดตามของบัญชีนั้น ≥ 2 เท่า** (คลิปไปไกลกว่าฐานแฟนของบัญชี) · 0.5–2 = ปกติ-ดี · <0.5 = ไม่ติด
- ไม่รู้จำนวนผู้ติดตาม → ป้าย **"วัด mass ไม่ได้"** แสดงวิวดิบ (ห้ามเดา)
- คลิปอายุ <3 วัน → ป้าย "ยังไม่สุก"
- สัญญาณรอง: **บันทึก ÷ วิว** (คนเก็บไว้ = ใกล้การซื้อ) · mass แต่บันทึกต่ำ = "ดูเพลิน ไม่ใช่คนซื้อ"
- **mass ≠ ควรทำตาม** — ทุกคลิปต้องมีช่อง "ใช้กับเราได้ไหม" (ใช้ได้ / ปรับแล้วใช้ได้ / ใช้ไม่ได้ + กฎแบรนด์ที่ชน)

### 6.3 คลัง hook — 8 ประเภท

| ประเภท | ตัวอย่างโครง |
|---|---|
| คำถาม | "สร้อยเงินทำไมดำ?" |
| ข้อเท็จจริง | "925 แปลว่าอะไร" |
| คำเตือน | "ก่อนซื้อ ดู 3 อย่างนี้" |
| เปิดเบื้องหลัง | ภาพเทโลหะ/ขัด/ชุบใน 1 วินาทีแรก ไม่มีคำพูด |
| ก่อน–หลัง | ขัดเงา · ชุบใหม่ |
| เสียงลูกค้า | "เมื่อคืนมีคนถามว่า…" |
| บอกตรงเรื่องไลฟ์ | "ชิ้นนี้ขึ้นไลฟ์คืนนี้" |
| เรื่องเล่า | เรื่องโรงงาน/ช่าง/เจ้าของ |

**เส้นทางของ hook (UI ต้องให้ไล่ดูได้ทั้งเส้น)**
คลิปอ้างอิง (hook ของเขา) → ถอด **โครง** (ไม่ลอกคำ) → AI เขียน hook ใหม่ 2 ตัวคนละประเภทในชิ้นงานของเรา (A = ประเภทที่สถิติดี · B = ประเภทที่ยังทดสอบน้อย) → ตอนโพสต์เลือกว่าใช้ตัวไหนจริง → ผลวันที่ 7 → สะสมต่อประเภท → **ครบ 4 โพสต์ต่อประเภทถึงจะบอกว่า "ชนะ/แพ้"** (ก่อนหน้านั้นแสดง "ยังสรุปไม่ได้ (3/4)")

> ไม่ใช่ A/B test แบบสุ่มคนดู — แค่ติดป้ายประเภท hook ให้ทุกโพสต์ตั้งแต่ต้น แล้วเทียบสะสม · **ช่วงแรกไม่ต้องมี dashboard/กราฟ hook** แค่ตาราง + ตัวนับ จนกว่าจะมีข้อมูลราว 20–30 โพสต์

## 7. หน้าจอที่ต้องมี (Screen inventory)

### โครงเมนู (IA) ที่เสนอ

```
การตลาด
 ├─ 🏠 งานที่รอฉัน            (หน้าแรก — A)
 ├─ 🔍 Research               (B: สัญญาณทั้งหมด · คลิปอ้างอิง · เทรนด์รายวัน · คลัง hook)
 ├─ 🗓 วางแผน                 (C: คัดไอเดียประจำสัปดาห์ · D: ปฏิทิน · E: แคมเปญ)
 ├─ 🎬 ผลิต                   (F: หน้าชิ้นงาน · G: รอบถ่ายสัปดาห์นี้)
 ├─ 📤 โพสต์ & บันทึก          (H: โพสต์วันนี้ · I: บันทึกหลังไลฟ์ · J: กรอกยอด)
 ├─ 📊 ผลลัพธ์                 (K: ผลต่อโพสต์ · ต่อ hook · ต่อแคมเปญ · สรุปรายสัปดาห์)
 └─ ⚙ อื่นๆ (หน้าที่มีอยู่แล้ว: ค่าแอด · วัดผลโค้ด · กลุ่มลูกค้า · แบบทดสอบพลอย — ไม่อยู่ในขอบเขตออกแบบรอบนี้ แค่ต้องมีที่วาง)
```
- เมนูข้าง (sidebar) กับแถบเมนูย่อยต้อง **ตรงกันเป๊ะ** (ระบบเดิมไม่ตรง)
- ทุกหน้าต้องมีทางเข้า · ไม่มี URL ที่เปิดแล้วว่าง/404

### A. งานที่รอฉัน (Inbox) — หน้าแรก
- **เป้าหมาย**: เจ้าของเปิดแล้วรู้ใน 5 วินาทีว่ามีอะไรรอ และจัดการจบในหน้านี้
- **4 กอง** (เรียงตามความเร่ง · แต่ละกองมีตัวนับ):
  1. **วันนี้ต้องโพสต์** — การ์ดมีฉบับพร้อมคัดลอก + ปุ่ม "โพสต์แล้ว" (เปิด sheet วางลิงก์ + เลือก hook A/B) · เตือนโพสต์ที่ค้างวางลิงก์
  2. **รออนุมัติ** — การ์ดย่อ: ชนิด · วันที่จะโพสต์ · hook A/B · ผล 3 ด่าน · ปุ่ม อนุมัติ / แก้ / ส่งกลับ (+เหตุผล) · กดขยายดู storyboard ได้ในที่
  3. **ไอเดียรอคัด** — (มีเฉพาะช่วงคัดประจำสัปดาห์) ทางลัดเข้าหน้า C
  4. **คำถาม/ข้อเสนอจาก AI** — ใช้เวลากี่นาที · ค่าเริ่มต้นถ้าไม่ตอบภายในวันที่ X · ปุ่มตอบในที่
- ส่วนบน: **สรุปสัปดาห์ 5 บรรทัด** (จาก AI) + ลิงก์ฉบับเต็ม
- ส่วนล่าง: "สัปดาห์นี้" แถบสถานะชิ้นงาน (มีภาพแล้ว / ต้องถ่าย / รออนุมัติ / โพสต์แล้ว) + นัดรอบถ่าย
- **ว่าง** = "ไม่มีอะไรรอคุณ 🎉" + บอกงานถัดไปที่จะมา
- แยกมุมมองตามบทบาท (ดู §8)

### B. Research (ศูนย์รวมสัญญาณ)
- **แท็บ/ตัวกรอง**: ทั้งหมด · คลิปอ้างอิง · เทรนด์รายวัน · คำถามจากไลฟ์ · โมเมนต์ช่าง · บทเรียน — กรองตามสถานะ / กลุ่มลูกค้า / ประเภท hook / ป้าย mass / ใช้กับเราได้ไหม
- **การ์ดคลิปอ้างอิง**: บัญชี · ป้าย mass · hook แรก · ประเภท hook · รูปแบบ · ใช้กับเราได้ไหม (สี) · ปุ่ม เปิดลิงก์ / หยิบเป็นไอเดีย / ไม่ใช้ / เก็บไว้ก่อน
- **เทรนด์รายวัน (AI)**: ต่อวันแสดง มุมที่หยิบได้ (≤3) + ทำไมตอนนี้ + ต้องมีอะไรถึงถ่ายได้ + แหล่งอ้างอิง + ความมั่นใจ · **และต้องแสดงส่วนที่ AI ตัดทิ้งพร้อมเหตุผล** (ข้อมูลคู่แข่ง/รูปแบบคลิปมักอยู่ตรงนี้) · วันที่ "ไม่มีอะไรใหม่" ก็ยังแสดงคำถามที่รอยืนยัน · ปุ่ม **"หยิบเข้ากล่อง"** ต่อมุม (พาลิงก์ + เหตุผล + ประเภทไปด้วย)
- **รายละเอียดสัญญาณ** (drawer/หน้า): ทุกฟิลด์ + ประวัติ (ถูกหยิบไปเป็นไอเดียไหน → ชิ้นงานไหน → ผลเป็นยังไง)
- **คลัง hook** (แท็บ): ตาราง hook ทั้งของคนอื่นและของเรา · ต่อประเภท: จำนวนที่ใช้ · ผลสะสม เหนือ/ปกติ/ต่ำ · สถานะ "ยังสรุปไม่ได้ (n/4)"
- ปุ่มลอย **"+ แปะลิงก์"**

### C. คัดไอเดียประจำสัปดาห์ (Triage)
- รายการไอเดียที่ AI เสนอ (≤ โควตา + 2) · แต่ละใบ: ชื่อ · ประเภท (สี) · กลุ่มลูกค้า · ช่องทาง · สมมติฐาน · ฐาน → เกณฑ์ผ่าน · hook ตั้งต้น · ต้องถ่ายอะไร · สัญญาณต้นทาง (กดดูได้)
- ปุ่ม ✓ ทำ / ✗ ไม่ทำ (+เหตุผล 1 บรรทัด) / ↷ เลื่อน
- แถบบน: โควตาสัปดาห์ (เช่น TikTok 3 · IG 1 · LINE เหลือ x ครั้งในรอบ 28 วัน) · ช่องว่างในปฏิทิน · คิวรออนุมัติปัจจุบัน
- ✓ แล้ว → ชิ้นงานไปโผล่ในปฏิทินอัตโนมัติ (สถานะ "วางแผนแล้ว")
- ⏱ เป้า: ทั้งหน้าจบใน 5–10 นาที

### D. ปฏิทิน (Planner) — ปฏิทินเดียว
- **มุมมอง**: สัปดาห์ (ค่าเริ่มต้นบน desktop) · เดือน · รายการ (ค่าเริ่มต้นบนมือถือ) — สลับได้ จำค่าล่าสุด
- การ์ดชิ้นงาน: ชนิด · ช่องทาง · **สีประเภท** · ช่วงเวลา ("ก่อนไลฟ์" / "เช้า") · **สถานะ** · ธง (ต้องถ่าย · รอเงื่อนไข · ต้องยืนยัน) · แคมเปญ
- แสดง **โฮสต์ที่คาดว่าไลฟ์** ต่อคืน (แถบบนแต่ละวัน) และ **วันสำคัญ/เทศกาล** (ไม่ต้องแยกเป็นแท็บอีกหน้า)
- ลากเพื่อเลื่อนวันได้บน desktop · มือถือใช้ปุ่ม "เลื่อน"
- กรองตามแคมเปญ / ช่องทาง / สถานะ / ประเภท
- งานหลายวัน **ต้องโผล่ทุกวันที่ครอบคลุม แม้ข้ามเดือน** (ระบบเดิมหล่น)
- คลิกการ์ด → หน้าชิ้นงาน (F) · desktop เปิดเป็นแผงขวาได้
- ตัวนับ LINE (ส่งได้ไม่เกิน 4 ครั้ง/28 วัน) แสดงเมื่อกรองช่อง LINE

### E. แคมเปญ (ระดับที่ระบบเดิมไม่มีจอแสดงเลย)
- **รายการ**: ชื่อ · ช่วงวันที่ · สถานะ · ความคืบหน้าชิ้นงาน (x/y โพสต์แล้ว) · คำตัดสิน
- **รายละเอียด**: สมมติฐาน · ตัวชี้วัด · ค่าฐาน ณ วันตั้ง · เกณฑ์ผ่าน · timeline ชิ้นงานในแคมเปญ · ผลลัพธ์ล่าสุด · คำตัดสินที่ AI เสนอ + ปุ่มเจ้าของ "ยืนยัน" / "แก้" · บทเรียน
- ถ้าเกณฑ์ผ่านแคบกว่าช่วงแกว่งปกติของค่าฐาน → แสดงคำเตือน "เกณฑ์นี้แยกผลจากความบังเอิญไม่ได้"

### F. หน้าชิ้นงาน (Piece) — บ้านเดียวของงาน 1 ชิ้น
- หัว: ชนิด · ประเภท (สี) · ช่องทาง · วัน/ช่วงเวลา · แคมเปญ · **stepper สถานะ (§3.1)** · ป้าย "AI ร่าง" / "แก้โดยคน"
- **เส้นทางต้นทาง**: สัญญาณ → ไอเดีย → สมมติฐาน (กดดูได้)
- **Storyboard**: ช็อต / วินาที / บทพูด / ภาพ · ติ๊กช็อตที่ถ่ายแล้ว
- **Hook A / Hook B**: การ์ดคู่ แสดงประเภท + มาจากคลิปอ้างอิงไหน · ปุ่มเลือก (ตอนอนุมัติหรือตอนโพสต์)
- แคปชัน + CTA · **ปุ่มคัดลอกต่อส่วน และคัดลอกทั้งก้อน**
- shot list (ใช้รวมในหน้า G)
- **3 ด่าน** (§5) + ธง `[ต้องยืนยัน]`
- ปุ่มหลักตามสถานะ (ปุ่มเดียวเด่น เช่น "อนุมัติ" / "ทำเครื่องหมายถ่ายแล้ว" / "โพสต์แล้ว")
- **ส่วนผลลัพธ์**: เมื่อโพสต์แล้ว แสดงยอดแต่ละรอบ + ป้ายผล + โฮสต์คืนนั้น (ปิดวงจรในหน้าเดียว)
- **ที่เขียนสคริปต์มีที่เดียว** (ระบบเดิมมี 2 ที่ในหน้าเดียว)
- รองรับชนิดที่ไม่ใช่คลิป (ข้อความ LINE / โพสต์ภาพ) ด้วย layout เดียวกันแต่ซ่อนส่วนที่ไม่เกี่ยว

### G. รอบถ่ายสัปดาห์นี้ (Shoot list)
- รวม shot list ของทุกชิ้นที่ "อนุมัติแล้ว/ต้องถ่าย" ในสัปดาห์ · จัดกลุ่มตามสถานที่ (โรงงาน / โต๊ะสินค้า / หน้ากล้องคนไลฟ์) · ติ๊กตอนถ่าย · ประเมินเวลารวม
- ปุ่ม "ถ่ายไม่ได้ → เลื่อนชิ้นนี้"
- ใช้บนมือถือขณะถ่ายจริง (ตัวใหญ่ ติ๊กง่าย)

### H. โพสต์วันนี้ + sheet "โพสต์แล้ว"
- อยู่ในกอง 1 ของ inbox ด้วย · sheet: วางลิงก์ (ตรวจว่าเป็นลิงก์จริง) → เลือก hook ที่ใช้จริง (A / B / อื่น) → บันทึก = สถานะ "โพสต์แล้ว" ในทุกหน้าทันที
- **โพสต์นอกแผน**: วางลิงก์ได้ ติดป้าย "นอกแผน" · และ **ผูกเข้าชิ้นงานทีหลังได้** (ระบบเดิมผูกทีหลังไม่ได้)

### I. บันทึกหลังไลฟ์ (มือถือ 1 นาที)
- ช่อง: เวลาเริ่ม · เวลาเลิก · คนดูสูงสุด · **โฮสต์** (เลือกจากรายชื่อ + เพิ่มใหม่) · ของประมูล (ไม่บังคับ) · **คำถามที่ลูกค้าถามซ้ำ** (1 บรรทัด → กลายเป็นสัญญาณอัตโนมัติ)
- เปิดจากลิงก์ตรงได้ (คนไลฟ์ไม่ต้องรู้จักเมนู) · แสดงว่าคืนไหนยังไม่ได้บันทึก (ย้อนได้ 7 วัน)

### J. กรอกยอด (Metric queue)
- คิวโพสต์ที่ถึงรอบกรอกวันนี้ (วันที่ 1–2 / 3–4 / 5–9 หลังโพสต์) · ตัวนับ "วันนี้ x/y"
- การ์ดกรอก 5 ช่อง เรียงตามลำดับที่เห็นในแอป TikTok · ทวน → ยืนยัน
- **แก้ตัวเลขที่กรอกผิดย้อนหลังได้** (+เหตุผล) — ระบบเดิมแก้ไม่ได้
- รายการ **"พลาดรอบไปแล้ว"** แยกให้เห็น (ไม่ใช่หายเงียบ)
- ⏱ เป้า ≤3 นาที/วัน

### K. ผลลัพธ์
- **ต่อโพสต์**: ยอดวันที่ 7 · อัตราบันทึก/แชร์ เทียบค่ากลางของ 10 โพสต์ล่าสุด → ป้าย เหนือ / ปกติ / ต่ำ · hook ที่ใช้ · โฮสต์คืนนั้น · ลิงก์กลับชิ้นงาน
- **ต่อประเภท hook / รูปแบบ**: ตารางดิบ ประเภท × จำนวน × ผลสะสม · "ยังสรุปไม่ได้ (n/4)" (ช่วงแรกตาราง ไม่ต้องกราฟ)
- **ต่อแคมเปญ**: ลิงก์ไป E
- **สรุปรายสัปดาห์** (จาก AI): อ่านในแอปได้ ไม่ต้องเปิดไฟล์ · ข้อเสนอในนั้นตอบได้ (เชื่อมกับ inbox กอง 4)
- **สัดส่วนเดือนหน้า** (สิ้นเดือน): ประเภทชนะ 50% / รอง 25% / เผื่อ 25% — AI เสนอ เจ้าของปรับ

## 8. บทบาทผู้ใช้

| บทบาท | เห็น/ทำ | ไม่เห็น/ไม่ทำ |
|---|---|---|
| **เจ้าของ** | ทุกหน้า · คัดไอเดีย · อนุมัติ · ตอบคำถาม · ยืนยันคำตัดสิน | — |
| **ผู้ช่วย** (อาจมีหรือไม่มี — ออกแบบให้รองรับทั้งสองแบบ) | โพสต์ตามฉบับอนุมัติ · วางลิงก์ · กรอกยอด · บันทึกหลังไลฟ์ · แปะลิงก์ research | **ไม่มีปุ่มอนุมัติ** · ไม่แก้ copy/สมมติฐาน · ไม่เห็นตัวเลขการเงินภายใน |
| **คนไลฟ์** | ฟอร์มหลังไลฟ์ · แปะลิงก์ · ดู storyboard ที่ตัวเองต้องเป็นหน้ากล้อง | ส่วนอื่น |
| **AI** (ไม่ใช่ผู้ใช้หน้าจอ แต่ต้องมีร่องรอยบนจอ) | ร่าง · เสนอ · ตรวจ 3 ด่าน · สรุป | อนุมัติ · แทรกปฏิทินเอง · ตอบเรื่องภาษี/สุขภาพ/การลงทุน |

**Inbox ตามบทบาท**: เจ้าของเห็น 4 กอง · ผู้ช่วยเห็น "วันนี้ต้องโพสต์" + "กรอกยอดวันนี้" + "บันทึกหลังไลฟ์ที่ค้าง" · คนไลฟ์เห็นแค่ฟอร์มหลังไลฟ์ + storyboard ของคืนนี้

## 10. ข้อจำกัดที่ UI ต้องเคารพ (เปลี่ยนไม่ได้)

1. **ไม่มีข้อมูลคู่แข่งอัตโนมัติ** — ทุกตัวเลขคู่แข่งมาจากคนกรอกหรือ AI สรุปจากเว็บ (ห้ามออกแบบที่สมมติว่ามี feed อัตโนมัติ)
2. **ยอด "บันทึก" ต้องกรอกมือเสมอ** (ระบบดึงไม่ได้)
3. **วัดยอดขายต่อคลิปไม่ได้** — ห้ามมีช่อง "คลิปนี้ขายได้กี่บาท" / CTR / conversion
4. **ไม่ตัดสินผลรายวัน** — ยอดขายรายคืนนิ่งหลัง 3 วัน · รูปแบบต้องลงอย่างน้อย 4 ชิ้นก่อนตัดสิน
5. **กลุ่มลูกค้าเครื่องประดับ 925 กับเงินแท่งแทบไม่ทับกัน** — ชิ้นงาน 1 ชิ้นเลือกได้กลุ่มเดียว
6. **LINE ส่งได้จำกัด** (≤4 ครั้ง / 28 วัน) — ต้องมีตัวนับ · **ข้อความ LINE ปกติส่งถึงเพื่อนทุกคน** (ค่าเริ่มต้น) · เลือก "เฉพาะกลุ่ม" ได้เฉพาะข้อความส่วนลดหรือสินค้า exclusive ⇒ ชิ้นงาน LINE มีช่อง "ผู้รับ: ทุกคน / เฉพาะกลุ่ม (+เหตุผล: ส่วนลด / exclusive)"
7. **เวลาไลฟ์ไม่ตายตัว** — ใช้ช่วงเวลา "ก่อนเริ่มไลฟ์คืนนั้น" แทนเวลาเป๊ะ

## 14. สิ่งที่อยากได้กลับจากผู้ออกแบบ

1. **ผังหน้าจอ (sitemap)** + เส้นทางผู้ใช้หลัก 3 เส้น: เช้าวันจันทร์ของเจ้าของ · วันปกติก่อนไลฟ์ · เส้นทางคลิปคู่แข่ง → โพสต์ของเรา → ผลลัพธ์
2. **mockup ทุกหน้าใน §7** ทั้ง **มือถือ** และ **desktop** พร้อมสถานะ ว่าง / โหลด / ยังสรุปไม่ได้
3. **component กลาง**: การ์ดชิ้นงาน · การ์ดสัญญาณ · badge สถานะ · chip ประเภท · stepper สถานะ · sheet "โพสต์แล้ว" · ฟอร์มแปะลิงก์
4. **รายการคำถาม/ข้อสงสัย** ที่เจอระหว่างออกแบบ (ดีกว่าเดาเอง)

### เจ้าของยืนยันแล้ว (6 ต.ค. 2569)
- **ตอนนี้ยังไม่มีผู้ช่วย** — เจ้าของคนเดียวถ่าย ตัด โพสต์ เอง ⇒ ออกแบบให้คนเดียวใช้จบได้เป็นหลัก · มุมมองผู้ช่วย/คนไลฟ์ยังเก็บไว้ได้แต่เป็นลำดับรอง
- **แผนถัดไป: AI ช่วยตัดคลิปจากฟุตเทจจริง** ตาม "แม่แบบคลิป" (format clip) ที่ทำไว้ — หน้าชิ้นงานควรเลือกแม่แบบคลิปได้ (ยังไม่ต้องออกแบบรอบนี้ แค่เว้นที่)
- รายชื่อโฮสต์มีได้ (ชื่อจริง + ป้าย "โฮสต์ A/B") บนจอแสดงแบบป้าย
- ข้อความ LINE/สตอรี่: กด "โพสต์แล้ว" ได้เลยไม่ต้องมีลิงก์ และไม่มีการวัดผลรายชิ้น
- งานก่อน 1 ต.ค. 2569 ไม่ต้องแสดงในหน้าจอใหม่
- ไฟล์คลิปเก็บนอกระบบ แอปเก็บแค่ลิงก์ · ยอดวิว/ไลก์/คอมเมนต์/แชร์ของโพสต์เราเอง **ระบบจะดึงอัตโนมัติในอนาคต** (ช่อง "บันทึก" ยังกรอกมือ) ⇒ หน้ากรอกยอดควรแสดงว่าช่องไหน "ดึงอัตโนมัติแล้ว" ช่องไหนต้องกรอก
