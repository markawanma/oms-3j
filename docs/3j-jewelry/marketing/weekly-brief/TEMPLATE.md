## หน้าต่างเวลา
- ช่วงรายงาน = **จันทร์–อาทิตย์ที่เพิ่งจบ** เทียบสัปดาห์ก่อนหน้า
- เจ้าของ import ยอด Shipnity ถึงวันอาทิตย์ **ก่อนจันทร์ 09:00** — ถ้าไม่ทัน brief ต้องเขียนใน §0 ว่า "ข้อมูลถึงวันไหน" **ห้ามเดา** และทุกตัวเลขต้องมีบรรทัด "ต่อวัน / ต่อคืนไลฟ์" กำกับ
- สัปดาห์ที่ <6 คืนไลฟ์ หรือ <6 วัน import → ดอกจัน + normalize ต่อคืน บังคับ

## โครง (ลำดับตายตัว)
**สรุป 5 บรรทัด** (บนสุด — เจ้าของอ่านจากมือถือ): 3 ตัวเลข · ปัญหา 1 · ข้อเสนอรวมนาที
0. **หัว** — ช่วงข้อมูล · ข้อมูลถึงวันไหน · อะไรยังไม่ import · อะไรไม่มีเลย · บริบท (ออกบูท/ไลฟ์สั้น/ฯลฯ)
1. **ตัวเลขหลัก 3 ตัว** (WoW ดิบ · ต่อวัน · ต่อคืนไลฟ์) + ตารางช่องทาง + 1 บรรทัด GSC (คำ non-brand เครื่องประดับ — "ไม่มีข้อมูล" ถ้ายังดึงมือไม่ได้)
1b. **ตารางคืนไลฟ์** — วัน · เริ่ม–เลิก · ชม. · viewer · ประมูล · ออเดอร์ · ยอด · ยอดไม่รวมประมูล · ยอด/ชม. (จาก log หลังไลฟ์ของเจ้าของ)
2. **อะไรเปลี่ยนจากสัปดาห์ก่อน** — เฉพาะเรื่องที่**ไม่ใช่**แคมเปญ (แคมเปญไป §3) · ทุกข้อติดป้าย **Fact / Observation / Hypothesis**
3. **ผลแคมเปญที่วัดได้** — ต่อแคมเปญ: quote hypothesis คำต่อคำ · execution log (ขั้นไหนส่งจริง วันไหน reach) · ผลจริง · `result_verdict` ที่เสนอ (`validated` / `invalidated` / `inconclusive` / `not_measured`) + `result_note` พร้อม copy · **เสนอให้เจ้าของ ไม่เขียนลง campaign เอง**
4. **สัปดาห์หน้าต้องทำอะไร** — ตาราง วัน · งาน · พร้อมแล้ว · ยังขาด (ห้ามยิงถ้าไม่ครบ) · ใคร · นาที — งาน "หลายชิ้น" ต้องแตกเป็นวัน
5. **ข้อเสนอ ≤3** — ต้น §5: สถานะข้อเสนอสัปดาห์ก่อน (done / rejected / pending / expired + acceptance MTD จาก `v_recommendation_acceptance`) · แต่ละข้อ: title · detail · owner_action · effort_minutes · confidence · expected outcome · trade-off · วันทบทวน · related_campaign
   - เรียงตาม **Impact×Relevance×Urgency×Confidence ÷ max(นาที, 5)** · ≤15 นาที/ข้อ เป็น **gate** ไม่ใช่ตัวหาร
   - ห้ามเสนอสิ่งที่เจ้าของล็อกไว้ (ดู memory) · ข้อที่ต้นทุนจริงเป็นชั่วโมงเจ้าของ (เช่น ไลฟ์ยาวขึ้น) ยกไป §7 เป็น next test ไม่ใช่ข้อเสนอ
6. **ช่องว่างข้อมูล + สิ่งที่ต้องการ** — คำถามเจ้าของ (Q) แยกจากงาน Tech Lead (T) · ท้ายสุด 1 บรรทัด "สุขภาพคลังเอกสาร" (`node scripts/doc-index-check.mjs`)
7. **Decision / Learning ที่ควรบันทึก** — แบบฟอร์ม: what happened · why it matters · learned · confidence · repeat · avoid · next test · Decision ในอำนาจ CMO ระบุชัดว่าใครตัดสิน

## ข้อมูลที่ต้องดึงทุกจันทร์ (Supabase `analytics`, shop 3J)
1. ต่อช่องทาง × 2 สัปดาห์: ออเดอร์ · ยอด · AOV · ลูกค้า · ลูกค้าใหม่ · สัดส่วนยอด
2. รายวัน: ออเดอร์ · ยอด · AOV · TikTok/LINE · จังหวัดไม่ทราบ · + join ชั่วโมงไลฟ์/viewer จาก log → ยอด/ชม.
3. ต่อคืน: ยอดสินค้าที่**ไม่ใช่** `[ประมูล]` · มีประมูลไหม · ชิ้น/ราคาปิด
4. **AOV เครื่องประดับ** ต่อช่องทาง (exclude SKU `S-*` เงินแท่ง และ `[ประมูล]`) — metric หลักแทน AOV รวม
5. Top 10 SKU (ยอด+ชิ้น) ติดป้าย S-* / [ประมูล] / LiveS* · สัดส่วน 3 กลุ่มต่อยอดรวม
6. เงินแท่ง: แท่ง/สัปดาห์ · ราคาขายเฉลี่ย/แท่ง · ราคาเนื้อเงินล่าสุด (เมื่อ pipeline มี)
7. RFM: จำนวนต่อ segment + Δ vs สัปดาห์ก่อน + **คนเข้า/ออก at_risk** (diagnostic)
8. Campaign board: ขั้นที่ครบกำหนดใน 7 วัน · effective_status · audience สด · artifact ready/blocked
9. แคมเปญที่ anchor ผ่านแล้วและ `result_verdict = 'not_measured'` → บังคับเสนอ verdict
10. `recommendation_log`: pending >7 วัน · done/rejected/expired เดือนนี้ · acceptance MTD
11. Data coverage: วันสุดท้ายที่ import · ออเดอร์ไม่มีรายการ · ไม่มีจังหวัด · ใบปะหน้าค้าง
12. LINE: broadcast ส่งจริง 28 วันล่าสุด vs เพดาน ≤4
13. GSC: คำ non-brand เครื่องประดับ (มือ จนกว่าอัตโนมัติ)
14. `node scripts/doc-index-check.mjs` 1 บรรทัด

## เกณฑ์ "เปลี่ยนแปลงมีนัย" ก่อนยกขึ้นพูด (rule of thumb — <1,000 ออเดอร์/เดือน ห้ามอ้างนัยสำคัญทางสถิติ)
| ตัวชี้วัด | พูดได้เมื่อ | ไม่งั้น |
|---|---|---|
| ยอด/ออเดอร์ **ต่อคืนไลฟ์** (ห้ามใช้ยอดดิบสัปดาห์) | Δ ≥ ±20% และ ≥5 คืนไลฟ์ทั้งสองสัปดาห์ | 10–20% = "จับตา" พูดเมื่อ 2 สัปดาห์ทิศเดียวกัน |
| AOV เครื่องประดับ | Δ ≥ ±10% และ n ≥150 ใบทั้งสองสัปดาห์ | เงียบ |
| ช่องทางที่ <30 ใบ/สัปดาห์ (LINE) | รายงานจำนวนดิบ ห้ามคิด % · flag ถ้า <50% ของค่าเฉลี่ย 4 สัปดาห์ | — |
| สัดส่วนลูกค้าใหม่ | Δ ≥ ±10 จุด | เงียบ |
| SKU | เข้า/ออก top 10 · "ขึ้น" = ≥2× และ ≥฿5,000 | เงียบ |
| แคมเปญ vs ฐาน | ตามเกณฑ์ pre-registered เท่านั้น ห้าม post-hoc · เทียบคืนต่อคืน ต้อง ≥6 คืน/ฝั่ง + ชม./คืน | not_measured |
| RFM segment | Δ ≥ ±10% WoW → **diagnostic ก่อนใช้เป็น audience** | ใช้ได้ |
| เงินแท่ง | แท่ง ≥2× หรือ ราคา/แท่ง ≥ ±10% → พูดได้แต่ label Observation เสมอ | เงียบ |
