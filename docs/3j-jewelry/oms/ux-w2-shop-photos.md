## มติเจ้าของ 21 ต.ค. 69 (ที่ spec นี้ยึด)

รูปจากหน้างาน **สูงสุด 3 รูป/ใบ** · ผู้จัดการแก้/ลบรูปของตัวเองได้ **จนช่างเริ่มรับงาน (ขั้นแรกถูกรับ)** · ถ่าย/เลือกรูปในเวลาเดียวกับเปิดใบ · A5 พิมพ์ได้ (รูปหลัก 30×30 มม. มีอยู่แล้ว)
**design ระบบ (Yoda)**: รูปต้องมี job_id ⇒ เลือก/ถ่ายก่อนกดเปิด (เก็บในเครื่อง) → อัปโหลดหลังเปิดสำเร็จทีละรูป ผูกด้วย idem key ต่อรูป · reload ก่อนเปิด = รูปหาย · ย่อ md 1200 / sm 480 ≤ 1 MB (`lib/images/client`) · ไม่ตรวจภาพอัตโนมัติ — ออฟฟิศเห็นทุกรูปตอนรับทราบ ลบได้พร้อมเหตุผล

## 1. สิ่งที่ยึด (ไม่คิดค่าใหม่)

- หน้าช่าง/หน้างาน: ตัวพื้น ≥ 18px · ตัวรอง ≥ 14–15px · ปุ่มหลัก ≥ 56px (`BigButton`) · แตะ ≥ 44px · `max-w-md` · **รองรับ 360px (เนื้อหา 328px)** · `ShopStepHeader` + `StickyAction` เดิม
- สี: `bg-primary-600` (#a2191d) ปุ่มหลักเดียวต่อจอ · เขียว = สำเร็จ · แดง `red-700/red-50` = ผิด · amber = เตือน/ค้าง · sky = info (ตาม W-8b) — ไม่เพิ่ม hex
- ภาพ: ย่อ md 1200 / sm 480 ≤ 1 MB ผ่าน `resizeImageVariants` (ลบ EXIF/GPS โดย re-encode อยู่แล้ว) · ข้อความ error ของไฟล์ใช้ชุดเดียวกับ `describeResizeError` / `HEIC_MESSAGE`
- viewer = `JobPhotoViewer` เดิม (รับ `smUrl`/`mdUrl` เป็น blob URL ในเครื่องได้) · ปุ่มเพิ่ม = `PhotoAddButtons` เดิม (+ 2 prop เล็ก §10)
- ไม่ลิงก์ออกนอกแอปช่าง · ข้อความ error ผ่านฟังก์ชันกรองไทยล้วน ไม่มีรหัส/ชื่อตาราง

## 2. User flow

```
[W-1 hub → เปิดงานใหม่]
  W-2 ผลิตอะไร? ─► (W-2b ทำจากอะไร? เฉพาะสินค้าใหม่) ─► W-3 เท่าไร · เสร็จเมื่อไร
        ▼
  ★ W-5 ใส่รูปให้ช่างดู (ใหม่ · ไม่บังคับ · ≤ 3 รูป · เก็บในเครื่อง ยังไม่ส่ง)
     ├─ [ถ่ายรูป]  → กล้องหลัง → กลับมา → "กำลังย่อรูป…" → ภาพย่อ  (ทีละรูป)
     ├─ [เลือกจากคลัง] → เลือกได้หลายรูป (เกินที่เหลือ = ตัดท้าย + แจ้ง)
     ├─ ไฟล์เปิดไม่ได้ (HEIC/เสีย/ใหญ่) → แถวแจ้งเหตุผลเหนือภาพย่อ [ปิด] (ไม่กินช่อง)
     ├─ แตะภาพย่อ → viewer → ★ ตั้งเป็นรูปหลัก / เอารูปนี้ออก
     ├─ ครบ 3 → ปุ่มเพิ่มหาย แทนด้วย "ครบ 3 รูปแล้ว"
     └─ [ถัดไป] (มีรูป) / [ข้าม ไม่ใส่รูป] (ไม่มีรูป)
        ▼
  W-6/7 ทวน (+ แถว "รูป" สุดท้ายของการ์ด · [แก้] กลับ W-5) ─► [เปิดงาน]
     ├─ error ตาม §B.8 ทุกเคส → ฟอร์ม + รูปคงอยู่ (รูปอยู่ในเครื่อง ยังไม่ส่ง)
     └─ สำเร็จ ─►  W-8a  (หรือ W-8b)
                    ├─ ไม่มีรูป:  W-8a เดิมทุกประการ + แถวเดียว "+ เพิ่มรูป" (เพิ่มภายหลังได้)
                    └─ มีรูป:    ส่งทีละรูปอัตโนมัติ (รูปหลักก่อน) · QR ซ่อนจนครบ
                         ├─ ครบ → แถบพับ "✓ ส่งรูปแล้ว 3 รูป · แก้ได้จนช่างเริ่มรับงาน [จัดการ ▾]" + QR
                         ├─ บางรูปล้ม → แถวแดง [ลองใหม่]/[เอาออก] · QR แสดงพร้อมคำเตือน
                         ├─ ช่างรับงานแล้ว (server ปฏิเสธ) → ล็อก "ช่างรับงานแล้ว แก้รูปไม่ได้ — แจ้งออฟฟิศ"
                         ├─ กด [เสร็จแล้ว]/[เปิดอีกใบ] ตอนยังส่งไม่ครบ → แผ่นยืนยัน "ยังส่งรูปไม่ครบ"
                         ├─ กด [เสร็จแล้ว] → กลับ hub W-1c → เห็นใบที่เพิ่งเปิดในรายการ "ใบที่ฉันเปิด"
                         └─ ปิดแท็บ/รีโหลดตอนยังส่ง → beforeunload (iOS ไม่การันตี — ข้อความบนจอคือด่านหลัก)

[ภายหลัง — Q1=B] hub W-1c (หลัง PIN) → "ใบที่ฉันเปิด" (W-9) → แตะการ์ด → W-10 แก้รูปของใบนั้น
     ├─ การ์ด "แก้ได้" → เพิ่ม/ลบ/ตั้งรูปหลัก (ส่งทีละรูป เหมือน W-8) จนช่างรับงาน
     ├─ การ์ด "ช่างรับงานแล้ว" → ดูรูปได้ แก้ไม่ได้ ("แจ้งออฟฟิศ")
     └─ ไม่มี QR ใบงาน (ดูซ้ำไม่ได้) → ให้ออฟฟิศพิมพ์ A5 ให้ช่างสแกน

[ออฟฟิศ] OfficeAck: แถบ "รูปจากหน้างาน" (ดูใหญ่ · ตั้งรูปหลัก · ลบพร้อมเหตุผล) → รับทราบ (ไม่ผูกกับรูป)
[ช่าง]   /w/[token] + A5 = ไม่เปลี่ยน (ใช้รูปหลักเดิม) — §7
```

**ทำไม W-5 อยู่หลัง W-3 ก่อนทวน (ไม่ใช่ก่อน):** ข้อมูลที่มีผลต่อต้นทุน/ความถูกต้อง (โลหะ เนื้อ จำนวน) ต้องกรอกตอนสมาธิยังอยู่ · รูปเป็นของเสริม · และเป็นขั้นเดียวที่เรียกกล้อง (เสี่ยง P3) จึงอยู่ใกล้ปลายทางที่สุด · trade-off: ผู้จัดการที่อยากถ่ายก่อนแล้วค่อยกรอกทำไม่ได้ (ไม่เห็นว่าจำเป็น)

│ ช่างทุกขั้นเห็นรูปนี้               │
├────────────────────────────────────┤
│ [          ถัดไป          ]        │ StickyAction · BigButton 56–60px
└────────────────────────────────────┘
```
- **ปุ่มหลักเดียวของจอ = sticky ล่าง**: มีรูป ≥ 1 → `ถัดไป` (primary) · ไม่มีรูป → `ข้าม ไม่ใส่รูป` (**secondary tone** — กันคนกดข้ามโดยไม่ตั้งใจแล้วคิดว่าเป็นปุ่มหลัก ทั้งที่ไม่ใช่ด่าน) · ระหว่างมีรูปกำลังย่อ → `ถัดไป` aria-disabled "รอย่อรูป…" (กันไปต่อก่อนย่อเสร็จ)
- ปุ่มเพิ่มอยู่**เหนือ**ภาพย่อ ตำแหน่งนิ่ง (D3 ของ ux-job-photos) · ปุ่ม 2 ใบเมื่อ `pointer: coarse` · ไม่ตรวจว่าปฏิเสธกล้อง (D5)
- ภาพย่อ 3 คอลัมน์ ≈ 104px (เนื้อหา 328 − 2×8 gap = 104) — ไม่ใช้ 2 คอลัมน์แบบออฟฟิศ เพราะ 3 รูปพอดีหนึ่งแถว เห็นครบไม่ต้องเลื่อน · **ไม่วางปุ่ม × / ★ ทับภาพ** (ปุ่ม 44px สองปุ่มบนช่อง 104px = บังรูป + แตะพลาด) → แตะภาพ = viewer ที่มีแถบจัดการ (ตรง D2 ของออฟฟิศ)
- รูปเรียง: **รูปหลักก่อน** แล้วตามลำดับที่เลือก · รูปแรกที่เพิ่ม = รูปหลักอัตโนมัติ · ลบรูปหลัก → รูปถัดไปเป็นหลักแทน (invariant ≥1 รูป ⇒ มีหลัก 1)
- **ย่อรูปตอนเลือก (ไม่ใช่ตอนส่ง)**: ทีละรูป (ไม่ขนาน) ช่องขึ้น spinner "กำลังย่อรูป…" · ผลลัพธ์ที่เก็บในเครื่อง = blob md+sm (≤ 2 MB/รูป ≤ 6 MB รวม) ไม่ถือไฟล์ต้นฉบับ 5–12 MB ×3 · ได้ error เร็วขณะผู้ใช้ยังแก้ได้ (ถ่ายใหม่ได้ทันที) แทนรู้หลังเปิดใบ

### 3.2 ช่องรูป (tile) — 4 สถานะ

| สถานะ | หน้าตา | แตะ | a11y label |
|---|---|---|---|
| กำลังย่อ | พื้น `zinc-200` + spinner + "กำลังย่อรูป…" (14px) | disabled | `aria-busy` "กำลังย่อรูปที่ 2" |
| พร้อม | ภาพ `sm` blob `object-cover` rounded-xl | เปิด viewer ที่รูปนี้ | "รูปที่ 2 จาก 3 · แตะเพื่อดู" |
| รูปหลัก | วงแหวนดำ 3px + แท็กขาว "★ รูปหลัก" มุมซ้ายบน (ไอคอน+คำ ไม่พึ่งสี) | เหมือนพร้อม | "รูปที่ 1 จาก 3 · รูปหลัก · แตะเพื่อดู" |
| (ไม่มี tile ล้ม) | ไฟล์ที่เปิดไม่ได้ **ไม่เป็นช่อง** — เป็นแถวแจ้งเหนือกริด (ข้างล่าง) เพราะข้อความ HEIC ยาวเกินช่อง 104px และไม่ควรกินโควตา 3 | — | — |

**viewer + แถบจัดการ (ก่อนเปิดใบ)**: `JobPhotoViewer` เดิม (`closeSize` = ช่าง 56px) · slot `renderActions`: `[★ ตั้งเป็นรูปหลัก]` (รูปหลัก → disabled "เป็นรูปหลักอยู่แล้ว") · `[เอารูปนี้ออก]` — **ไม่มีกล่องยืนยัน** (ยังไม่ถึง server ถ่ายใหม่ได้ทันที) + toast "เอารูปออกแล้ว" · ไม่มีเลื่อนซ้าย-ขวา-ลำดับ (≤ 3 รูป ใช้ ★ ตัวเดียว) · เอาออกรูปสุดท้าย = ปิด viewer เอง

### 3.3 แถวแจ้งไฟล์เปิดไม่ได้ (เหนือกริด · `role="alert"` · พื้น `red-50` ขอบ `red-700` · ข้อความ ≥ 16px · [ปิด] 44px)

| เหตุ | ข้อความ (ใช้ของเดิม) | หมายเหตุ |
|---|---|---|
| HEIC อ่านไม่ได้ | `ไฟล์ HEIC เปิดไม่ได้ — iPhone: ตั้งค่า > กล้อง > รูปแบบ > รองรับมากที่สุด แล้วถ่ายใหม่ หรือส่งผ่าน LINE ก่อน` | เหมือน `HEIC_MESSAGE` |
| decode ไม่ได้ / ไฟล์เสีย | ข้อความเดิมของ `describeResizeError` (ไฟล์เสีย/เปิดไม่ได้) | |
| ย่อแล้วยังเกิน 1 MB | ข้อความเดิม "ย่อแล้วยังเกิน 1MB…" | |
| ต้นฉบับ > 30 MB | ข้อความเดิม | |
| เลือกเกินที่เหลือ | `เลือกมา 5 รูป ใส่ได้อีก 2 รูป — ตัด 3 รูปท้ายออก` (amber `role="status"` ไม่ใช่ error) | รับตามลำดับที่เลือก |

ขึ้นสูงสุด 3 แถว (ใหม่สุดก่อน) · แต่ละแถวบอกเลขลำดับที่เลือก เช่น `รูปที่ 3 ที่เลือก — …` เมื่อเลือกหลายรูปพร้อมกัน เพื่อให้รู้ว่าไฟล์ไหนพัง

### 3.4 ครบ 3 / empty / state ครบ 4

- **ครบ 3**: `PhotoAddButtons` ถูก**แทนด้วย**กล่อง `zinc-100` "ครบ 3 รูปแล้ว — เอารูปออกก่อนถ้าจะเพิ่ม" (`role="status"`, `tabIndex=-1` + ย้าย focus มาที่นี่ถ้า focus เดิมอยู่บนปุ่มที่เพิ่งหาย — กัน focus หล่น) · ตัวนับ `รูป 3/3`
- **รูปที่ 4 ผ่านการเลือกหลายไฟล์** → ตัดท้าย + แถบ amber (ข้างบน) · **รูปที่ 4 จากปุ่มถ่าย** ทำไม่ได้ (ปุ่มหายแล้ว)

| state | หน้าตา |
|---|---|
| loading | ช่องที่กำลังย่อ (spinner ต่อช่อง) · `ถัดไป` aria-disabled "รอย่อรูป…" · ไม่มี skeleton ระดับจอ (ไม่ได้ดึงข้อมูลจากเซิร์ฟเวอร์) |
| empty | กล่องเส้นประ `zinc-300` สูง ≈ 104px + ไอคอน `ImageOff` · **มี SKU**: `ยังไม่มีรูป — ไม่บังคับ ช่างดูจากชื่อและรหัสสินค้าได้` · **สินค้าใหม่ไม่มีรหัส**: `สินค้าใหม่ไม่มีรหัส — ถ่ายรูปให้ช่างรู้ว่าทำชิ้นไหน` (ตัวหนา · ไม่บล็อก — P6) · ปุ่มข้าม = secondary |
| error | แถวแจ้งไฟล์ §3.3 (ต่อไฟล์ · ไม่บล็อกขั้น) · ไม่มี error ระดับจอ (ยังไม่ส่งอะไรไป) · ไม่แสดงแถบ "ไม่มีเน็ต" ที่ W-5 (ไม่ต้องใช้เน็ตจนกว่าจะกดเปิดงาน) |
| success | ≥ 1 ภาพย่อ + ตัวนับ + `ถัดไป` primary |

กลับไปขั้นก่อนหน้าแล้วกลับมา: รูปคงอยู่ (state เดียวกับฟอร์ม) · เปลี่ยนคนที่ระบุตัว/`เปิดอีกใบ`/ฟอร์มถูกล้าง = **รูปหายพร้อมฟอร์ม** (revoke blob URL ทุกครั้ง) — ข้อความเดิม `MSG_FORM_CLEARED` ครอบคลุม (เติม "และรูป" ไม่จำเป็น — ฟอร์มทั้งก้อนหายอยู่แล้ว)

## 4. W-6/7 ทวน — delta

เพิ่ม**แถว "รูป" เป็นแถวสุดท้ายของการ์ดสรุป** (หลัง "แบบใหม่") — ไม่แทรกก่อน "ทำจาก/จำนวน" เพราะโลหะ/เนื้อ/จำนวนคือจุดตรวจ R6 สำคัญสุด ไม่ควรถูกดันลง (trade-off: Open6 ของเจ้าของวางรูปหลักไว้แถวสินค้า — แต่ shipped W1 ไม่มีรูปอยู่แถวนั้นอยู่แล้ว จึงไม่ย้ายของเดิม)

```
│ แบบใหม่       ไม่ใช่                                   │
│ รูป           ┌────┐┌────┐┌────┐  3 รูป        [แก้]   │ ← ภาพย่อ 56×56 (★ มุมเล็กบนรูปหลัก)
│               จะส่งหลังกด "เปิดงาน"                    │ 14–16px zinc-700
```
- มีรูป: ภาพย่อ 56px ได้ถึง 3 + `n รูป` + `จะส่งหลังกด "เปิดงาน"` · `[แก้]` (≥ 44px) → กลับ W-5 (รูปคงอยู่)
- ไม่มีรูป: `ไม่มีรูป` + `[เพิ่ม]` → W-5 (สินค้าใหม่ไม่มี SKU + ไม่มีรูป: เพิ่มบรรทัด `⚑ ช่างจะไม่เห็นภาพชิ้นงาน` ใช้ธง amber อ่อนเดียวกับ "ไม่มีรหัสสินค้า" — ไม่บล็อก)
- ข้อความท้ายจอ (ของเดิม "เปิดแล้วช่างเริ่มได้ทันที · ออฟฟิศจะ …") เมื่อมีรูปเติมบรรทัด: `ส่งรูป {n} รูปหลังเปิดงาน — อยู่หน้าจอนี้จนส่งเสร็จ`
- ระหว่างส่ง (`busy`): ปุ่ม `แก้` ของแถวรูป disabled เหมือนทุกแถว (fieldset เดิม) · ภาพย่อ `alt` = "รูปที่ 1 จาก 3"
- **รูปไม่ถูกส่งไปกับคำขอเปิดใบ** — error §B.8 ทุกเคสไม่แตะรูป (ยังอยู่ในเครื่อง กดเปิดซ้ำได้ด้วย idem key เดิม)

state: loading = ปุ่ม "กำลังเปิดงาน…" เดิม · empty = "ไม่มีรูป" · error = §B.8 เดิม · success = W-8

## 5. W-8a / W-8b — ส่งรูป + จัดการหลังเปิด

### 5.1 แถวส่งรูป (ใช้ "แถว" ไม่ใช่ช่องภาพ — จอนี้เน้นสถานะ/ข้อความ/ปุ่มลองใหม่ ช่อง 104px ใส่ไม่พอ)

```
┌ รูปจากหน้างาน ──────────── รูป 2/3 ┐   หัวการ์ด: ชื่อ + ตัวนับ "ส่งแล้ว/ทั้งหมด" (live)
│ ┌────┐ รูปที่ 1 · ★ รูปหลัก          │   thumb 56×56 = ปุ่มเปิด viewer
│ │ ✓  │ ✓ ส่งแล้ว                     │
│ └────┘                               │
│ ┌────┐ รูปที่ 2                      │
│ │ ↑  │ กำลังส่ง…  ▰▰▰▱ (วิ่ง)         │   แถบ indeterminate (server action ไม่มี %)
│ └────┘                               │
│ ┌────┐ รูปที่ 3                      │
│ │ ⚠  │ ⚠ ส่งไม่สำเร็จ — ไม่มีเน็ต      │
│ └────┘ [ ลองใหม่ ]  [ เอาออก ]        │   ปุ่ม 48–56px · ลองใหม่ = primary ของแถว
│ อย่าปิดหน้านี้ · อย่าล็อกจอ           │   amber 16px · เฉพาะตอนมีรูปค้างส่ง
└──────────────────────────────────────┘
```
สถานะแถว (ไม่พึ่งสีอย่างเดียว: ไอคอน + คำ):

| สถานะ | ข้อความแถว | ปุ่ม |
|---|---|---|
| รอคิว | `รอคิวส่ง` | — |
| กำลังส่ง | `กำลังส่ง…` + แถบวิ่ง | — |
| สำเร็จ | `✓ ส่งแล้ว` (เขียว `green-800`) | แตะ thumb = viewer |
| ล้ม ลองใหม่ได้ (เน็ต/ทั่วไป/หมดเวลา) | `⚠ ส่งไม่สำเร็จ — {เหตุผลสั้น}` | `ลองใหม่` · `เอาออก` |
| ล้ม ลองใหม่ไม่ช่วย (ครบ 3 · ใบปิด/ยกเลิก · ไม่ใช่ผู้เปิด) | `⚠ {เหตุผล}` | `เอาออก` |
| ล็อก (ช่างรับงานแล้ว) รูปที่ยังไม่ได้ส่ง | `ไม่ได้ส่ง — ช่างรับงานแล้ว` | `เอาออก` |

- ส่ง **ทีละรูป เรียงรูปหลักก่อน** อัตโนมัติทันทีที่เข้า W-8 (ไม่ต้องกดอะไร) · แต่ละรูปมี idem key ของตัวเองสร้างตอนเลือก → ลองใหม่/กดซ้ำไม่เกิดรูปซ้ำ
- `ลองใหม่ทั้งหมด (n รูป)` เมื่อล้ม ≥ 2 และเน็ตกลับมา (pattern ของออฟฟิศ — ไม่ส่งเองอัตโนมัติ)
- session หมดเวลากลางส่ง → แถวล้มด้วย `หมดเวลาแล้ว — ใส่ PIN ใหม่` + แถบมี `ใส่ PIN ใหม่` (เรียก `onSessionLost` เดิม) → ใส่แล้วกลับมากด `ลองใหม่` · ⚠ ต้องแน่ใจว่าแผ่น PIN ซ้อน **ไม่ unmount** `ShopOpenFlow` (QR/ไฟล์อยู่ใน state) — วันนี้ฟอร์ม "ซ่อน" เฉยๆ ตรวจซ้ำ
- `aria-live="polite"` บรรทัดซ่อนสรุป: `กำลังส่งรูป 2 จาก 3` / `ส่งรูปครบ 3 รูปแล้ว` / `ส่งไม่สำเร็จ 1 รูป` (เปลี่ยนเมื่อสถานะเปลี่ยน ไม่อ่านทุกเฟรม)

### 5.2 หลังส่งครบ — แถบพับ (กันดัน QR ลงล่าง)

```
│ ┌──┐┌──┐┌──┐ ✓ ส่งรูปแล้ว 3 รูป                 │ thumb 40px
│ └──┘└──┘└──┘ แก้ได้จนช่างเริ่มรับงาน   [จัดการ ▾] │ ปุ่ม 44px · aria-expanded
```
- `จัดการ ▾` ขยายเป็นแถวด้านบน + ปุ่มเพิ่มรูป (ถ้ายังไม่ครบ 3) · แตะ thumb = viewer แถบจัดการ: `★ ตั้งเป็นรูปหลัก` · `ลบรูปนี้`
- **ลบรูปที่ส่งแล้ว = มีกล่องยืนยัน** (ถึง server แล้ว กู้ไม่ได้): `ลบรูปนี้? ลบแล้วกู้คืนไม่ได้` [ลบรูป] (danger) / [ยกเลิก] (focus เริ่มที่ยกเลิก · ปุ่มเรียงเหมือนกล่องอื่นของแอปช่าง) · ไม่ต้องใส่เหตุผล (เป็นรูปของตัวเอง — เหตุผลบังคับเฉพาะฝั่งออฟฟิศลบรูปคนอื่น §6)
- ★ ตั้งหลัก: optimistic + toast `ตั้งเป็นรูปหลักแล้ว` · ล้ม → ย้อน + ข้อความ
- เพิ่มรูปหลังเปิด = ย่อ → เข้าคิวส่งทันที (แถวใหม่ท้ายรายการ) · ตัวนับ `รูป n/3`
- แถบมีข้อความใน `จัดการ`: `ออกจากหน้านี้แล้ว กลับมาแก้ได้ที่ "ใบที่ฉันเปิด" จนช่างเริ่มรับงาน` (Q1=B — แทนข้อความเดิม "แก้ได้เฉพาะจอนี้")

### 5.3 W-8a สำเร็จ — ลำดับบนจอ + QR gate + **รูปหลักคู่ QR**

│ │  รูปหลัก  │ │       QR         │ │  QR 184×184 (เดิม 200 → ลด 16px เพื่อให้วางคู่ใน 328px)

└────────────────────────────────────┘
```
- เฉพาะใบที่มีรูป (≥ 1) · ใบไม่มีรูป = QR 200px ตรงกลางเดิม (DOM เดิม) · ใช้รูปหลักที่ผู้จัดการเลือก **จากไฟล์ในเครื่อง** (ไม่รอ signed URL) — ถ้ารูปหลักยังส่งไม่สำเร็จ/ล้ม ภาพคงอยู่แต่มีป้าย `⚠ ยังไม่ได้ส่ง` ทับมุมล่าง (กันผู้จัดการเข้าใจว่าช่างจะเห็นแล้ว)
- ระหว่าง QR gate: ช่องรูปหลักแสดงตามปกติ (+ ป้าย `กำลังส่ง…`) ช่อง QR เป็นกล่อง sky ขนาดเท่ากัน
- ตัด QR 200 → 184px: **ต้อง validate สแกนได้จากมือถือช่างที่ระยะยื่นจอ** (§13 ข้อ 10) · ถ้าไม่ผ่าน ให้วางแนวตั้ง (รูป 96px แถบบน, QR 200 ล่าง) แทน — ยอมดัน QR ลงล่าง
- ถ้า QR สร้างไม่ได้ (เดิม `svg === null`) → ช่อง QR ไม่ render; รูปหลักตรงกลางเดี่ยวไม่ต้องมี (ไม่แสดงรูปโดดๆ ที่ไม่มีคู่)

| สภาพ | QR | ที่เหลือ |
|---|---|---|
| **ไม่เลือกรูปเลย** | แสดงทันที (**W-8a เดิมทุกประการ**) | + แถวเดียวใต้ QR: `＋ เพิ่มรูป (ช่างจะเห็นตอนสแกน)` ปุ่มรอง 56px → ขยายเป็น `PhotoAddButtons` · เพิ่มแล้วเข้าสู่สภาพ "ส่งรูป" ข้างล่าง (QR คงอยู่ ไม่ซ่อนย้อนหลัง — ผู้จัดการอาจยื่นจอไปแล้ว) |
| **กำลังส่งรูป** (ส่งรูปชุดเปิดใบ) | **ซ่อน** แทนด้วยกล่อง `sky` "QR จะขึ้นเมื่อส่งรูปครบ — ให้ช่างรอก่อนสแกน จะได้เห็นรูปตอนรับงาน" + ลิงก์ `แสดง QR เลย (รูปที่เหลือส่งต่อได้ถ้าช่างยังไม่รับงาน)` ≥ 44px | การ์ดรูปขยาย |
| **ส่งครบ** | แสดง (focus ไม่ขยับ · live region ประกาศ `ส่งรูปครบแล้ว — QR พร้อมให้สแกน`) | แถบพับ §5.2 |
| **ส่งครบบางรูป มีล้ม (ไม่ busy)** | แสดง + กล่อง amber `รูปที่ 3 ยังไม่ได้ส่ง — ให้ช่างสแกนได้เลย แต่ช่างจะยังไม่เห็นรูปนั้น · ลองส่งใหม่ได้จนช่างรับงาน` | การ์ดรูปขยายค้าง |
| **ล็อก (ช่างรับแล้ว)** | แสดงตามเดิม (QR ไม่เกี่ยว) | แถบ `ช่างรับงานแล้ว แก้รูปไม่ได้ — แจ้งออฟฟิศ` (info) แทนปุ่มเพิ่ม/จัดการ · thumb ดูได้ ลบ/★ ไม่ได้ |

**ทำไมซ่อน QR (P2) ไม่ใช่แค่เตือน**: คนยื่นจอให้ช่างสแกนทันทีเป็นนิสัยจริง (W1 ใช้ข้อความ "ให้ช่างขั้นแรกสแกนจากจอนี้") — ข้อความเตือนอ่านไม่ทัน · QR สร้างในเครื่องอยู่แล้ว (ไม่เสียอะไรที่จะเลื่อนแสดง) · trade-off: เน็ตแย่ = ผู้จัดการรอ/ต้องกดข้าม (ต้อง validate §13 ข้อ 3) · ทางข้ามมี 1 ชั้นเสมอ ไม่ติดค้างทั้งงานหลัก

### 5.4 W-8b "เปิดไว้แล้ว" (กดซ้ำ/เน็ตสะดุด — ไม่มี QR)

- รูปยังอยู่ในหน้านี้ (คำขอเปิดแรกสำเร็จแต่ไม่ได้ตอบกลับ → ยังไม่เคยส่งรูปเลย) → **ส่งรูปทั้งหมดต่อได้ตามปกติ** ด้วยการ์ดรูปเดียวกัน (ไม่มี QR gate เพราะไม่มี QR)
- `เปิดอีกใบ` ยังไม่มี (ของเดิม) · `เสร็จแล้ว` ใช้ exit guard เดียวกัน
- ใบ `cancelled` (W-8 เดิม "ใบนี้ถูกยกเลิกแล้ว") = **ไม่แสดงการ์ดรูป** · รูปที่ค้างหายพร้อมหน้า
- หลัง reload = idem key + รูปหาย → เปิดซ้ำไม่ได้อยู่แล้ว (ไม่มีทางเข้า 8b) · ข้อความ 8b เดิม "ขอออฟฟิศพิมพ์ใบงานให้…" + เติมบรรทัดเมื่อเคยเลือกรูปไว้แต่ไม่ได้ส่ง: ไม่มีทางรู้หลัง reload จึงไม่เติม

### 5.5 Exit guard (กด `เสร็จแล้ว` / `เปิดอีกใบ` / ปุ่มกลับของเบราว์เซอร์ตอนยังมีรูปค้าง)

ค้าง = มีแถวสถานะ รอคิว/กำลังส่ง/ล้ม (ที่ไม่ใช่ล็อก) · แผ่น bottom sheet (ใช้ `Modal` เดิม/แบบ `JobCreateDialog`):

```
ยังส่งรูปไม่ครบ
รูปที่ 3 ยังไม่ได้ส่ง ถ้าออกตอนนี้รูปนั้นจะหาย
{ถ้ามี QR} และ QR ก็จะหายจากจอด้วย — ดูซ้ำไม่ได้ ต้องให้ออฟฟิศพิมพ์ใบให้ช่าง
ใบนี้ยังอยู่ใน "ใบที่ฉันเปิด" เพิ่มรูปใหม่ได้ถ้าช่างยังไม่รับงาน
[ กลับไปส่งรูปต่อ ]            ← primary · focus เริ่มที่นี่
[ ออกเลย — ทิ้งรูปที่ยังไม่ส่ง ]  ← secondary
```
(Q1=B: รูปที่ค้างหาย แต่ "ใบ" ไม่หาย — ผู้จัดการถ่ายใหม่แล้วเพิ่มจาก W-10 ได้ จึงลดความรุนแรงของ guard แต่ **QR ยังหายถาวร** จึงยังคงหัวข้อ "QR ก็จะหาย" เมื่อ QR ยังอยู่บนจอ)
- `beforeunload` เปิดเมื่อมีรูปค้าง (ข้อความมาตรฐานของเบราว์เซอร์ ปรับไม่ได้ · iOS Safari ไม่เรียกเสมอ → ข้อความ "อย่าปิดหน้านี้ · อย่าล็อกจอ" บนการ์ดคือด่านหลัก) · ไม่มีรูปค้าง = ออกได้ทันทีตามเดิม (ไม่เพิ่มขั้นให้ใบที่ไม่มีรูป)
- ล็อก (ช่างรับแล้ว) ที่ยังมีรูปไม่ได้ส่ง: guard ขึ้นด้วยข้อความ `รูปที่ไม่ได้ส่งจะหาย — ช่างรับงานแล้ว ส่งเพิ่มไม่ได้` (ไม่มีทางส่งต่อ → ปุ่มหลัก = `ออกจากหน้านี้`)

### 5.6 state ครบ 4 ของการ์ดรูป W-8

| state | หน้าตา |
|---|---|
| loading | แถวรอคิว/กำลังส่ง/แถบวิ่ง (ข้างบน) · QR gate |
| empty | ไม่เลือกรูป = แถวเดียว `＋ เพิ่มรูป` (ไม่มีการ์ด) |
| error | แถวล้มต่อรูป + banner เน็ต/PIN + ล็อก §5.1/§5.3 · ไม่มีรูปไหนทำให้ทั้งใบ "ล้ม" — ใบเปิดสำเร็จแล้วเสมอ |
| success | แถบพับ `✓ ส่งรูปแล้ว n รูป` |

แถบเน็ต: ไม่มีเน็ตระหว่างส่ง → แถว amber `ไม่มีอินเทอร์เน็ต — ส่งรูปไม่ได้ตอนนี้ ห้ามปิดหน้านี้` (ข้อความ pattern ออฟฟิศ) · เน็ตกลับมา: `เน็ตกลับมาแล้ว — แตะ "ลองใหม่" ที่รูปสีแดง`

|---|---|
| loading | หัว + แถบสถานะ skeleton + แถวรูป skeleton 2 แถว `role="status" aria-label="กำลังโหลดรูป"` · ปุ่ม `กลับ` ใช้ได้ |
| empty (แก้ได้ แต่ 0 รูป) | `ยังไม่มีรูป — ถ่ายให้ช่างดูได้จนช่างเริ่มรับงาน` + ปุ่มเพิ่มรูป · (ล็อก + 0 รูป) `ใบนี้ไม่มีรูป — ช่างรับงานแล้ว เพิ่มไม่ได้` |
| error | โหลดไม่ได้: `โหลดรูปไม่ได้ — เช็คสัญญาณแล้วลองอีกครั้ง` `[ลองอีกครั้ง]` (กลับได้) · ส่ง/ลบ/★ ล้ม = ตามแถวล้ม §5.1 / ข้อความเหนือปุ่ม |
| success | แถวรูป + ปุ่มเพิ่ม (หรือแถบล็อก) |

### 5A.3 สิทธิ์ที่ UI สมมติ (server เป็นด่านจริง — §14.2 R2/R8)
แก้รูปได้เมื่อ: ใบ open ∧ ผู้เรียก = ผู้เปิดใบ ∧ ขั้นแรกยังไม่ถูกรับ ∧ session ช่างยังไม่หมด · รูปที่แก้ได้ = รูป `source='shopfloor'` ของใบนี้เท่านั้น (รูปที่ออฟฟิศเพิ่ม/แคตตาล็อกผู้จัดการไม่เห็นในจอนี้ — ตัวนับ "n/3" นับเฉพาะรูปหน้างาน ตรง Q3=ก)

### 5A.4 QR ใบงานซ้ำ — **ไม่แสดง** (ข้อเสนอ — รอเจ้าของยืนยัน Q8)
- backend เก็บ hash ของ token → แสดงซ้ำไม่ได้ · จะแสดงซ้ำต้องออก token ใหม่ ซึ่งกินโควตา **5 ใบ/ใบงาน** และทำให้ QR เดิมที่ยื่นไปแล้วใช้ไม่ได้ (งงง่าย)
- **UX**: W-10 มีข้อความ `QR ใบงานแสดงซ้ำไม่ได้ — ให้ออฟฟิศพิมพ์ใบ A5 ให้ช่างสแกน` · ไม่มีปุ่ม "ออก QR ใหม่" บนหน้างาน
- **ผลที่ต้องรู้**: ถ้าผู้จัดการออกจาก W-8 ก่อนช่างสแกน ใบนั้นไปถึงช่างได้ทางเดียวคือ A5 จากออฟฟิศ (เหมือนที่ W1 บอกอยู่แล้ว "ขอออฟฟิศพิมพ์ใบให้") — Q1=B ให้ **แก้รูปได้** ไม่ได้ให้ **ส่งต่อให้ช่างได้** · ทางเลือกอื่น = ปุ่ม "ออก QR ใหม่" (เสียเพดาน + ต้องมีกล่องยืนยันแบบ QR ร้าน) — ไม่แนะนำรอบนี้
- **ความเสี่ยงเอกสารกระดาษ**: ถ้าออฟฟิศพิมพ์ A5 แล้วผู้จัดการเปลี่ยนรูปหลัก/ลบรูปทีหลัง กระดาษมีรูปเก่า (ช่างเห็นรูปปัจจุบันบนมือถือเสมอ) — ไม่มีสัญญาณบอกออฟฟิศ · ลดด้วยประวัติเหตุการณ์ใน OfficeAck/ใบงาน (§6) ไม่เพิ่มด่าน `[ต้องยืนยัน ว่ารับได้ — Q9]`

## 6. OfficeAck — แถบ "รูปจากหน้างาน" (PC · ภายในการ์ด `ProductionOfficeAckCard` ก่อนรับทราบ)

วางระหว่างตาราง "ที่หน้างานกรอก" กับแถว ⚠/ⓘ · แสดงเฉพาะการ์ดเต็ม (ก่อนรับทราบ) — หลังรับทราบการ์ดหดเป็นแถบเดียวตามเดิม (รูปดู/จัดการต่อที่ `JobPhotosCard` บนหน้าใบงาน)

```
┌ รูปจากหน้างาน · 3 รูป ────────────────────────────────────────────┐
│ ┌────────┐ ┌────────┐ ┌────────┐                                  │ thumb 96–112px · ≤ 3
│ │★ รูปหลัก│ │        │ │        │   แตะ/คลิก = viewer ใหญ่          │
│ └────────┘ └────────┘ └────────┘                                  │
│ ถ่าย/ส่งโดย หัวหน้าช่าง · วันนี้ 09:12 (จากหน้างาน)                 │ caption ครั้งเดียว (ถ้าทุกรูปมาจากหน้างาน)
└────────────────────────────────────────────────────────────────────┘
```
- ที่มา: ถ้าใบมีรูปหลายที่มา (หน้างาน + ออฟฟิศ + แคตตาล็อก) → **ป้ายต่อภาพ** `หน้างาน` (`Badge tone="blue"` เหมือน "จากหน้างาน") / `ออฟฟิศ` / `แคตตาล็อก` (ของเดิม) — ถ้าทุกรูปมาจากหน้างาน ใช้ caption เดียว (กันป้ายซ้ำสามอัน) · **`JobPhotosCard` บน /jobs/[id] ก็ได้ป้าย `หน้างาน` ด้วยกฎเดียวกัน** (ออฟฟิศต้องแยกรูปของผู้จัดการออกจากรูปที่ตัวเองถ่าย) · ชื่อผู้เปิดมาจาก `openedByWorkerName` ที่การ์ดโชว์อยู่แล้ว (ไม่เปิดชื่อเพิ่ม · ไม่โชว์ชื่อไฟล์/EXIF)
- viewer: `JobPhotoViewer` เดิม (`closeSize="office"`) + แถบจัดการ `JobPhotoManageBar` เดิม **ตัดปุ่มเลื่อน** (≤ 3 รูป ใช้ ★ ตัวเดียว) → `★ ตั้งเป็นรูปหลัก` · `ลบรูปนี้`
- **ลบรูปจากหน้างาน = บังคับเหตุผล** (มติเจ้าของ) — กล่อง `JobPhotoDeleteDialog` (เพิ่ม prop `requireReason`):
  ```
  ลบรูปนี้ออกจากใบงาน JB-0031?
  รูปนี้ผู้จัดการส่งจากหน้างาน · ลบแล้วกู้คืนไม่ได้ · ระบบจะบันทึกว่าใครลบและเพราะอะไร
  เหตุผล (บังคับ)  [ ไม่ใช่ชิ้นงาน ][ ภาพไม่ชัด ][ ไม่เหมาะสม ]   ← ชิปเติมข้อความในช่อง (แก้ต่อได้)
  [ textarea 3 บรรทัด · max 300 ตัว · นับตัวอักษร ]
  [ยกเลิก]  [ลบรูป] (aria-disabled จนเหตุผลมีอักขระจริง)
  ```
  ความยาว/รูปร่างตาม `JOB_PHOTO_REASON_MAX` (300) · "มีเหตุผล" ต้องใช้ validator เดียวกับที่ DB ตัดสิน (whitelist — ไม่ blacklist ช่องว่างเอง ตามบทเรียน `oem_note_present`) — frontend-dev จับคู่กับ RPC จริง · ปุ่ม `ลบรูป` ใช้ `aria-disabled` + บรรทัดบอกเหตุ "ใส่เหตุผลก่อนลบ" ไม่ใช่ disabled เงียบ
  รูปที่ออฟฟิศ/แคตตาล็อกลบ = กล่องเดิมไม่บังคับเหตุผล (ไม่เปลี่ยนพฤติกรรมที่ใช้อยู่)
- ★ ตั้งรูปหลัก: เหมือนออฟฟิศเดิม (optimistic + toast) · ออฟฟิศแก้ได้เสมอ **ไม่ผูกกับสถานะช่างรับงาน** (หน้าต่าง "จนช่างรับ" เป็นของผู้จัดการเท่านั้น)
- ปุ่ม `✓ รับทราบ · …` **ไม่ผูกกับรูป** (ไม่เพิ่ม checkbox/ด่าน — รูปไม่ใช่ด่าน จ5)

## 7. หน้าช่าง `/w/[token]` + A5 — **ไม่เปลี่ยน** (ยืนยัน)

- **ยืนยันตามมติ Q2 ("ช่างสแกน QR แล้วเห็นรูปเพื่อตรวจว่าถูกชิ้น")**: จากโค้ดที่ขึ้นแล้ว (`WorkerApp.tsx` — อ่านแล้ว) หน้าช่าง `/w/[token]` **หลังใส่ PIN** แสดงรูปหลักที่ **หัวหน้าจอ ข้างเลขใบงาน** ก่อนปุ่ม/ขั้นตอนทั้งหมด · แตะ = เต็มจอ ปัดดูทุกรูป · ไม่มีรูป = ไม่ render · **ช่างเห็นรูปได้หลังใส่ PIN เท่านั้น** (bucket private + ลิงก์ 15 นาที — ก่อน PIN ไม่เห็นรูปใดๆ; ถ้าเจ้าของหมายถึง "สแกนแล้วเห็นเลยไม่ต้อง PIN" = เปลี่ยนความปลอดภัย ต้องถาม architect/security — ไม่ทำในรอบนี้)
- ⚠️ **ขนาดจริงคือภาพย่อ 80×80 px ไม่ใช่รูปใหญ่** — ตรวจชิ้นงานได้ระดับ "ทรงนี้ใช่ไหม" ไม่ใช่ดูรายละเอียด (ต้องแตะขยาย) · ถ้าเจ้าของต้องการให้เด่นกว่านี้ (เช่นรูปกว้างเต็มจอ ~160 px บนหัว) = เปลี่ยนจอช่างที่ใช้อยู่ และดันปุ่ม sticky (ความเสี่ยงเดิมที่ ux-job-photos §3.7 เตือน) — **ไม่เปลี่ยนรอบนี้** เสนอเป็น Q10 + validate ข้อ 11
- หน้าช่าง (เดิม): ภาพย่อ 80×80 มุมขวาบนข้างเลขใบ = **รูปหลัก** เหมือน `ux-job-photos.md` §3.7
- A5 (`JobSheet`): รูปหลัก 30×30 มม. ลอยในหัวใบ **ติด QR** (รูปมาคู่ QR บนกระดาษอยู่แล้ว — ตรงมติ Q2) · ใบไม่มีรูป = layout เดิม · กฎกันกรอบว่าง/ตกกลับ/ตัววัดความสูง ตาม §3.6 เดิม
- ช่างไม่เห็น: ที่มาของรูป (หน้างาน/ออฟฟิศ) · ผู้ส่ง · เหตุผลลบ — `sanitizeWorkerView` allowlist `photos: {id, smUrl, mdUrl}` เดิมพอ **ไม่ต้องเพิ่ม field**
- ผลต่อเนื่องที่ต้องรู้ (ไม่ใช่งานเพิ่ม): ใบ A5 ที่ออฟฟิศพิมพ์ **ก่อน** ผู้จัดการเพิ่ม/เปลี่ยนรูปหลักที่ W-8/W-10 ไม่มีรูปนั้นบนกระดาษ — ช่างเห็นผ่านมือถือเสมอ (กฎ Q3 ของ ux-job-photos เดิม) · การเปลี่ยนรูปหลักหลังช่างรับ = ทำไม่ได้โดยผู้จัดการ (ล็อก) จึงไม่กระทบกระดาษที่ช่างถืออยู่ · **ช่วงที่กระดาษอาจเก่ากว่ารูปจริง** = หลังออฟฟิศพิมพ์ ก่อนช่างรับ (Q1=B ทำให้ช่วงนี้เกิดได้จริง) — ดู §5A.4

| 360px | กริด 3 คอลัมน์ ≈ 104px · แถว W-8 ข้อความ `break-words` ≤ 2 บรรทัด + ปุ่มลงบรรทัดใหม่ได้ (`flex-wrap`) · ไม่มี overflow แนวนอน |
| รูปแนวตั้ง/นอน | ช่อง/ thumb `object-cover` · viewer `object-contain` (ไม่ตัดชิ้นงาน) |
| ตัวเลขเยอะ | ตัวนับ ≤ "3/3" · "รูป n/3" · ไม่มีเลขอื่น |

## 12. Design decision + trade-off

| # | ตัดสินใจ | ทำไม ไม่ใช่แบบอื่น | แลกกับอะไร |
|---|---|---|---|

## 13. ต้อง validate กับผู้ใช้จริง (design จับ usability ไม่ได้)

ผู้จัดการ/ช่าง ≥ 3 คน (Android รุ่นล่าง 1 · iPhone 1 · สายตาไม่ดี 1) · มือถือของตัวเอง · ไม่อธิบายก่อน
1. 🔴 **กล้องแล้วหน้า reload ไหม** — ถ่าย 3 รูปติดกันบนเครื่องรุ่นล่าง (RAM น้อย) ที่ขั้น W-5 แล้ววัด: wizard ยังอยู่ไหม (ตัดสินว่าต้องทำ draft ลง storage หรือไม่ · P3)
2. 🔴 **ผู้จัดการทำอะไรทันทีหลังเปิดสำเร็จ**: ยื่นจอให้ช่างสแกนเลยไหม · ช่างสแกนแล้วรับงานภายในกี่วินาที — เทียบกับเวลาส่งรูปจริง 3 รูปบนเน็ตหน้างาน (วัด วินาที/รูป) → ยืนยันว่าการซ่อน QR (D6) คุ้ม หรือทำให้หงุดหงิด
3. เน็ตอ่อน (Wi-Fi โรงงานหรือ 4G ตามจริง): ผู้จัดการกด "แสดง QR เลย" บ่อยไหม · ข้อความ "QR จะขึ้นเมื่อส่งรูปครบ" เข้าใจไหม
4. หลังส่งครบ ผู้จัดการรู้ไหมว่าออกจากจอแล้วกลับมาแก้ได้ที่ "ใบที่ฉันเปิด" (ถามว่าถ้าลืมถ่ายรูปที่ 3 ตอนนี้จะทำยังไง) — และรู้ไหมว่า QR ใบงานดูซ้ำไม่ได้
5. ปุ่ม "ข้าม ไม่ใส่รูป" (secondary) — ผู้จัดการหาเจอไหม หรือคิดว่าต้องใส่รูป
6. สินค้าใหม่ไม่มี SKU: ใส่รูปบ่อยแค่ไหน (วัดสัดส่วนใบไม่มี SKU + ไม่มีรูป หลังใช้ 2 สัปดาห์)
7. iPhone: ถ่าย HEIC แล้วข้อความแนะนำตั้งค่ากล้องทำตามได้ไหม · "เลือกจากคลัง" ได้รูปที่เพิ่งถ่ายไหม
8. ออฟฟิศ: เจอรูปจากหน้างานใน OfficeAck ภายใน 5 วินาที · ลบพร้อมเหตุผลทำได้โดยไม่ถาม · ป้ายที่มาเข้าใจไหม
9. ภาพย่อ 104px พอให้ผู้จัดการรู้ว่ารูปไหนเป็นรูปไหนไหม (รูปหลักก่อน)
10. 🔴 **QR 184px คู่รูปหลัก 128px สแกนได้ไหม** จากมือถือช่างที่ยื่นจอ ระยะแขน/แสงโรงงาน (จอเปียก/แสงสะท้อน) — ไม่ผ่าน → วางแนวตั้ง QR 200px
11. **ช่างตรวจ "ถูกชิ้น" จากภาพ 80px ที่หัวหน้าช่างได้ไหม** (ไม่ให้อ่านชื่อ/JB): ยื่นมือถือช่างสแกน → ใส่ PIN → ถามว่าชิ้นนี้คืออะไร · นับกี่คนต้องแตะขยาย (ตัดสิน Q10)
12. **"ใบที่ฉันเปิด"**: ผู้จัดการหาใบที่เพิ่งเปิดเจอใน 5 วินาทีไหม · เข้าใจป้าย `แก้ได้` / `ช่างรับงานแล้ว` ไหม · เปิดการ์ดล็อกแล้วเข้าใจว่าทำไมแก้ไม่ได้ไหม · ผู้จัดการคาดหวังว่าจะเห็น QR ซ้ำไหม (ตัดสิน Q8) · จำนวนใบที่เปิดต่อวันจริง (ตัดสินว่า "5 ใบแรก + ดูทั้งหมด" พอไหม)
