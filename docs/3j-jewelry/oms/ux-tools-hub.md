## 1. User flow + IA

```
ที่มา (LINE ริชเมนู / 3jthailand.com / IG-FB bio)
        │ ลูกค้ามี "ความตั้งใจ" 3 แบบ (ไม่ใช่เส้นทางเดียว)
        ▼
   ┌── HUB ──┐   อ่านหัวเรื่อง 1 บรรทัด → เลือก 1 การ์ด (≤ 5 วินาที)
   ▼         ▼           ▼
 ดูแหวน    ทำแบบทดสอบ    วัดไซซ์
 (ring-    (gem-quiz)    (ring-size)
 builder)     │              │
   ▲          └─ ผล → ring-builder (มีอยู่แล้ว)
   └──────────────┴─ "ไม่รู้ไซซ์?" → ring-size → กลับ ring-builder (มีอยู่แล้ว)
 ทุกหน้า ── มาร์ก 3J (กดได้) ──► HUB
 จบที่: ring-builder → "ส่งให้แอดมินทาง LINE" (ปลายทางเดียวของทั้งชุดเครื่องมือ)
```

IA: hub ไม่เก็บข้อมูล ไม่มี state ที่ต้องกรอก · ไม่มี search/filter · 3 การ์ด + 1 แถวติดต่อ + 1 บรรทัดหมายเหตุ

Edge path: ลูกค้าเข้า hub ตอน JS ยังไม่ทำงาน/LINE browser ช้า → การ์ดเป็น `<a>` ธรรมดาใช้ได้ทันที (ข้อ 4)

## 2. ลำดับการ์ด + เหตุผล

**ลำดับ: 1) ดูแหวน → 2) แบบทดสอบพลอย → 3) วัดไซซ์** (ต่างจากลำดับที่เจ้าของพูด — เหตุผลด้านล่าง; เจ้าของสลับได้ ข้อ Q1)

| # | การ์ด | บทบาทใน funnel | เหตุผลที่อยู่ลำดับนี้ |
|---|---|---|---|
| 1 | ดูแหวน (/ring-builder) | **จุดปิดการขายเดียว** (ปุ่ม LINE อยู่ที่นี่) | quiz และ ring-size ต่างก็ส่งคนไปหน้านี้อยู่แล้ว · คนที่เข้าตรงจะเห็นแหวน+CZ ขาวทันที ไม่ต้องทำอะไรก่อน (friction ต่ำสุด) |
| 2 | แบบทดสอบพลอย (/gem-quiz) | เพิ่ม personal ให้ #1 (ผล → แหวนพร้อมพลอยของเขา) | เป็น "ทางอ้อมที่สนุก" เข้า #1 · ใช้เวลาสั้นสุดที่มีผลลัพธ์ในตัว (< 1 นาที) |
| 3 | วัดไซซ์ (/ring-size) | เครื่องมือสนับสนุน — ตัวเองไม่ทำให้เกิดการสั่ง | ต้องเตรียมเหรียญ/บัตร ใช้เวลานานกว่า · คนที่ "ตั้งใจมาวัดไซซ์" จริงมองหาเองเจอแน่เพราะชื่อการ์ดตรง |

Trade-off: ถ้าสัดส่วนคนมาจาก LINE ริชเมนูปุ่ม "วัดไซซ์" เยอะ การเอาไซซ์ไว้ท้ายเพิ่มการเลื่อน 1 จังหวะ → ลดความเสี่ยงด้วยการ **ให้ทั้ง 3 การ์ดมองเห็นพร้อมกันบน 375×667 โดยไม่ต้องเลื่อน** (ข้อ 5) และแนะนำให้ริชเมนู/ลิงก์ในแต่ละช่องทางไปตรงหน้าเครื่องมือเลย ไม่ผ่าน hub (hub สำหรับคนที่ไม่รู้จะเริ่มตรงไหน) · ต้อง validate ด้วยสถิติคลิก (ข้อ 8)

**Primary action เดียว:** การ์ด #1 ใช้สไตล์ filled (พื้น `--gq-burgundy` ตัวอักษรขาว — contrast #a2191d/ขาว ≈ 7.6:1 ผ่าน AA) · การ์ด #2–#3 สไตล์ outline (พื้นขาว ขอบ `--gq-border` ชื่อสี `--gq-burgundy-dark`) — ไม่ใช่ปุ่มหลัก 3 อัน

### Copy ต่อการ์ด (ไทยทั้งหมด)

| การ์ด | หัวข้อ | คำบรรยาย | meta chip (เวลา · ได้อะไร) | CTA |
|---|---|---|---|---|
| ดูแหวน | ดูแหวนและลองพลอย | ดูแหวนไขว้พลอยไข่ 2 เม็ด ลองสลับพลอยบนแหวน เลือกไซซ์ แล้วส่งให้แอดมินยืนยัน | `890 บาท · พรีออเดอร์ ทำภายใน 21 วัน` (ต้องมาจาก `formatPriceThb()` + `leadTimeLabel()` ห้ามพิมพ์เลข) | ดูแหวน |
| แบบทดสอบ | แบบทดสอบพลอยประจำวัน | ตอบ 5 คำถามสั้นๆ เพื่อดูพลอยที่เข้ากับวันของคุณ | `ไม่ถึง 1 นาที · ได้พลอยแนะนำ 3 แบบ` | ทำแบบทดสอบ |
| วัดไซซ์ | วัดไซซ์แหวน | วัดนิ้วด้วยหน้าจอมือถือ ไม่ต้องไปร้าน ไม่ต้องมีอุปกรณ์พิเศษ | `ไม่กี่นาที · ใช้เหรียญ 10 บาทหรือบัตร 1 ใบ` | วัดไซซ์ |

- เวลา "ไม่ถึง 1 นาที" มาจาก Landing เดิม · "ไม่กี่นาที / เหรียญหรือบัตร" มาจาก `COPY.r0` ของ ring-size (ใช้ประโยคเดิมไม่แต่งใหม่)
- ราคา 890 เป็นราคาเดียวที่แสดงบน hub · เป็นราคา "ของแบบที่ดูได้" ไม่ใช่คำสัญญาอื่น · ไม่มีคำว่า "เพชร" · ไม่มีเคลมผลพลอย — คำบรรยายแบบทดสอบใช้ "เข้ากับวันของคุณ" (เชิงสนุก) ไม่ใช่ "นำโชค/เสริมดวง"
- ตัวหน้าที่: หัวเรื่อง hub (h1) = `เครื่องมือเลือกแหวนของ 3J` · ประโยคใต้ = `เริ่มจากสิ่งที่อยากทำตอนนี้` (ตัด "ใช้ฟรี ไม่ต้องสมัคร" แล้ว — มติ 18 พ.ย. ท้ายไฟล์)

## 3. ผลล่าสุดบน hub (localStorage)

**ตัดสินใจ: แสดงเฉพาะ "เบอร์แหวนล่าสุด" บนการ์ดวัดไซซ์ · ไม่แสดงผลพลอย · ไม่แสดงอะไรจาก quiz นอกจากไม่มีเลย**

| ข้อมูล | แสดงไหม | เหตุผล |
|---|---|---|
| เบอร์แหวนล่าสุด (`getLastMeasuredSize`) | ✅ chip เล็กบนการ์ดวัดไซซ์: `ผลวัดล่าสุด: เบอร์ N` + ปุ่มรอง `วัดใหม่` (= ลิงก์การ์ดเดิม) | ตัวเลขอย่างเดียว ไม่ระบุตัวตน/ขนาดนิ้วจริงเป็น มม. (ไม่โชว์ `circ`) · reuse `LAST_MEASURED` copy ที่ ring-builder ใช้แล้ว |
| ผลพลอย/เรื่องที่เลือก | ❌ | ไม่ได้เก็บใน localStorage อยู่แล้ว · เป็นข้อมูลความเชื่อ/ความตั้งใจส่วนตัว ไม่ควรเด้งบนหน้ารวม (เครื่องแชร์ในครอบครัวได้) |
| "เคยทำ quiz แล้ว" (`DONE_KEY`) | ❌ ไม่แสดง | ไม่มีข้อมูลที่ให้ประโยชน์ต่อการเลือก · เพิ่ม key ผูกข้ามหน้าโดยไม่จำเป็น (over-design) |
| วันที่/เวลาวัด (`savedAt`) | ❌ | ไม่ต้องใช้ · ลดข้อมูลบนหน้า |

กติกา: อ่านใน `useEffect` หลัง mount เท่านั้น (hydration — แบบเดียวกับ RingShowcaseClient) · try/catch · ค่าเสีย/ถูกบล็อก/นอกช่วง = เหมือนไม่เคยวัด (ไม่ขึ้น error) · ถ้า `inShopRange=false` ไม่แสดง chip (ไม่ต้องให้ hub ตัดสินเรื่องนอกช่วง ปล่อยให้ ring-builder แจ้ง) · chip มี `aria-live="polite"` ไม่จำเป็น — ใช้ข้อความธรรมดาในการ์ดก็พอ เพื่อไม่ให้ screen reader อ่านซ้ำ

**⚠️ ข้อจำกัดโดเมน (Yoda ต้องยืนยัน):** localStorage ผูกกับ origin — ถ้า hub อยู่ `tools.3jthailand.com` แต่ `/ring-size` ยังอยู่ `app.3jthailand.com` หรือโดเมนอื่น chip นี้จะ **ไม่เห็นข้อมูลเลย** (ไม่ error แค่ไม่ขึ้น) และผลวัดเดิมของลูกค้าที่เคยวัดบนโดเมนเก่าจะหายหลังย้าย · ถ้า 3 หน้าย้ายไปอยู่ tools.* ทั้งหมด ก็คือลูกค้าเก่าต้องวัดใหม่ 1 ครั้ง (ไม่เสียหาย แต่ต้องรู้) · ถ้า origin ไม่ตรงกัน → ตัด chip ออกจาก v1 (ฟังก์ชันที่เหลือครบ)

## 4. ทางกลับ hub — component ที่เพิ่มในหน้าเดิม (ไม่รื้อ)

หลักการ: **ทำให้มาร์ก/โลโก้ 3J ที่มีอยู่แล้วกดกลับ hub ได้** ไม่เพิ่มปุ่มข้อความใหม่ใน header (header แต่ละหน้ามี back/ตัวนับ/ขั้นตอนครบแล้ว) · ทุกที่ target ≥ 44×44 px · `aria-label="กลับหน้าเครื่องมือ 3J"`

| หน้า | จุดที่ทำ | การแก้ | ผลกระทบ/ความเสี่ยง |
|---|---|---|---|
| /ring-size | `RsHeader` — `<img 3j-mark>` ขวาบน | ห่อด้วย `<a href={HUB_URL}>` + padding ให้ได้ 44×44 | เสี่ยงกดพลาดทิ้งงานกลางทาง (กำลังปรับวงกลมขนาด) → ให้แสดงเป็นลิงก์เฉพาะเมื่อ `step === null` (หน้าแรก R0 + หน้าผล) ส่วนระหว่างทำ = รูปเฉยๆ ตามเดิม · ทางออกกลางทางคือ back ของเบราว์เซอร์ |
| /ring-builder | ปัจจุบันไม่มี header ถ้าเพิ่ม: แถบบางบนสุด (ในคอลัมน์ข้อความ ก่อน `<header>` ของหน้า) | **เพิ่ม `ToolsHubLink`**: ข้อความ `← เครื่องมือ 3J` ขนาดเล็ก ลิงก์ ไม่ใช่ปุ่มหลัก | หน้านี้ไม่มี state ที่เสียได้เกินการเลือกพลอย (URL เก็บ state ให้แล้ว) จึงเปิดลิงก์ได้ตลอด |
| /gem-quiz Landing | เพิ่มลิงก์ข้อความเล็กใต้ปุ่ม "เริ่มทำแบบทดสอบ" | `← เครื่องมือ 3J` | Landing = ยังไม่มี state |
| /gem-quiz Q1–Q5 | **ไม่เพิ่ม** | มาร์ก "3J" ใน QuizHeader คงเป็นข้อความธรรมดา | กัน back ชนกัน + กันกดพลาดกลาง quiz (เสียคำตอบ) |
| /gem-quiz Result | ไม่แก้ | ผลมีปุ่มไป ring-builder อยู่แล้ว (ปุ่มหลักเดียว) — ring-builder มี `ToolsHubLink` ให้ต่อ | ไม่เพิ่ม action บนหน้าผล |

**Component ใหม่ที่ 3 หน้าใช้ร่วม:** `ToolsHubLink` (ตัวอ่าน `HUB_URL` จาก config กลางจุดเดียวของ Yoda) — รับ prop `variant: "text" | "mark"` · ห้าม import ไฟล์ `use server` (กฎ `(quiz)`) · ห้ามแตะ `RsHeader` มากกว่าห่อ `<a>` · ไม่แก้ `(quiz)/layout.tsx`

เมื่อลิงก์ข้ามโดเมน: ใช้ `<a>` ธรรมดา ไม่ใช้ `next/link` (full navigation) · ไม่ใช้ `target=_blank` (ใน LINE browser เปิดแท็บใหม่ทำให้กลับยาก)

## 6. ปุ่มทัก LINE แอดมินบน hub — **มี แต่เป็นระดับรอง**

- เหตุผล: คนที่ "ไม่รู้ว่าจะเลือกอะไร" ต้องมีทางหนีไปคุยกับคน · แต่ถ้าใหญ่เท่าการ์ด จะแย่ง primary ของ "ดูแหวน" · และทั้งชุดมีจุดปิดการขายที่ LINE ใน ring-builder อยู่แล้ว
- รูปแบบ: outline button (ไม่ใช่ filled) ใต้การ์ด 3 · ข้อความ `ไม่แน่ใจจะเริ่มตรงไหน? ทักแอดมินได้` + ปุ่ม `ทักแอดมินทาง LINE`
- ลิงก์ = `LINE_OA_URL` จาก `lib/shop/line.ts` (ค่าที่เจ้าของยืนยัน) · เป็น `<a>` ธรรมดา **ไม่ส่งข้อความสำเร็จรูป** (hub ไม่มีข้อมูลให้ส่ง ต่างจาก ring-builder/ring-size)
- ไม่มีเบอร์โทร/อีเมล/ลิงก์ social อื่นบน hub — ค่าติดต่อนอกจาก LINE OA = `[ต้องยืนยัน]` ถ้าเจ้าของต้องการ
- ห้ามลิงก์ TikTok/Shopee ทุกตำแหน่ง (นโยบาย off-platform ไม่เกี่ยวกับหน้านี้โดยตรง แต่ห้ามตามคำสั่ง)

## 7. State ครบ 4 + edge

hub แทบไม่มีข้อมูลแบบ async — state จริงมี 2 จุดเท่านั้น: chip ผลวัด และ navigation

| State | พฤติกรรม |
|---|---|
| **Loading** | ไม่มี spinner — หน้าเป็น static render ทั้งหมด การ์ดแสดงทันที · chip ผลวัดโผล่หลัง mount (ไม่มี skeleton; ที่ว่างของ chip จอง `min-h` เล็กน้อยเฉพาะบรรทัดนั้นเพื่อกัน layout shift ไม่ต้อง — เลือก **ไม่จอง** เพราะการ์ดสูงพอ ถ้าโผล่จะดัน 18px ใต้การ์ด 3 ซึ่งเป็นท้ายสุด ไม่ดันการ์ดอื่น) |
| **Empty** | = ไม่เคยวัดไซซ์ / localStorage ว่าง/ถูกบล็อก → ไม่มี chip การ์ด 3 แสดงปกติ · ไม่แสดงข้อความ "ยังไม่มีผล" (เป็นเสียงรบกวนสำหรับลูกค้าใหม่ทุกคน) |
| **Error** | ① storage/parse พัง → เหมือน Empty (เงียบ) ② ลิงก์ปลายทางล่ม/โดเมนยังไม่ผูก → เป็น browser error ของเขา hub จัดการไม่ได้ (ดู Q4) ③ JS ไม่โหลด → การ์ดยังกดได้เพราะเป็น `<a>` · chip ไม่โผล่ (ยอมรับได้) |
| **Success** | = การ์ดครบ 3 + (ถ้ามี) chip เบอร์ + ปุ่ม LINE · "success" ของ hub = การกดเข้าการ์ดหนึ่ง ไม่มีหน้ายืนยัน |
| ข้อความยาวเกิน | ชื่อการ์ด `break-words`, คำบรรยายไม่ clamp (ภาษาไทยไม่มีช่องว่าง → ใส่ `[overflow-wrap:anywhere]`) · meta chip wrap หลายบรรทัดได้ ห้าม truncate ราคา |
| ตัวเลขเยอะ/ตัวใหญ่ (font scale 130%+) | การ์ดสูงตามเนื้อหา ไม่ fix height · ทั้งหน้าเลื่อนได้ · ทดสอบที่ 200% zoom |
| สิทธิ์ไม่พอ | ไม่เกี่ยว — หน้าสาธารณะ ไม่มี login |
| in-app browser (LINE) | ไม่ใช้ `window.open`/`target=_blank` · ไม่พึ่ง localStorage สำหรับฟังก์ชันหลัก · ทดสอบเครื่องจริง iOS+Android ใน LINE ก่อนประกาศ |

## 8. Accessibility

- โครง: `<main>` > `<h1>` > `<ul role="list">` ของ 3 การ์ด (แต่ละการ์ด = `<li>` > `<a>`) > แถวติดต่อใน `<section aria-labelledby>` · มี `<h2>` ซ่อนด้วย sr-only ไม่จำเป็น — ใช้ชื่อการ์ดเป็น `<h2>` อยู่ในลิงก์ (ชื่อ accessible = ชื่อ + คำบรรยาย)
- `<a>` ทั้งการ์ด (ไม่ใช่ `div onClick`) · ลูกศร `aria-hidden` · focus ring ใช้ `FOCUS` เดียวกับ ring-size (outline 2px สี brand offset 2px) · ลำดับ Tab = ลำดับภาพ (1→2→3→LINE)
- Contrast: การ์ด filled ขาวบน `#a2191d` ≈ 7.6:1 · ข้อความ muted `--gq-text-muted #6F6A66` บน `#fff` ≈ 5.3:1 ผ่าน AA · meta chip บนการ์ด filled ใช้พื้นขาวโปร่ง 15% + ตัวขาว ต้องตรวจจริงตอน implement (≥ 4.5:1) ถ้าไม่ผ่านให้ใช้ chip พื้นขาวตัวสี burgundy-dark
- Touch target: ทั้งการ์ด ≥ 96px สูง · ปุ่ม LINE สูง ≥ 48px · ลิงก์ `← เครื่องมือ 3J` ในหน้าอื่น area ≥ 44×44 (padding ไม่ใช่ขนาดตัวอักษร)
- `prefers-reduced-motion`: hover/press ใช้แค่เปลี่ยนสี ไม่มี animation ที่ต้องปิด (ถ้ามี fade-up เหมือน Landing ใช้ `motion-safe:` เหมือนเดิม)
- `lang="th"` ให้ root ตาม Yoda · ชื่อหน้า `<title>` = `เครื่องมือเลือกแหวน | 3J Jewelry` · `robots: noindex` ตามหน้าอื่นที่ยังเป็น demo (เปิดเมื่อเจ้าของสั่ง)

## 10. Design decision + trade-off

1. **การ์ดแนวตั้งเรียงลำดับ ไม่ทำ wizard ถามก่อน ("คุณอยากทำอะไร?" → ไปต่อ)** — wizard เพิ่ม 1 คลิกโดยไม่จำเป็นกับ 3 ตัวเลือก
2. **ring-builder เป็นการ์ดนำ** แม้เจ้าของลิสต์เป็นลำดับสุดท้าย — เพราะคือปลายทางเดียวที่มีปุ่มสั่ง (ข้อ 2)
3. **chip ผลวัดไซซ์: ใส่** — ลด friction ของคนกลับมา ต้นทุนต่ำ (reuse ฟังก์ชันเดิม) · **ผลพลอย: ไม่ใส่** — ข้อมูลไม่ได้ถูกเก็บ + อ่อนไหวกว่า
4. **ปุ่มกลับ hub ผ่านมาร์ก 3J/ลิงก์ข้อความเล็ก** แทนปุ่มใหม่ใน header — ไม่รื้อ header ที่คุมด้วย test เดิมจำนวนมาก (ring-size มี `_tests` เยอะ) · ไม่ใส่กลางทาง quiz/วัดไซซ์ เพื่อกันเสียงานของลูกค้า
5. **hub ไม่มีรูปแหวนจริง/3D/ราคาแยกชิ้น** — โหลดเร็วใน LINE browser · ลด risk ผิดกฎราคา · ไอคอน SVG ธรรมดาจาก set เดิม (`GemIcon` ใช้กับการ์ด quiz ได้)
6. **ไม่เพิ่ม feature ที่ไม่ได้ขอ:** ไม่มี search, ไม่มีแชร์, ไม่มีสถิติโชว์ลูกค้า, ไม่มี dark mode

### ต้อง validate กับผู้ใช้จริง
- ลูกค้า LINE กดการ์ดไหนก่อน (ต้องการ event คลิกต่อการ์ด — ถามทีม analytics ว่าจะวัดอย่างไรโดยไม่เพิ่ม PII; อย่าเพิ่ม tracking ที่ไม่ผ่านนโยบายเดิมของ ring-size `track`) — ใช้ตัดสินลำดับ
- "ดูแหวนและลองพลอย" เข้าใจไหมว่าเป็นหน้าสั่งซื้อ/ยังไม่ใช่สั่งจริง (ring-builder เขียน "ยังไม่ใช่การสั่งซื้อ" ไว้แล้ว)
- ลูกค้าเห็น chip "ผลวัดล่าสุด" แล้วสบายใจหรือสงสัยว่าเว็บจำข้อมูลเขา (ถ้ามี feedback ลบ → เพิ่มลิงก์ "ลบผลวัด" ไม่ใช่ตอนนี้)
- ทดสอบเครื่องจริงใน LINE iOS/Android: ลิงก์กลับ hub ไม่ถูกบล็อก

## 11. ช่องโหว่ / ข้อโต้แย้งต่อ requirement (พูดตรงๆ)

- คำสั่ง "ดูแหวน/ลองพลอยบนแหวน" ซ้อนกับ quiz: ถ้าลูกค้าเลือก "ดูแหวน" โดยตรงจะเห็น CZ ขาว + การ์ดชวนทำ quiz อยู่แล้ว → 2 การ์ดนี้ทับกันเชิงเนื้อหาบางส่วน ชื่อการ์ดต้องแยกชัด (การ์ด 1 = "ดูแหวน" การ์ด 2 = "หาพลอยที่เหมาะ") — copy ด้านบนทำแล้ว แต่ถ้าลูกค้าสับสนให้พิจารณาลดเหลือ 2 การ์ด + quiz เป็นทางผ่านของ ring-builder
- hub ที่แยกโดเมน (tools.*) ต่างจาก origin ของหน้าเดิม → ผล localStorage ข้ามกันไม่ได้ (ข้อ 3) และ Referer/OG ต้องตรวจ
