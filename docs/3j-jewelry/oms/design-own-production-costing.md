> สร้าง 19 ก.ย. 69 · เจ้าของสั่งเอง · **อัปเดต 21 ก.ย. 69**
>
> **สถานะ: 0140–0143 apply + merge + push แล้ว · หน้าจอขึ้น production แล้ว (58c82c0)**
> เหลือ `0144` (ช่องติ๊ก "แบบใหม่") — migration เขียนแล้ว ยังไม่ซ้อม ยังไม่ลง

>

## 1. โจทย์ — คำพูดเจ้าของ

เปิดหน้าใบผลิตแล้วสะดุดทันที:

> *"หน้าตาไม่เหมือนผลิต OEM เลย ไม่มีให้กรอกจำนวนกรัมหรือว่าผลิตแบบมีพลอยไหม แบบ เรียบ กลาง ยาก เลย ต้นทุนจะคำนวณยังไง"*

แล้วสั่งทางแก้เอง:

> *"จริงๆแค่อยากจะให้เอาผลิต OEM มาวางสำหรับผลิตเอง แต่ไม่คิด Margin ไม่ต้องคำนวณ floor แบบนี้"*

## 2. สภาพวันนี้ (ตรวจจาก DB จริง 19 ก.ย. 69)

| | ใบผลิตเข้าสต็อก | ใบเสนอราคา OEM |
|---|---|---|

| ตัวแปรที่ใช้ | **3 ตัว** — น้ำหนัก · ความบริสุทธิ์ · ค่าแรงก้อนเดียว | **34 ตัว** (กรอกครบแล้ว 34/34, 85 แถวรวม scope) |

| รู้จักพลอย (ราคา+ความเร็วฝัง แยกขนาด) | ❌ | ✅ |

| รู้จักน้ำหนักก้านต้น · โลหะที่หายตอนขัด · อัตราหลอมคืน | ❌ | ✅ |

**SKU โหมด `spot` มี 6 ตัว = เงินแท่งล้วน** · อีก 300 ตัวเป็น `fixed` (ตัวเลขพิมพ์มือ)
⇒ **เครื่องคิดไม่เคยถูกใช้กับงาน 925 เลย** ตรงกับที่เจ้าของรู้สึกว่า "แล้วมันคำนวณยังไง" — คำตอบคือมันไม่ได้คำนวณ

## 3. 🔴 กับดักที่ทำให้ทางแก้แบบแรกถูกทิ้ง

เครื่องคิด OEM **รวมเนื้อโลหะไว้ใน `cost_piece` แล้ว** (มี sprue loss · polish loss · recovery rate)
แต่ `production_cost_calc` **บวกเนื้อเงินแยกต่างหาก**

⇒ ถ้าเอา `cost_piece` ไปยัดใส่ช่อง `labor_cost` ตรงๆ = **นับเนื้อเงินสองรอบ ต้นทุนพองโดยตัวเลขยังดูสมเหตุสมผล**

**ทางที่เจ้าของเลือกปิดกับดักนี้ทิ้งไปเอง**: ใช้ต้นทุนต่อชิ้น**ทั้งก้อน**เป็นต้นทุนผลิต ไม่แยก ไม่บวกเนื้อเงินซ้ำ
⇒ ไม่ต้องแกะอะไรออกจากต้นทุนเลย

## 4. ข่าวดีจากการอ่านโค้ดจริง

- ใน `oem_price_calc` (0083 ราว บ.615): `cost_piece = metal + labor + batch` และ **margin ไม่แตะสามก้อนนี้** ใช้แค่ตอนคิด `price_piece`/`nre_price`/`margin_state`
  ⇒ **ชั้นต้นทุนแยกจากชั้นราคาอยู่แล้วในเชิงตรรกะ แค่ตัดที่รอยต่อที่มีอยู่**
- **`nre_cost` ไม่อยู่ใน `cost_piece`** อยู่แยกใน `breakdown.nre` คิดเฉพาะ `is_new_design = true`
  ⇒ คำถาม "เฉลี่ย NRE ด้วยอะไร" เป็นคำถามนโยบาย ไม่ใช่ปัญหาโค้ด

## 6. โครงที่จะทำ

```
public.product                          analytics.oem_cost_calc  (0140 — ชั้นต้นทุนล้วน)
  cost_type: fixed | spot | spec ──┐         ▲ oem_price_calc เรียก (ชั้นราคา/floor เดิม ไม่เปลี่ยนผลลัพธ์)
  silver_weight_g, silver_purity   │         ▲ production_cost_calc เรียก (branch 'spec')
  make_spec jsonb (0141)           │
        │                          ▼
production_order_item ──preview/done──▶ production_cost_calc(shop, product, spot, qty)
  cost_calc jsonb (0141 = snapshot)        ├ spot  → น้ำหนัก×ราคาเงิน×ความบริสุทธิ์+ค่าแรง (เดิม)
        │                                  ├ fixed → unit_cost (เดิม)
        ▼                                  └ spec  → oem_cost_calc(make_spec + น้ำหนัก + qty + ราคาเงิน) → cost_piece
analytics.stock_lot.unit_cost = round(cost_piece, 2)
```

`make_spec` = `{metal, item_kind, polish_tier, plating_type|null, gem_tier|null, gem_count, is_new_design}`
**น้ำหนัก/ความบริสุทธิ์ใช้คอลัมน์เดิม** `silver_weight_g`/`silver_purity` (fact หนึ่งอยู่ชั้นเดียว)

**3 โหมดอยู่ร่วมกันถาวร** — เงินแท่ง 6 ตัวใช้ `spot` ต่อไป ไม่ต้องไปกรอกฟอร์ม
หน้าจอมีป้ายบอกต่อบรรทัด: `กรอกเอง` · `น้ำหนัก×ราคาเงิน` · `คำนวณจากสเปค`

## 8. ตั้งใจไม่ทำเฟสแรก

- ไม่แตะ `v_dim_product.effective_unit_cost` / `transform_pending_order_lines` ⇒ **กำไรย้อนหลังของออเดอร์เก่าไม่ขยับ**
  (ต้นทุนจาก spec ไหลถึงกำไรทางเดียวคือผ่าน `stock_lot` → cutover ของงาน lot)
- ไม่แก้ `current_date` (UTC, trap #6) ใน `oem_price_calc` — แก้แล้ว golden replay จะไม่เท่า **จดเป็นหนี้แยก**
- ไม่รองรับ gold/brass (`production_spot_resolve` มีแค่ silver) ⇒ เฟสแรก `make_spec.metal` ต้องเป็น `silver`
- ไม่แปลง SKU เดิม 300 ตัวอัตโนมัติ — opt-in ต่อ SKU ถาวร ไม่บังคับ
- ไม่มี override สเปคต่อบรรทัดในใบผลิต (ถ้ารอบนี้ต่างจริง = SKU ใหม่ตามกติการ้าน)
- ไม่แตะ margin/floor/ราคาขาย/ส่วนลด/มัดจำ/VAT/ใบเสร็จ ทุกชนิด

## 9. ข้อควรระวังตอน implement

1. **ห้ามใบเสนอราคาที่ออกไปแล้วขยับแม้สตางค์เดียว** — มีใบเสร็จภาษีออกจริงแล้ว (ใบแรก `RT-2608-016`) · golden replay คือด่านเดียวที่จับได้
2. `_raw` (ค่าไม่ปัดเศษที่ส่งระหว่างสองชั้น) **ห้ามหลุดออกไปใน output** — ต้อง assert
3. `oem_cost_calc` **ห้ามมี fallback ราคาโลหะเมื่อถูกเรียกจากใบผลิต** — บังคับที่ตัวฟังก์ชัน ไม่พึ่งวินัย caller
4. `missing[]` ต้องเรียงเดิมทุกตัว — หน้าจอ OEM ใช้ลิสต์นี้บอกผู้ใช้ว่าต้องไปกรอกอะไร
5. ถ้าบน prod ไม่มีใบ jewelry จริงเลย (มีแต่ใบเงินแท่ง) **ชุดสังเคราะห์คือหลักฐานเดียว** ต้องครอบ gold ด้วย และเขียนกำกับไว้ว่าหลักฐานมาจากไหน
6. 🔴 **ตัวแปร 8 ตัวที่นิยามไว้แต่ไม่มีสูตรไหนอ่าน** (`admin_hours_per_job`, `capacity_pieces_per_day`, `fx_buffer_pct`, `lead_time_days_total`, `metal_supplier_credit_days`, `own_line_gp_thb_per_day`, `rubber_mold_life_uses`, `metal_purchase_premium_pct`) — **ห้ามไปต่อสายให้มันเอง** ตัวที่กระทบเงินคือตัวสุดท้าย ซึ่งเจ้าของตั้ง 0 ทั้งสามโลหะ ⇒ ไม่มีผล

## 10. เรื่องที่ต้องบอกเจ้าของระหว่างรอ

ตอนนี้ SKU ที่เลือกโหมด "คำนวณจากน้ำหนักเงิน" แล้ว**ปล่อยค่าแรงเป็น 0** จะได้ต้นทุน = เนื้อเงินล้วน
⇒ **margin ที่แสดงจะสูงเกินจริงเท่ากับค่าแรงที่หายไปทั้งก้อน** และไหลต่อไปถึงแดชบอร์ด/กำไรรายออเดอร์

ทางชั่วคราวจนกว่า 0140/0141 จะเสร็จ: ใช้หน้า **คิดราคา OEM** ทำใบทดลองด้วยสเปคจริง → ดูต้นทุนต่อชิ้น →
**ลบส่วนเนื้อเงินออก** → เอาที่เหลือใส่ช่อง "ค่าแรง/ค่าบล็อก"
(เลขประมาณที่ผิด 20% ยังใกล้ความจริงกว่าเลข 0 ที่ผิด 100%)
