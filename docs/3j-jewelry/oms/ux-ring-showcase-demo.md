# UX build spec — /ring-builder (DEMO "แบบของ 3J Jewelry")

ผู้เขียน: Padmé · 12 พ.ย. 69 · มือถือ 360–390 เป็นหลัก · `design-ring-showcase-demo.md` ยังไม่มีใน worktree ใช้สรุปจาก brief แทน
Token/ฟอนต์: ชุด `--gq-*` ของ quiz (ivory/burgundy) · `font-quiz-display`/`font-quiz-serif` · reuse `PrimaryButton` `GemIcon` · ห้ามสร้างสีใหม่

## 1. Flow
ผลquiz → ปุ่ม "ลองพลอยของคุณบนแหวน" (หลัง "ดูเครื่องประดับจากพลอยนี้" เดิม แทนที่ปุ่มนั้น) → `/ring-builder?g=a.b.c` → เลือกแบบ 1/2/3 → เลือกไซซ์ → ดูรูปจริง → ส่ง LINE / คัดลอก
เข้าตรง: เห็นแหวน CZ ขาว + การ์ดชวนทำ quiz → quiz → กลับมาพร้อม g
param เสีย/ซ้ำ/พลอยไม่รู้จัก = ถือว่าไม่มี param (ไม่ error)

## 2. ลำดับ section (มือถือ)
```
[stage ติดบน ~40dvh]  แหวน 3D หมุนได้ · มุมซ้ายบน "ภาพจำลอง" · มุมขวา "ลากเพื่อหมุน"
-- เลื่อนใต้ stage --
1 หัวข้อ "แหวนไขว้พลอยไข่ 2 เม็ด" [ชื่อชั่วคราว — ต้องยืนยัน: ชื่อแบบ] · "800 บาท · พรีออเดอร์ ทำภายใน 21 วัน"
2 "พลอยที่คุณเลือกได้" radiogroup แบบ 1/2/3 (การ์ดแนวตั้ง 3 ใบเต็มกว้าง)
  การ์ด: GemIcon บน+ล่าง · "แบบ 1" · "{เม็ดบน} + {เม็ดล่าง}" · ป้าย "อันดับ 1 จากแบบทดสอบ"
  ใต้การ์ดที่เลือก (aria-live=polite): GEM_QUIZ_PAIRS ของคู่นั้น title / th / "เหมาะกับ: {fit}" คำต่อคำ
  + "บน = พลอยหลักของแบบ · ล่าง = พลอยเสริม · CZ เล็ก 2 เม็ดมาพร้อมแหวน" (CZ ไม่ใช่เพชร)
3 "เลือกไซซ์" แถว 55 56 57 58 (ปุ่ม 48×48 เว้น 8) · ลิงก์ "ไม่รู้ไซซ์? วัดด้วยเครื่องมือวัดไซซ์" → `/ring-size`
4 "ดูของจริง" รูป 5 รูป สไลด์แนวนอน scroll-snap (กว้าง 80%) · เลื่อนต่อได้ด้วย swipe/ปุ่ม ‹ ›
5 การ์ดสรุป: แบบ · พลอยบน · พลอยล่าง · ไซซ์ · "800 บาท" · "ยังไม่ใช่การสั่งซื้อ — ส่งให้แอดมินยืนยันก่อน"
6 [ส่งให้แอดมินทาง LINE] (primary เดียว, 56px) · [คัดลอกข้อความ] (secondary)
7 disclaimer เดิม `GEM_QUIZ_DISCLAIMER` + "CZ คือคิวบิกเซอร์โคเนีย ไม่ใช่เพชร"
```
ลำดับ DOM = ลำดับ focus · stage เป็น `<section aria-label="ภาพแหวน">`
Desktop (≥1024): 2 คอลัมน์ กว้างสุด 1080 · ซ้าย stage sticky top-6 · ขวา section 1–3,5–7 · รูปจริงเต็มความกว้างใต้ทั้งสอง

## 3. ข้อความ
- LINE ปุ่ม: "ส่งให้แอดมินทาง LINE" · คัดลอก: "คัดลอกข้อความ"
- ข้อความ (โครง HANDOFF §5 ไม่มีรหัส/ชื่อลูกค้า):
```
สวัสดี ขอสั่งทำแหวนตามแบบนี้
แบบ: {ชื่อแบบ} · แบบ {n}
พลอยบน: {ชื่อ} · พลอยล่าง: {ชื่อ} · CZ เล็ก 2 เม็ด
ไซซ์: เบอร์ {n}   |   ไซซ์: รอแอดมินช่วยเช็ก
ราคา 800 บาท (พรีออเดอร์ ทำภายใน 21 วัน)
รบกวนยืนยันราคาและขั้นตอนต่อไป
```
- สร้างจาก helper ตัวเดียว · ลิงก์ = `lineOaMessageUrl(msg)` เป็น `<a>` ปกติ ห้ามพิมพ์ LINE ID/URL เอง

## 4. State
| State | ทำอย่างไร |
|---|---|
| โหลด 3D | stage แสดงรูปจริงรูปแรกเบลอ + "กำลังโหลดภาพ 3 มิติ…" (`role=status`) · ตัวเลือกกดได้ทันที |
| WebGL ใช้ไม่ได้/โหลดล้ม | stage = รูปจริงรูปแรก + "เครื่องนี้แสดงภาพ 3 มิติไม่ได้ ดูรูปจริงด้านล่างแทน" · พลอยเลือกได้ · ข้อความพลอยยังเปลี่ยน |
| มาจาก quiz | แบบ 1 ถูกเลือก · พลอยเริ่มต้น = แบบ 1 |
| เข้าตรง | แหวน CZ ขาว · แทนการ์ดแบบ 1/2/3 ด้วยการ์ด "อยากรู้ว่าพลอยไหนเหมาะกับคุณ? ทำแบบทดสอบ 1 นาที" → `/gem-quiz` · ยังเลือกไซซ์/ส่ง LINE ได้ (พลอย = "CZ ขาว") |
| ไม่เลือกไซซ์ | ปุ่ม LINE ยังกดได้ ไม่ disabled · แถบเหลืองเหนือปุ่ม "ยังไม่ได้เลือกไซซ์ — ส่งได้เลย แอดมินจะช่วยเช็กไซซ์ให้" · การ์ดสรุปแสดง "ไซซ์: รอแอดมินช่วยเช็ก" |
| แบบ 1 กับ 2 คู่เดิมสลับ | การ์ดใต้ชื่อมีป้าย "คู่เดียวกับแบบ n — สลับว่าเม็ดไหนอยู่บน" · ข้อความอธิบายใช้ GEM_QUIZ_PAIRS เดิม ซ้ำได้ |
| คัดลอกสำเร็จ | ปุ่มเปลี่ยน "คัดลอกแล้ว ✓" 3 วิ + `role=status` |
| คัดลอกไม่สำเร็จ | แสดง textarea read-only พร้อมข้อความ + "กดค้างเพื่อคัดลอกเอง" · ปุ่ม LINE ยังเปิดได้ |
| กลับจาก /ring-size | เก็บ g + แบบที่เลือกใน URL (`&d=2`) · ไซซ์จาก ring-size (query ที่หน้านั้นมีอยู่) แสดงเป็น "ผลวัดล่าสุด: เบอร์ n — ใช้เบอร์นี้" ปุ่มเสนอ ไม่เลือกให้ · นอก 55–58 = "ไซซ์นี้อยู่นอกช่วงของแบบนี้ ทักแอดมินได้" |
| รูปจริงโหลดไม่ได้ | กรอบ ivory + "รูปนี้โหลดไม่ได้" ปุ่ม "ลองอีกครั้ง" |
| ว่าง/ล้ม ทั่วไป | ไม่มีข้อมูลดึงจากเซิร์ฟเวอร์ ไม่มี loading เต็มหน้า |

## 5. a11y
- แบบ 1/2/3 = `role=radiogroup` + `aria-labelledby` · แต่ละใบ `role=radio` `aria-checked` · ลูกศรซ้ายขวาเปลี่ยน (roving tabindex) · ไซซ์ทำแบบเดียวกัน
- ทุกจุดแตะ ≥44px · ปุ่มหลัก 56px
- alt รูปจริง: "แหวนไขว้พลอยไข่ 2 เม็ด รูปที่ n จาก 5 — {มุมมอง}" `[ต้องยืนยัน: คำบรรยายแต่ละรูป]` · 3D canvas `role=img` + aria-label สรุปพลอยปัจจุบัน
- `prefers-reduced-motion`: ปิดหมุนอัตโนมัติ/fade ของ gq · หมุนด้วยมือยังได้ · ห้าม `touch-action:none` ทั้ง stage (ให้เลื่อนหน้าได้ — ใช้ `pan-y`)
- สีสถานะไม่ใช้สีอย่างเดียว · contrast ≥ 4.5:1 · ใช้ `dvh` + safe-area

## 6. Trade-off
- stage ติดบน 40% = เห็นผลทันทีที่เปลี่ยนพลอย แลกกับพื้นที่อ่านน้อยลง · ปุ่ม LINE ไม่ติดล่าง (ไม่แย่งจอ) · ถ้าเจ้าของอยากให้ติด เพิ่ม BottomBar ภายหลัง
- ไม่ disable ปุ่มเมื่อไม่มีไซซ์ = ไม่ขวางคนที่ไม่รู้ไซซ์ แลกกับข้อมูลไม่ครบ (แอดมินถามต่อ)

## 7. ห้ามทำ (Luke)
- ห้ามแต่งสรรพคุณ/คำสัญญาผล · ห้ามเรียก CZ ว่าเพชร · ห้ามแสดงสเปก/น้ำหนัก/ต้นทุน · ห้ามเทียบราคาเงิน
- ห้ามมีรหัส/QR/ฟอร์มข้อมูลส่วนบุคคล/ชำระเงิน · ห้ามปุ่ม disabled เงียบๆ · ห้ามเปลี่ยนสีรายเม็ด
- ห้ามพิมพ์ LINE ID/URL เอง · ห้ามใส่ราคาอื่นนอกจาก "800 บาท" (ค่าเดียวจาก constant)
- ห้าม import ไฟล์ `"use server"` · ห้ามใช้ `window.open` กับลิงก์ LINE
- ห้ามใช้คำว่า "นำโชค/เสริมดวง" ใน alt หรือข้อความใหม่ (ใช้เฉพาะข้อความ GEM_QUIZ_PAIRS เดิม)

## 8. ต้อง validate / ยังไม่รู้
- `oaMessage` ฝังข้อความได้จริงใน LINE/TikTok webview ไหม (handoff เดิมเลือก "คัดลอก + เปิด lin.ee" เพราะกลัวไม่ติด) · ทดสอบเครื่องจริงก่อนปล่อย
- ผู้ใช้เข้าใจ "เม็ดบน/ล่าง" โดยไม่มีคำอธิบายไหม · ปุ่มบนหน้าผลอยู่ลึกใต้ scroll — วัดอัตราคลิก
