## 1. ที่อยู่หน้า — `/jobs/gems-to-buy` เป็นแท็บใน JobsSubNav (ตัดสินแล้ว)

**ตัดสิน**: แท็บที่ 2 ของ `JobsSubNav` ต่อจาก "บอร์ดใบงาน" · ชื่อแท็บ `พลอยที่ต้องสั่ง` · icon `Diamond` (lucide — ใช้ใน sidebar แคตตาล็อกพลอยอยู่แล้ว) · + เพิ่มลิงก์ในเมนูข้างกลุ่ม "ใบงาน" (owner/admin เท่านั้น เหมือนกลุ่มเดิม)

ลำดับแท็บ: `บอร์ดใบงาน · พลอยที่ต้องสั่ง · ทะเบียนช่าง · แบบการบันทึก` — 2 อันแรกคืองานประจำวัน 2 อันหลังคือ setup

**ทำไมใต้ `/jobs` ไม่ใช่ใต้ "แคตตาล็อกพลอย"**
- หน้านี้ขับด้วย**ใบงานที่เปิดอยู่** (ข้อมูลเปลี่ยนทุกครั้งที่เปิด/ปิดใบ) ไม่ใช่ข้อมูลอ้างอิง — คนมาที่นี่หลังดูบอร์ด · แคตตาล็อก = ที่ตั้งชื่อ/ตั้งราคา (setup นานๆ ครั้ง)
- ต้นทุนเป็นคอลัมน์รอง ไม่ใช่เหตุผลที่เปิดหน้า → ไม่ควรเอาสิทธิ์/ภาษาของหน้าราคามากำหนดที่อยู่
- สิทธิ์ตรงกับ `/jobs/*` เดิม (`canManageJobs()`) · staff → `EmptyState` "หน้านี้จำกัดสิทธิ์" แบบ `/jobs/profiles`

**trade-off**: ผู้ใช้ที่นึกถึง "พลอย" แล้วไปเปิดเมนูแคตตาล็อกจะไม่เจอ → แก้ด้วยลิงก์ข้ามกัน: หัวหน้า `/oem/gems` เพิ่ม `พลอยที่ต้องสั่ง →` และหน้านี้ลิงก์ไป `/oem/gems` ตอนตั้งราคา (§4.7) · ไม่ทำ badge ตัวเลขบนแท็บ (ต้อง query ทุกหน้า `/jobs/*` ผ่าน layout — เก็บไว้ Phase 2 ถ้าเจ้าของลืมเปิดหน้านี้)

> `JobsSubNav` มีคอมเมนต์ "ห้ามลิงก์ไปหน้ายังไม่เสร็จ" → เพิ่มแท็บใน PR เดียวกับหน้า

## 2. User flow

```
[A · งานประจำ — ไล่สั่งพลอย]
เปิดแท็บ "พลอยที่ต้องสั่ง" → อ่านบรรทัด "ต้องใช้ ไม่ใช่ต้องสั่ง" → ดูกล่องเตือน "ใบที่ยังไม่ได้ใส่พลอย" (ถ้ามี)
 → ตาราง "ยังไม่สั่ง" เรียงใบที่ใกล้/เลยกำหนดก่อน → เทียบกับของที่มีในร้าน (นอกระบบ)
 → เลือกรายการที่จะสั่ง (ติ๊กช่องเลือก)  [หรือไม่เลือก = ทั้งหมดที่เห็น]
 → [คัดลอกไปส่งร้านพลอย] → วางใน LINE
 → แถบถาม "ส่งร้านพลอยแล้วใช่ไหม?" → [ทำเครื่องหมายว่าสั่งแล้ว (n)]
 → รายการออกจาก "ยังไม่สั่ง" ไปอยู่ "สั่งแล้ว" · toast [ย้อนกลับ] 10 วิ
 └ จบ

[B · สั่งแล้วบางใบ] กางแถว → กด "สั่งแล้ว" ที่ใบนั้นใบเดียว → ยอดแถวลด · ป้าย "สั่งไปแล้ว 40" โผล่ที่แถว
[C · กดผิด / ยกเลิกคำสั่ง] toast [ย้อนกลับ] ภายใน 10 วิ  หรือ  แท็บ "สั่งแล้ว" → "ยกเลิกสั่งแล้ว" (ทั้งรายการ หรือรายใบ)
[D · ใบยังไม่ระบุพลอย] กล่องเตือน → ลิงก์เปิดใบ /jobs/[id] → ใส่พลอยในการ์ด "พลอย" → กลับมารีเฟรช
[E · ตั้งราคาที่ขาด] สวิตช์ "แสดงต้นทุนประมาณ" → chip "ยังไม่มีราคา" → ลิงก์ /oem/gems (แท็บใหม่) → ตั้งราคา → กลับมากด ↻ รีเฟรช
[F · พิมพ์] [พิมพ์ใบรายการ] → หน้าต่างพิมพ์ของเบราว์เซอร์ (A4) → ไม่มีราคา
error/edge: ติ๊กชนกับคนอื่น/ใบปิดไปแล้ว → toast แดง + รีเฟรชข้อมูลอัตโนมัติ (§4.5) · คัดลอกไม่ได้ (clipboard ถูกบล็อก) → กล่องข้อความให้ Ctrl+C เอง (§4.6)
```

## 3. ลำดับความสำคัญบนหน้า (อะไรต้องเห็นก่อน)

1. **ตาราง "ยังไม่สั่ง" เรียงเร่งด่วน** — งานหลักของหน้า
2. **ปุ่มหลักเดียว: `คัดลอกไปส่งร้านพลอย`** (primary เพียงปุ่มเดียวบนหน้า) — ปลายทางของงานคือส่งให้ร้านพลอย
3. คำเตือนที่ทำให้ยอดผิด: บรรทัด "ต้องใช้ ไม่ใช่ต้องสั่ง" + กล่องใบยังไม่ระบุพลอย
4. ปุ่ม `สั่งแล้ว` ต่อแถว (secondary — ซ้ำหลายแถว ห้ามเป็น primary)
5. ต้นทุนประมาณ — ปิดเป็นค่าเริ่ม (สวิตช์)

### 4.2 คอลัมน์ + กติกาข้อมูล

| คอลัมน์ | กติกา |

| ☐ เลือก | ช่องเลือกสำหรับ bulk (คัดลอก/พิมพ์/สั่งแล้ว) — **ไม่ใช่ช่อง "สั่งแล้ว"** (ดู §11 D2) · `aria-label="เลือก {label}"` · หัวคอลัมน์ = เลือกที่เห็นทั้งหมด (`indeterminate` ได้) |

| จำนวนใบ | `3 ใบ` |
| ครบกำหนดเร็วสุด | วันที่ `thaiDate` + ป้ายคู่คำ: **เลยกำหนด n วัน** (แดง `Badge red` + `AlertTriangle`) · **ครบใน n วัน** (amber · n ≤ 3 — ตรงกับ tile "ครบใน 3 วัน" ของบอร์ด) · ไม่มีกำหนด = ข้อความ `ไม่ระบุกำหนด` สีปกติ · คำนวณจาก `todayBkk` ที่ server ส่งมา (ห้ามใช้นาฬิกา client — กันเวลาไทยเหลื่อม) |
| ต้นทุนประมาณ | เฉพาะเมื่อเปิดสวิตช์ (§4.7) |

**เรียง (ค่าเริ่ม = เร่งด่วน)**: กำหนดเร็วสุดขึ้นก่อน (เลยกำหนด → ใกล้ → ไกล) · **ไม่ระบุกำหนดไปท้าย** · เสมอกัน → ชนิด → รูปทรง → ขนาด · ตัวเลือกเดียวที่เพิ่ม = `เรียงตามชนิด` (ใช้ตอนเทียบกับของในลิ้นชักที่จัดตามชนิด) — segmented 2 ปุ่ม `aria-pressed` · **ไม่ทำเรียงทุกคอลัมน์** (ไม่มีเหตุผลใช้จริง ไม่ over-design)

**ตัวกรอง** (state เก็บใน URL ด้วย `replaceState` แบบ `GemCatalogClient` — `?tab=ordered&q=&type=&shape=&sort=type&urgent=1` เพื่อให้กด Back จาก `/jobs/[id]` แล้วตัวกรองไม่หาย): ค้นหา (ไม่สนช่องว่าง/ตัวพิมพ์ — `normalizeGemName`) · ชนิด · รูปทรง (`<select>` เดิมของ catalog) · ปุ่ม toggle `เร่งด่วน n` (เลยกำหนด + ครบใน 3 วัน; `aria-pressed`; `n` = นับหลังกรองอื่น) · ปุ่ม `ล้างตัวกรอง` เมื่อมีตัวกรอง

### 4.3 แถวกาง "ดูใบ"

- กาง = รายการ**ใบ** (JB-xxxx เป็นลิงก์ `/jobs/[id]` แท็บเดียวกัน) · ชื่อแบบ · กำหนดของใบนั้น · จำนวนที่ใบนี้ต้องใช้ · ปุ่ม `สั่งแล้ว` ระดับใบ
- แท็บ "ยังไม่สั่ง" กางแล้วเห็น**เฉพาะบรรทัดที่ยังไม่สั่ง** · แท็บ "สั่งแล้ว" เห็นเฉพาะบรรทัดที่สั่งแล้ว (+ `สั่งเมื่อ 22 ต.ค. · โดย {ชื่อ}` ถ้า Han ให้ — §9 H3)
- มากกว่า 10 ใบ → แสดง 10 แรก + ปุ่ม `ดูอีก {n} ใบ` (ไม่ทำ scroll container ซ้อน — แก้ปัญหา focus/keyboard)
- ใบที่เลยกำหนด = ป้ายแดงข้างวันที่ (ชุดเดียวกับตารางหลัก)
- กางหลายแถวพร้อมกันได้ (ไม่ใช่ accordion — เทียบรายการกันบนจอเดสก์ทอป)

### 4.4 การเลือก + แถบคำสั่ง (toolbar) — scope ชัดเจนเสมอ

หลักเดียว: **คำสั่งทำกับ "ที่เลือก" ถ้ามี ไม่งั้นทำกับ "ทั้งหมดที่เห็นตามตัวกรอง"** · ตัวเลขใน**ปุ่ม**บอกขอบเขตเสมอ

| สถานะ | ปุ่มที่เห็น |
|---|---|
| ไม่ได้เลือก | `คัดลอกไปส่งร้านพลอย (14)` primary · `พิมพ์ใบรายการ (14)` secondary |
| เลือก 3 | `คัดลอกที่เลือก (3)` primary · `พิมพ์ที่เลือก (3)` · `สั่งแล้ว (3)` secondary · `ล้างที่เลือก` ghost · toolbar `sticky top-16 z-10` |
| มีตัวกรอง ไม่ได้เลือก | ปุ่มเป็น `คัดลอกตามตัวกรอง (3 จาก 14)` — ไม่ให้คนส่งรายการขาดโดยไม่รู้ตัว |

- "สั่งแล้ว (n)" **ไม่มีถ้าไม่ได้เลือก** (ห้ามมีปุ่ม "สั่งแล้วทั้งหมด" — เสี่ยงกดผิดทั้งหน้า)
- selection จริง = รายการที่เลือก **∩ ที่มองเห็นอยู่** — เปลี่ยนตัวกรอง/แท็บแล้วรายการที่ถูกซ่อนไม่ถูกนับ/ไม่ถูกกระทำ (กัน "ติ๊กของที่มองไม่เห็น") · ข้อความ `เลือกอยู่ 3 รายการ` อยู่ใน aria-live
- แท็บ "สั่งแล้ว": toolbar เหลือ `ยกเลิกสั่งแล้ว (n)` เมื่อเลือก · **ไม่มีคัดลอก/พิมพ์** (ไม่มีหน้าที่ใช้จริง — ตัดเพื่อไม่ให้คัดลอกรายการที่สั่งไปแล้วส่งร้านซ้ำ)

### 4.5 ติ๊ก "สั่งแล้ว" — ระดับรายการ / ระดับใบ / bulk

| ทำที่ | ทำอะไร | ยืนยัน | ย้อน |
|---|---|---|---|
| ปุ่ม `สั่งแล้ว` ที่แถวรายการ | ทุกบรรทัด "ยังไม่สั่ง" ของรายการนั้น | ไม่มีกล่องยืนยัน | toast `ทำเครื่องหมายสั่งแล้ว: โกเมน ไข่ 4×6 มม. (3 ใบ)  [ย้อนกลับ]` |
| ปุ่ม `สั่งแล้ว` ที่บรรทัดใบ | บรรทัดนั้นบรรทัดเดียว | ไม่มี | toast เหมือนบน (`JB-0031`) |
| `สั่งแล้ว (n)` ใน toolbar | ทุกบรรทัดของ n รายการที่เลือก | **การเลือกคือการยืนยัน** · ไม่มีกล่องซ้ำ | toast `ทำเครื่องหมายสั่งแล้ว 5 รายการ (12 ใบ) [ย้อนกลับ]` |
| (แท็บสั่งแล้ว) `ยกเลิกสั่งแล้ว` ระดับรายการ/ใบ/bulk | กลับไปเป็น "ยังไม่สั่ง" | ไม่มี | toast `ยกเลิกสั่งแล้ว … [ย้อนกลับ]` (ย้อนของการยกเลิก = ติ๊กใหม่) |

กติกา
- **ทำงานแบบ "รอ server ตอบ" (ไม่ optimistic)**: ปุ่มเข้า `loading` + แถว `aria-busy` + ปุ่มอื่นของแถวนั้น disabled · สำเร็จ → ข้อมูลใหม่จาก server (ไม่แก้เลขใน client) · เหตุผล §11 D3
- ✅ **ทำจริง (24 ต.ค. 69 รอบแก้ security/review) — ย้อนกลับมีเงื่อนไข ไม่ใช่ทุกครั้ง**: ย้อนกลับ = เรียกคำสั่ง**ตรงข้ามด้วย line ids เดิม** (ไม่ใช่ "undo ล่าสุด") แต่ **เสนอปุ่มเฉพาะเมื่อผล server บอกว่าย้อนแล้วกลับสภาพเดิมเป๊ะ** (ตัดสินจาก `prevOrderedQty` ต่อแถวของผลคำสั่ง ไม่ใช่จาก `is_ordered` ระดับใบของ summary — ใบผสมตัดสินผิด):
  - หลังติ๊ก: ทุกแถว `prevOrderedQty = null` (เดิมไม่เคยติ๊ก) และเปลี่ยนครบทุกแถวที่ส่ง — ติ๊กซ้ำที่ปรับยอดขึ้น (70 → 90) ย้อนด้วยการยกเลิกไม่ได้ (ได้ 0 ไม่ใช่ 70 → สั่งซ้ำ)
  - หลังยกเลิก: ทุกแถว ยอดที่ล้าง = ยอดที่ต้องใช้ตอนนี้ (ติ๊กใหม่แล้วได้ยอดเดิม) — "ยอดเปลี่ยนหลังสั่ง"/"สั่งเกิน" ย้อนไม่ได้
  - ไม่เข้าเงื่อนไข = toast บอกเหตุผล ไม่มีปุ่ม → ใช้แท็บฝั่งตรงข้ามเป็นทางสำรอง (มีเสมอ)
- หลังติ๊ก: แถวออกจากตาราง → **focus ไปปุ่ม `▾ ดูใบ` ของแถวถัดไป** (ไม่มีแถวถัดไป → focus ที่แท็บที่เลือกอยู่) · `aria-live` ประกาศ `ทำเครื่องหมายสั่งแล้ว 1 รายการ`
- **ชนกับคนอื่น** (บรรทัดถูกติ๊กไปแล้ว / ใบปิดไปแล้ว / ยอดเปลี่ยน): ขอให้คำสั่ง **idempotent** (§9 H2) → ติ๊กซ้ำไม่ error แต่ข้อมูลที่คืนมาสดกว่า · ถ้าบางบรรทัดไม่ผ่าน toast แดง `ทำเครื่องหมายได้ 4 จาก 5 รายการ — มีรายการที่เปลี่ยนไป รีเฟรชแล้ว` + ดึงข้อมูลใหม่อัตโนมัติ
- **nudge หลังคัดลอก** (ตัดได้ถ้าไม่ว่าง — ไม่กระทบ flow หลัก): คัดลอกสำเร็จ → แถบ sky ใต้ toolbar (`role="status"`, ไม่หายเอง จนกด/เปลี่ยนตัวกรอง):
  `คัดลอก 14 รายการแล้ว — ส่งร้านพลอยแล้วใช่ไหม?  [ทำเครื่องหมายว่าสั่งแล้ว (14)]  [ยังไม่ได้ส่ง]`
  เหตุผล: ลืมติ๊ก = สั่งซ้ำ = ปัญหาที่เจ้าของให้ติ๊กมาแก้ · **ไม่ติ๊กให้อัตโนมัติ** (คัดลอก ≠ ส่งแล้ว) · ปุ่มติ๊กในแถบนี้ใช้ชุดรายการเดียวกับที่เพิ่งคัดลอก (ไม่ใช่ที่เลือกตอนนี้)

### 4.6 คัดลอก + พิมพ์ (ดู §6 สำหรับรูปแบบข้อความ)

- คัดลอกสำเร็จ → toast `คัดลอก 14 รายการแล้ว` (มีตัวกรอง: `คัดลอก 3 จาก 14 รายการ (ตามตัวกรอง)`)
- คัดลอกไม่ได้ (clipboard API ใช้ได้เฉพาะ secure context/ถูกบล็อก) → `Modal` "คัดลอกเอง": `<textarea readonly>` เลือกข้อความทั้งหมดให้ + `กด Ctrl+C` + ปุ่ม `ปิด` (ไม่ใช่แค่ toast error แบบ `CopyButton` เดิม — ไม่มีทางออก) · focus เริ่มที่ textarea
- รายการว่าง (0) → ปุ่ม `aria-disabled` + เหตุผล `ไม่มีรายการให้คัดลอก`
- พิมพ์ = `window.print()` บนหน้าเดียวกัน · เนื้อหาพิมพ์เป็น component แยก `GemOrderSheet` (`hidden print:block`) และ UI อื่น `print:hidden` → **Ctrl+P ตรงๆ ก็ได้ใบรายการเดียวกัน** (ไม่มีทางได้ตารางที่มีต้นทุนบนกระดาษ)

### 4.7 ต้นทุนประมาณ (owner/admin — คอลัมน์แยก ซ่อน/แสดงได้)

- **สวิตช์** `ต้นทุนประมาณ [ปิด/เปิด]` (`role="switch"` 44px — ลอกรูปแบบ `QtyBufferToggle`; label ต้องสกัดเป็น prop) · **ค่าเริ่ม = ปิด** (ที่โต๊ะมีคนอื่นมอง/แชร์จอ · และหน้านี้ใช้สั่งของ ไม่ใช่ดูต้นทุน) · จำค่าที่เลือกไว้ใน `localStorage` ต่อเบราว์เซอร์ (ไม่ต้องกดทุกครั้ง) `[ต้องยืนยัน: เจ้าของอยากให้จำหรือปิดใหม่ทุกครั้ง — Q2]`
- **โหลดแยก เมื่อเปิดสวิตช์เท่านั้น** (action คนละตัว) → HTML/RSC ของหน้าตอนปิดสวิตช์ **ไม่มีเลขราคา** (ตรวจได้ด้วย grep ตามกฎ `oem-quote-invariants` ข้อ 1) · แลก: เปิดสวิตช์แล้วรอ 1 round trip (คอลัมน์ขึ้น skeleton)
- ✅ **ทำจริง — ไม่คูณ/ไม่บวกเลขเงินใน client เลย**: ต้นทุนต่อแถวมาจาก DB **ปัดสตางค์ 2 ตำแหน่งแล้ว** (§9 H4) · **ยอดรวม = `totals.cost_remaining_thb` ของ DB แสดงตรงๆ** (ไม่ใช่ผลบวกแถวที่เห็นตามที่เคยร่างไว้ — ส่วนเหลือ+สั่งแล้วอาจคลาด 0.01) → ยอดรวมนับ**ทุกรายการที่ยังไม่สั่ง ไม่ตามตัวกรอง** จอจึงมีบรรทัด "ไม่ตามตัวกรองที่เลือก" เมื่อมีตัวกรอง · ต้นทุนต่อแถว = ส่วน**ที่ยังไม่สั่ง** (`cost_remaining`) หัวคอลัมน์ระบุชัด · ต้นทุนที่ qty ไม่ตรงยอดบนจอ (สองชุดมาต่างเวลา) = ไม่แสดงเลข · ทุกรายการไม่มีราคา = ไม่โชว์ยอดรวม 0 · ทุกส่วนของต้นทุน `print:hidden` · ปิดสวิตช์แล้วเปิดใหม่ไม่โผล่เลขของรอบก่อน (skeleton)
- แถวที่ไม่มีราคา: chip amber + `AlertTriangle` + `ยังไม่มีราคา` (ไม่ใช่ 0 ไม่ใช่ "—") + ลิงก์ `ตั้งราคา ↗` → `/oem/gems` **เปิดแท็บใหม่** (`target="_blank" rel="noopener"` + `<span class="sr-only">(เปิดแท็บใหม่)</span>`) — เปิดแท็บใหม่เพราะหน้านี้มีสถานะ (เลือก/กาง) ที่ไม่อยากทิ้ง · กลับมากด `↻ รีเฟรช` · ขอ frontend ให้ `/oem/gems` รับ `?tab=items&filter=noPrice` (เล็ก — ไม่มีก็ลิงก์เปล่าได้)
- **รวมต้นทุน**: label = `ต้นทุนประมาณ (เฉพาะรายการที่มีราคา)` — **ห้ามตั้งชื่อ "รวมต้นทุน" เฉย ๆ** เมื่อมีรายการที่ไม่มีราคา (ผลบวกบางส่วนจะถูกอ่านเป็นยอดรวมจริง) · บรรทัด amber `ไม่รวม 3 จาก 14 รายการที่ยังไม่มีราคา` · ทุกรายการมีราคา = ไม่มีบรรทัดเตือน
- ต้นทุนเป็น "ประมาณ" เพราะ: ราคา ณ วันนี้ · ยอดไม่หักของในร้าน · ไม่เผื่อแตก → ข้อความใน `[รายละเอียด ▾]` ใต้หัวหน้า
- แท็บ "สั่งแล้ว" ไม่มีคอลัมน์ต้นทุนรอบนี้ (ไม่มีโจทย์ใช้ — YAGNI)
- ต้นทุนโหลดล้ม → `ErrorBanner` เหนือตาราง `โหลดต้นทุนไม่ได้` + `ลองใหม่` · เซลล์แสดง `โหลดไม่ได้` (ห้ามเป็น 0 หรือว่าง)

## 6. ข้อความคัดลอก + ใบพิมพ์ — 🔴 ไม่มีราคาเสมอ

### 6.1 ข้อกำหนด
- สร้างจาก type `GemOrderLine = { typeName, shapeName, sizeLabel, unitLabel, qty }` **ประกอบทีละ field ห้าม spread** · type นี้ไม่มี field ราคา/ต้นทุน/ผู้ขาย/เลข JB/กำหนดส่ง → "กันที่ type boundary ไม่ใช่วินัย" (`oem-quote-invariants` ข้อ 1)
- ฟังก์ชัน pure ตัวเดียว `buildGemOrderText(lines, { dateLabel })` ใช้กับปุ่มคัดลอก + modal สำรอง · `GemOrderSheet` (พิมพ์) รับ `GemOrderLine[]` ชุดเดียวกัน → ข้อความ/กระดาษตรงกันเสมอ
- จำนวน = **ยอด "ยังไม่สั่ง" ของรายการนั้น** (ส่วนที่กำลังจะสั่ง — ไม่ใช่ยอดรวมที่ใบต้องใช้ ถ้าสั่งไปบางส่วนแล้ว)
- ไม่ใช้คำว่า "ต้องสั่ง/ต้องการ" (ยอดคือ gross — G1) ใช้ `รายการสั่งซื้อพลอย`

## 10. Accessibility + edge

- แท็บ `role="tablist"` ←→/Home/End · `aria-controls`/`aria-labelledby` (ลอก `GemCatalogClient`) · แท็บมีเลขนับ `ยังไม่สั่ง 14`
- ตาราง semantic: `<caption class="sr-only">` · `th scope` · ทุกแถว `aria-label={label}` · ปุ่มใน**แถว**ใช้ชื่อเต็ม: visible `สั่งแล้ว` → accessible name `สั่งแล้ว — โกเมน ไข่ 4×6 มม.` (ขึ้นต้นด้วยข้อความที่เห็น — label-in-name) · `ยกเลิกสั่งแล้ว — …`
- `▾ ดูใบ` = `<button aria-expanded aria-controls>`
- ทุกป้ายสถานะ = ไอคอน + คำ (เลยกำหนด/ครบใน 3 วัน/ยังไม่มีราคา/สั่งไปแล้ว) ไม่พึ่งสีอย่างเดียว · คู่สีใช้ชุดเดียวกับ `GemItemsTable` (`amber-100/amber-950`, `sky-100/sky-950`, `red-100/red-800`) ผ่าน AA อยู่แล้ว
- touch target ทุกปุ่ม/ช่องเลือก ≥ 44px · `min-h-11`
- **ข้อจำกัด a11y ที่รู้**: toast ย้อนกลับอยู่ท้าย DOM — ผู้ใช้คีย์บอร์ด/screen reader เข้าไม่ถึงทันใน 10 วิ → ทางสำรองคือแท็บ "สั่งแล้ว" (ทำได้ทุกอย่างเท่ากัน) · ไม่ทำ shortcut Ctrl+Z (ชนกับ browser/ช่องค้นหา)
- ชื่อพลอยยาว/ไม่เว้นวรรค → `break-words [overflow-wrap:anywhere]` · เลข `whitespace-nowrap`
- รายการหลักร้อย: เลื่อนปกติ ไม่ virtualize · เกิน ~200 แถวค่อยแบ่งหน้า (เหมือน catalog)
- รีเฟรช/กดย้อนจาก `/jobs/[id]` → ตัวกรอง/แท็บคืนจาก URL · selection/กาง **ไม่คืน** (จงใจ — กัน "ติ๊กของที่ไม่ได้ตั้งใจหลังข้อมูลเปลี่ยน")
- ข้อมูลเก่า: แสดง `ข้อมูล ณ HH:mm` + `↻ รีเฟรช` (44px · `router.refresh()`) · หลังคำสั่งทุกครั้ง server คืนข้อมูลสด

## 11. Design decision + trade-off

| # | ตัดสิน | ทำไม | แลกกับ |
|---|---|---|---|
| D1 | หน้าอยู่ `/jobs` เป็นแท็บที่ 2 | งานประจำวันขับด้วยใบงาน · สิทธิ์เดียวกับ `/jobs/*` | คนที่นึกถึง "พลอย" แล้วหาในเมนูแคตตาล็อกอาจไม่เจอ → ลิงก์ข้าม 2 ทาง |
| D2 | **ช่องเลือก (☐) ≠ "สั่งแล้ว"**: ช่องเลือกไว้ทำ bulk · "สั่งแล้ว" เป็น**ปุ่มข้อความ** ไม่ใช่ checkbox | checkbox ที่กดแล้ว "แถวหายไป" ผิดความคาดหวัง (checkbox = สถานะ) · และแยก "เลือกเพื่อคัดลอก" ออกจาก "ฉันสั่งแล้ว" ซึ่งเป็นคนละเจตนา | เจ้าของใช้คำว่า "ติ๊ก" — ผลลัพธ์เทียบเท่า (แค่เป็นปุ่ม) · มี 2 ช่องทางกดต่อแถว (ช่องเลือก + ปุ่ม) ต้องเรียนรู้ 1 ครั้ง |
| D3 | คำสั่งสั่งแล้ว = **รอ server** (ไม่ optimistic) | ตัวเลขที่เห็นต้องเป็นของจริง (G2) · office เครือข่ายเร็ว ~ไม่ถึงวินาที · ไม่ต้องเขียน rollback | หน่วงนิดเดียวต่อคลิก (มี loading บนปุ่ม) |
| D4 | scope ของคัดลอก/พิมพ์ = ที่เลือก หรือ ที่เห็น และบอกตัวเลขบนปุ่ม | ส่งรายการไม่ครบโดยไม่รู้ตัวคือความเสี่ยงจริง | ปุ่มเปลี่ยนข้อความตามสถานะ (ต้องมีเทสต์) |
| D5 | ติ๊กทั้งรายการ = 1 คลิก ไม่มี dialog + undo 10 วิ | เจ้าของสั่ง undo toast · dialog ทุกครั้งทำให้ไล่ 14 รายการช้า | กดพลาดแล้ว 10 วิพลาดทางย้อน → ต้องไปแท็บ "สั่งแล้ว" |
| D6 | ต้นทุน: **โหลดแยก + ค่าเริ่มปิด + จำค่า** | ราคาไม่อยู่ใน payload เริ่มต้น (ตรวจได้) · โต๊ะมีคนมอง | เปิดแล้วรอ 1 round trip |
| D7 | พิมพ์ผ่าน print CSS ในหน้าเดียวกัน (`GemOrderSheet`) ไม่ทำ route `/print` | ตัวกรอง/ที่เลือกเป็น state ฝั่ง client — แยก route ต้องส่งผ่าน query ยาว | ต้องมั่นใจ `print:hidden` ครอบทุกอย่าง (เคสห้ามผ่าน #3) |
| D8 | แท็บ "ยังไม่สั่ง/สั่งแล้ว" (ไม่ใช่ "ต้องสั่ง/สั่งแล้ว") | G1: ตัวเลขคือ gross | ต่างจากคำในโจทย์ — ถาม Q1 |
| D9 | ไม่ทำ badge ตัวเลขบนแท็บ · ไม่ทำช่วงวันที่/โลหะ/แหล่ง ตัวกรอง · ไม่ทำคอลัมน์ต้นทุนในแท็บสั่งแล้ว | YAGNI · ลดจำนวน action ต่อจอ | ถ้าลืมเปิดหน้า → Phase 2 badge |
| D10 | กล่องใบ "ยังไม่ระบุพลอย" อยู่เหนือตารางเสมอ ไม่ใช่ฟุตเตอร์ | ยอดที่เห็นไม่ครบถ้าไม่รู้เรื่องนี้ | กินที่แนวตั้ง ~48px เมื่อพับ |

## 12. จุดที่ต้อง validate กับผู้ใช้จริง (ออกแบบจับไม่ได้)

1. **เจ้าของ/แอดมินอ่านเลขเป็น "ต้องใช้" ไม่ใช่ "ต้องสั่ง" ไหม** — ดูตอนเขาเปิดหน้าครั้งแรก: ลบสต็อกในหัวหรือส่งยอดตรงๆ ให้ร้าน? (ถ้าส่งตรงๆ = ต้องทบทวนมติไม่นับสต็อก)
2. **ติ๊กจริงไหม** — ผ่านไป 1–2 สัปดาห์ดูสัดส่วนรายการที่ถูกคัดลอกแล้วไม่ถูกติ๊ก (วัดจาก nudge ที่กด "ยังไม่ได้ส่ง" vs ไม่กดอะไร) → ตัดสินว่า nudge ใช้ได้ไหม
3. **ร้านพลอยอ่านข้อความคัดลอกรู้เรื่องไหม** — ให้ร้านพลอยดู 1 ข้อความจริง (กลุ่มตามชนิด/ตามขนาด ตัวไหนอ่านง่าย)
4. **ข้อมูลจริงกี่รายการ/ต่อรายการกี่ใบ** — ถ้าไม่เกิน ~10 รายการ ตารางกางอาจเกินความจำเป็น · ถ้า > 100 ต้องแบ่งหน้า
5. **มือถือใช้จริงไหม** — ถ้าเจ้าของใช้แต่เดสก์ทอป ตัด `GemsToBuyCard` ได้ (ลดงาน ~1 component)
6. **มีใครพิมพ์ไหม** — ถ้าไม่ ตัด `GemOrderSheet` ทั้งก้อน
7. **undo toast 10 วิพอไหม** — สังเกตว่ามีคนกดผิดแล้วหาทางย้อนไม่เจอไหม
8. **ใบที่ยังไม่ระบุพลอย** — เจ้าของจัดการกล่องเตือนเองไหม หรือต้องส่งเตือนเป็นงานแยก

## 13. ไม่ทำรอบนี้ (ไม่มีใน requirement)

นับสต็อก/หักของที่มี · เผื่อพลอยแตก · lead time ซัพพลายเออร์ ("ควรสั่งภายใน") · ใบสั่งซื้อ/สถานะรับของ (G4) · ผู้ขายต่อรายการ/แยกรายการตามร้าน · ประวัติราคา · badge บนแท็บ · บันทึกตัวกรองส่วนตัว · ส่ง LINE ตรงจากระบบ · คอลัมน์ต้นทุนในแท็บ "สั่งแล้ว" · ช่วงวันที่/โลหะ/แหล่ง OEM-ผลิตเอง เป็นตัวกรอง · staff เห็นหน้านี้ (รอบนี้ owner/admin เท่านั้น)

### 14.2 ที่ทำจริงใน UI (24 ต.ค. 69 · frontend-dev · หลัง security Mace + review C-3PO) — ทับ/เพิ่มจากข้างบน

- **ติ๊ก "สั่งแล้ว" ต้องส่ง `expected` ทุกครั้ง** (contract backend 7f583ae): `expected[line_id] = qty_needed_now` ของแถวที่จอแสดง/คัดลอก (ยอด "ต้องใช้" ระดับใบ — ไม่ใช่ยอดที่เหลือ) · ยอดในระบบเปลี่ยนหลังโหลดหน้า = DB ล้มทั้งชุดด้วย `qty_changed` → จอแจ้ง "ยอดพลอยของใบเปลี่ยนหลังโหลดหน้า — โหลดข้อมูลใหม่แล้ว ไม่ได้ทำเครื่องหมายรายการใดเลย" + โหลดใหม่ (ไม่ลองซ้ำเอง) · ยกเลิกติ๊กไม่ส่ง
- **แถบถามหลังคัดลอก** ส่ง `expected` จาก **snapshot ตอนคัดลอก** (ยอดที่ส่งร้านจริง) ไม่ใช่ยอดสดตอนกด · `qty_changed` ตอนนี้ = "ยอดเปลี่ยนหลังคัดลอก — คัดลอกใหม่แล้วส่งร้านส่วนต่าง" · แถบหายเมื่อข้อมูลหน้าเปลี่ยน (โหลดใหม่) · คัดลอกไม่ได้ (modal คัดลอกเอง) → ถามว่าส่งแล้วหรือยังเมื่อปิด modal
- **ยอดต่อ line**: `expected` ใช้ `jobs[].lines[].qtyNeededNow` ที่ DB ส่งมา (backend f983667 — mapper ตรวจผลรวม = ยอดของใบ และ ids ตรง `lineIds`) → ใบที่มีหลาย line ของรายการเดียวกัน (หลังรวมชื่อ) ติ๊กได้ ยอดต่อ line ถูกต้อง · ไม่แบ่ง/ไม่คำนวณเอง · ข้อมูล lines ไม่ครบ (ไม่ควรเกิดหลัง mapper) = จอไม่ยิง บอกให้โหลดใหม่
- **ย้อนกลับ/ยอดรวมต้นทุน**: ดู §4.5 / §4.7 (ที่แก้ให้ตรงของจริงแล้ว)
- **กล่องเตือน "เคยสั่งไว้แต่แถวถูกลบ"**: ปิดได้ทีละรายการ/ทั้งหมด จำใน localStorage (try/catch · อ่านไม่ได้ = แสดงทุกรายการ) · รายการใหม่ (ใบ/เวลาลบต่างจากเดิม) โผล่เสมอ · **ใบที่มีรายการเดียวกันกลับมาเป็น "ยังไม่สั่ง" ในแท็บยังไม่สั่ง = บังคับแสดง ปิดไม่ได้** (เสี่ยงสั่งซ้ำจริง) + chip "เคยสั่งไว้ N เม็ดก่อนถูกลบ — ระวังสั่งซ้ำ" ที่บรรทัดใบในแถวกาง · คีย์ใน storage ที่ไม่มีในข้อมูลปัจจุบันถูกทิ้ง
