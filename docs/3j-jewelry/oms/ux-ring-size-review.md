## 0. สรุป 5 บรรทัด

1. **ยังไม่พร้อมส่ง Luke ทันที** — โครงจอ/ลำดับ/ถ้อยคำดีมาก ตรงสเปคเกือบทุกจุด และเจ้าของแก้ 4 จุดที่ฉันกังวลไว้ได้ถูก (ปุ่ม LINE เดียว · ปุ่มปิดใช้งานมีเหตุผลที่ G1 · เส้นอยู่นอกขอบ · ไม่ปิด pinch-zoom) แต่มี 🔴 6 เรื่องที่ต้องตัดสิน/แก้ก่อน (แก้ใน canvas 4 · แก้ในสเปคส่ง Luke 2) ใช้เวลาไม่มาก
2. **เรื่องเหรียญ (D1): ตรรกะ "0.35 ต่ำกว่า 0.25" ขัดกันเองจริง** — 0.35 > 0.25 และ 0.25 ไม่ใช่ "ครึ่งเบอร์" (ครึ่งเบอร์ = 0.5 มม. ส่วน 0.25 คือ offset ของกฎปัด) เทียบกับงบ ±0.5 เหรียญกินไป ~70% ในแหล่งความคลาดเคลื่อนเดียว (บัตร ~34%) → ข้อความ "ทั้ง 2 วิธีแม่นใกล้เคียงกัน" และ "±ครึ่งเบอร์" ใช้กับเหรียญยังรับรองไม่ได้
3. **ภาพจำลองบัตร/เหรียญ/แหวนในเวที (R2, R2Coin, R5A, R5B) ห้ามขึ้นจริง** — ผู้ใช้ที่ยังไม่ได้หยิบของจริงจะปรับวงให้ตรง "ภาพจำลอง" แล้วค่าเทียบจอเพี้ยนทั้งระบบโดยไม่มีใครรู้ · และ mockup ออกแบบที่ความสูง 844 (ความสูงเครื่องเต็ม) แต่ 4 จอวัดต้องการ 715-773 px → ปุ่มหลักตกใต้ fold ใน Safari/webview
4. **คำสัญญาบนจอ 2 ประโยคไม่จริงเชิงเทคนิค** ("ไม่บันทึกอะไรเกี่ยวกับบัตรหรือเหรียญ" — เรา localStorage เก็บ `ref`+`pxPerMm` · "มือถือจะถามขออนุญาตก่อนเสมอ" — ยืนยันแทน webview ของแอปอื่นไม่ได้) + ข้อความยืนยันชนิดบัตร/เหรียญเกินที่ docs-researcher ยืนยันได้ → แก้ถ้อยคำตามข้อ 4 และ 5
5. **ไม่ต้องให้เจ้าของเลือกฟอนต์** (Noto Serif Thai + IBM Plex Sans Thai โหลดอยู่ใน `(quiz)/layout.tsx` แล้ว สี brand `#a2191d` เหมือน `--gq-burgundy`) — เลือกแค่ว่ารูปร่างปุ่ม/พื้นครีมแบบใหม่จะแยก namespace `--rs-*` หรือไม่ (Q4) · ค่าที่ยังต้องยืนยัน: มีอยู่แล้ว 3 กลุ่ม (ข้อ 5)

## 3. เหรียญ 10 บาท (D1) — วิเคราะห์

### 3.1 R1Pick ทำให้งงขึ้นไหม

- **ไม่งง ถ้าแก้ข้อความ** — 2 การ์ดเท่ากัน ป้ายต่างกันชัด ("ไม่ต้องใช้บัตร" / "แม่นที่สุด") ทางเลือกเป็นของที่ผู้ใช้ "มีหรือไม่มี" ไม่ใช่การตัดสินใจเชิงเทคนิค · ไม่มีค่าเริ่มต้นที่ต้องเดา
- จุดที่ทำให้งง = ข้อความความแม่น 3 ประโยคขัดกัน (R1) · กล่องความเป็นส่วนตัวใหญ่ (~125 px ใต้การ์ด) ที่หน้าตัดสินใจ — R0 พูดเรื่องนี้แล้ว 1 บรรทัด การเน้นไอคอนกล้องขีดฆ่าบนทุกคนอาจใส่ความกังวลให้คนที่ไม่เคยคิดถึงกล้อง · เสนอย่อเป็น 1-2 บรรทัด (ข้อ R4 ถ้อยคำใหม่)
- **trade-off ที่เจ้าของเลือก (เหมาะสม):** ได้ = คนกลัวกล้อง/ไม่มีบัตรติดตัวไปต่อได้ · เสีย = +1 จอ + 2 ทางที่ต้องทดสอบ/ดูแล · ผมเห็นด้วยกับ D1 โดยมีเงื่อนไขข้อ R1/R5/Y1

### 3.2 ตรรกะตัวเลข "1 px ≈ 0.35 มม. ยังต่ำกว่าเกณฑ์ 0.25 มม."

| ข้อ | ตรวจ | ผล |
|---|---|---|
| 1 px ที่เหรียญ → เส้นรอบวง | ที่ 6 px/มม.: เหรียญ 26 มม. = 156 px · 1 px = 0.64% ของสเกล × เส้นรอบวง 54 มม. = **0.35 มม.** | ✓ ตัวเลข handoff ถูก (ที่เบอร์ 68: 0.44 มม.) |
| 1 px ที่บัตร | บัตร 53.98 มม. = 324 px · 1 px = 0.31% × 54 = **0.17 มม.** | ✓ ถูก |
| "0.35 ต่ำกว่า 0.25" | 0.35 > 0.25 | ✗ **ขัดกันเอง** |
| 0.25 คือ "ครึ่งเบอร์"? | 1 เบอร์ = 1 มม. ของเส้นรอบวง → ครึ่งเบอร์ = **0.5 มม.** · 0.25 คือ offset ในสูตรปัด `ceil(c − 0.25)` และขอบของแถบ "ระหว่างเบอร์" (สเปค §3 R6) ไม่ใช่งบความคลาดเคลื่อน | ✗ **เทียบผิดตัวเลข** น่าจะตั้งใจเทียบกับ ±0.5 |
| เทียบ ±0.5 (สเปค §8 = งบรวมทุกแหล่ง) | เหรียญ 0.35 = **70%** ของงบ ในแหล่งเดียว · บัตร 0.17 = 34% · แหล่งอื่นที่ต้องอยู่ในงบเดียวกัน: ตัดสินช่องว่างแหวน ~0.31 มม./ก้าว 0.1 มม. · ขอบในโค้งมน · มุมมอง/พารัลแลกซ์ | **เหรียญ 0.35 ไม่ผิดเงียบๆ แต่ใช้งบหมด** รวมแบบ root-sum-square กับช่องว่างแหวน (√(0.35²+0.31²) ≈ 0.47) ก็ใกล้ ±0.5 แล้วโดยยังไม่นับแหล่งอื่น ส่วนบัตร (√(0.17²+0.31²) ≈ 0.35) ยังเหลือพื้นที่ |
| "1 px" คืออะไร | handoff นับ 1 px ของ **เส้นผ่านศูนย์กลางรวม** แต่ผู้ใช้ตัดสินที่ **ขอบ** ผิดข้างละ 1 px (รัศมี) = เส้นผ่านศูนย์กลางผิด 2 px = **0.69 มม.** (เหรียญ) / **0.33 มม.** (บัตร 2 เส้น) · ผิดทั้งสองข้างไปทางเดียวกันได้ (ชอบ "เกือบแตะ") | ไม่มีใครรู้ค่าจริงจนกว่าจะทดสอบ → ห้ามเขียนเลข ±ครึ่งเบอร์ เป็นคำสัญญาให้เหรียญ |
| พารัลแลกซ์ | เหรียญหนา ~2.2 มม. (บัตร 0.76 มม.) มองเฉียงขอบบังเส้นต่างกันมากกว่า ~3 เท่า | เหรียญเสียเปรียบอีกชั้น |
| ก้าว −/+ | เหรียญ 0.1 มม. ของเส้นผ่านศูนย์กลาง = 0.38% = **0.21 มม.** ที่เส้นรอบวง · บัตร 0.1 มม. = 0.185% = **0.10 มม.** | เหรียญหยาบกว่า 2 เท่า → ก้าว 0.05 มม. (Y1) |
| เกณฑ์ทดสอบ "ค่าต่างกัน < 0.25 มม." (handoff §7) | ความละเอียดของเหรียญเองคือ 0.35/px + ก้าว 0.21 → ต่างกัน 0.25 เกิดได้จากพิกเซลเดียว และ 0.25 มม. พลิกเบอร์ได้ ~25% ของกรณี (เบอร์ละ 1 มม.) | เกณฑ์ไม่สมเหตุผลทั้งสองฝั่ง ดูข้อ 7 |

**ข้อสรุปเรื่อง "แม่นใกล้เคียงกัน":** ไม่ตรงจริง — ตามเลขของ handoff เอง เหรียญหยาบกว่าบัตร ~2 เท่า ("เล็กน้อย" ใน R1Coin ยังไม่มีหลักฐานรับรอง) → ใช้ "บัตรแม่นกว่า" ไม่ใช้ "ใกล้เคียงกัน/เล็กน้อย" จนกว่าจะทดสอบ

**ไม่แนะนำให้เลิกเหรียญ** — ผลกระทบของความหยาบบรรเทาได้: เส้น 2 px + ไม่ปัด px + ก้าว 0.05 มม. + ข้อความตามจริง + ส่ง `ref` ไปกับ LINE เพื่อให้แอดมินรู้ + เก็บสถิติ G3/G4 ตาม `ref`

## 7. ต้อง validate กับผู้ใช้จริง/เครื่องจริง (design จับไม่ได้)

1. **วัดของอ้างอิง** (เจ้าของ/ช่าง): บัตร 2-3 ใบ + เหรียญหมุนเวียน 2-3 เหรียญ (ปีต่างกัน/สึกต่างกัน) ด้วยเวอร์เนียร์ ยืนยัน 53.98 และ 26 มม. ในทางปฏิบัติ
2. **เครื่องจริง ≥ 3 รุ่น × Safari/Chrome/TikTok/LINE:** ความสูง viewport จริงเทียบตาราง R3 · ปุ่มหลักอยู่เหนือ fold ไหม · G2 เกิดบ่อยแค่ไหนที่ R5B
3. **เหรียญ vs บัตร เครื่องเดียวกัน:** วัดแหวนที่ **รู้เบอร์จริง** (ใช้ ring sizer ร้านที่รู้เบอร์ — Jocasta แนะนำให้ทดสอบกับแหวนร้านที่รู้เบอร์) · ≥ 10 คน/วิธี · **เกณฑ์ที่เสนอ (ต้องเจ้าของเคาะ):** วัดจาก "เบอร์แนะนำตรงกับเบอร์จริงหรือต่าง ≤ 1" ไม่ใช่ "ต่างกัน < 0.25 มม." (ข้อ 3.2) · ผลนี้ใช้ตัดสินคำ ±ครึ่งเบอร์ vs ±1 เบอร์ บนจอ
4. **ผู้ใช้เห็นอะไรเมื่อ "พอดี"** (เหรียญ): เส้น 2 px บางลง vs ช่องขาว — ดูว่าคนเห็นตามที่ออกแบบไหม โดยเฉพาะ DPR ต่ำ/จอสว่างน้อย/กลางแดด
5. **ผู้ใช้ปรับตามเลข "เบอร์" ที่ขึ้นสด** หรือปรับตามแหวน? (ข้อ G3) — ลองซ่อนเลขในกลุ่มหนึ่ง
6. **LINE:** `oaMessage` ขึ้นข้อความในแชทจริงไหมทุกชุด (Q4)
7. **จับเวลา** flow คนใหม่/คนกลับมา (Y7)
8. **ข้อความ "ไม่ใช้กล้อง" ทำให้อุ่นใจหรือกังวลขึ้น?** (R1Pick กล่องใหญ่ vs บรรทัดเดียว)
