1. พิมพ์ชนิด/รูปทรงใหม่ลงในฟอร์มได้เลย → **เข้าแคตตาล็อกเอง** ครั้งหน้ามี dropdown · ไม่บังคับรอออฟฟิศ · "มานั่งสร้างก่อนจะงง" = **ไม่ seed ชนิด** (ตัวอย่างที่เจ้าของใช้: CZ · โกเมน · ซิทริน · อเมทิสต์ · เพอริดอท · ทับทิม · ไพลิน · บุษ)
2. รูปทรง = มาตรฐาน + เพิ่ม fancy cut เองได้ (หัวใจ · 6 เหลี่ยม ฯลฯ) · **ขนาดพิมพ์เอง**

5. 🔴 ราคาพลอยไม่ถึงผู้จัดการ/ช่าง

## 1. สิ่งที่ยึด (ไม่คิดค่าใหม่)

## 3. W-4 "พลอย" — มือถือ ผู้จัดการ (ขั้นใหม่ · 360px)

### 3.1 ตำแหน่งในวิซาร์ด + เหตุผล

`stepsFor(form)`: มี SKU `search → qty → **gems** → photos → review` (5 ขั้น) · สินค้าใหม่ `search → metal → qty → **gems** → photos → review` (6 ขั้น) — ตัวนับ n/N ใน `ShopStepHeader` ขยับเอง

**ทำไมหลัง W-3 ก่อน W-5**: "รวมทั้งใบ" ต้องรู้จำนวนที่จะเริ่มผลิต (W-3) ก่อน · รูป (W-5) ต้องอยู่ใกล้ปลายทางที่สุดเพราะเรียกกล้อง (เสี่ยงหน้า reload — P3 ของ W2) · trade-off: ผู้จัดการที่อยากใส่พลอยก่อนจำนวนทำไม่ได้ · วิซาร์ดยาวขึ้น 1 ขั้นทุกใบ (วัด §13 ข้อ 10)

กติกา
- **แถวขยายได้ทีละ 1 แถว** (accordion) — ลด scroll บน 360px เมื่อมีหลายแถว · แถวพับ = สรุปบรรทัดเดียว + ป้าย · แถวที่ยังไม่ครบ**ห้ามพับ** (ปุ่ม "เสร็จแถวนี้" aria-disabled + เหตุผลชี้ช่องที่ขาด)
- "＋ เพิ่มพลอย" พับแถวที่ครบแล้วอัตโนมัติ + เปิดแถวใหม่ + focus ช่อง "ชนิด" · แถวปัจจุบันไม่ครบ = กดไม่ได้ (aria-disabled `กรอกแถว {n} ให้ครบก่อน`)
- **ป้ายต่อแถว** (ไอคอน+คำ ไม่พึ่งสี): `จากแม่แบบ` (sky) · `แก้แล้ว` (amber — แถวจากแม่แบบที่แก้ค่า) · `ใหม่` (ชนิดหรือรูปทรงที่พิมพ์ใหม่ในฟอร์มนี้ — บอกว่ายังไม่เข้าแคตตาล็อกจนกดเปิดงาน)
- ลบแถว: ไม่มีกล่องยืนยัน (ยังไม่ถึง server) + toast `ลบแถวแล้ว` · ลบแถวจากแม่แบบ = เฉพาะใบนี้ (บรรทัดเล็ก "เฉพาะใบนี้")
- **แถวซ้ำ** (ชนิด+รูปทรง+ขนาดเดียวกับแถวอื่น): กล่อง amber ในแถว `มีพลอยแบบเดียวกันอยู่แล้วที่แถว 1` + ปุ่ม `รวมเข้าแถว 1` (บวกจำนวน/ชิ้น · ตำแหน่งต่อกันด้วย ", " ตัดซ้ำ) — **ไม่รวมเงียบๆ** · ถัดไปไม่ผ่านจนกว่าจะรวมหรือแก้ให้ต่าง (ตรงกับ unique ของ DB)
- ขนาด: รูปทรงที่ `has_length=false` = ช่องเดียว · `true` = `[กว้าง] × [ยาว]` · กรอกกลับด้าน (6×4) → ระบบเรียงเป็นกว้าง ≤ ยาวให้ + บรรทัดเล็ก `เรียงเป็น 4×6 ให้` (R5 ของ design: unique ต้อง normalize) · เปลี่ยนรูปทรงหลังกรอกขนาด: ค่าที่เข้ากันเก็บไว้ ที่เกินล้าง + บอก
- `inputMode="decimal"` · รับ `,` เป็น `.` · ทศนิยม ≤ 2 · `> 0` และ `≤ 100` · `> 30 มม.` ขึ้นกล่อง amber `ขนาด {x} มม. ใหญ่ผิดปกติสำหรับพลอยเครื่องประดับ — ตรวจว่าเป็นมิลลิเมตร` + ปุ่มติ๊ก `ใช่ ขนาดนี้ถูกต้อง` (ถัดไปไม่ผ่านจนติ๊ก — R4 ของ design)
- ชิปขนาด "เคยใช้": โชว์เฉพาะเมื่อเลือกชนิด+รูปทรงแล้วและแคตตาล็อกมีรายการนั้น (สูงสุด 6 · แตะ = เติมช่อง) — **ตัดได้ถ้า frontend ไม่ว่าง** (ไม่กระทบ flow หลัก) แต่ช่วยลดขนาดสะกดต่าง (`4×6` กับ `4.0×6.0`) และเป็นความหมายของ "ครั้งหน้ามี dropdown ให้" ในระดับขนาด · ต้องการข้อมูลจาก architect (§14.2 A3)
- จำนวนต่อชิ้น: 1–1,000 `[ต้องยืนยันเพดานกับเจ้าของ/architect]` · ช่องพิมพ์เลขตรง (`inputMode="numeric"`) + ปุ่ม −/+ · รวมทั้งใบ = จำนวน/ชิ้น × จำนวนผลิต (P10) · ตัวเลขใหญ่ขึ้นเป็นหลักล้านได้ (`tabular-nums` ไม่ตัดบรรทัดกลางตัวเลข)
- "ตำแหน่ง" ไม่บังคับ · ห้าม `<` `>` · ใช้ชุดตรวจเดียวกับ `name_invalid` เดิม

### 3.4 `GemPicker` — เลือกชนิด/รูปทรง (bottom sheet บนมือถือ)

เลือก `<select>` ธรรมดาไม่ได้ (ค้นหาไม่ได้ · รายการยาวขึ้นเรื่อยๆ) · ใช้ **แผ่นเต็มจอ** เปิดจากปุ่มช่อง (focus trap · คืน focus ที่ปุ่ม)

```
┌ 360 ───────────────────────────────┐
│ ‹ เลือกชนิดพลอย                    │ ปุ่มกลับ 56
│ [ ค้นหาหรือพิมพ์ชื่อ…           ]  │ 56px · ค่าตัวอย่าง "เช่น โกเมน"
├────────────────────────────────────┤
│ ใกล้เคียงที่พิมพ์                  │ เฉพาะเมื่อมีผลคล้าย (ไม่ตรงเป๊ะ)
│ [ โกเมน                          ] │ แถวตัวเลือก 56px
│ ทั้งหมด (7)                        │
│ [ CZ                             ] │
│ [ โกเมน                          ] │
│ [ ซิทริน                         ] │
│ …                                  │
├────────────────────────────────────┤
│ [ ＋ เพิ่ม "โกเมนต์" เป็นชนิดใหม่ ] │ sticky ล่าง · dashed · ขึ้นเมื่อพิมพ์แล้วไม่ตรงชื่อใดเป๊ะ
└────────────────────────────────────┘
```
- ค้นหา: ไม่สนช่องว่าง/ตัวพิมพ์เล็กใหญ่ · เลือกแล้วปิดแผ่น + focus กลับช่องถัดไป
- **ยังไม่พิมพ์อะไร** + ไม่มีรายการเลย (วันแรก — ไม่ seed): `ยังไม่มีชนิดพลอยในระบบ — พิมพ์ชื่อแรกได้เลย ชื่อที่ใส่จะอยู่ในรายการให้คนถัดไป`
- ชื่อใหม่ในฟอร์มนี้ที่ยังไม่บันทึก ขึ้นในรายการของแถวถัดไปพร้อมป้าย `ใหม่`
- กฎชื่อใหม่: trim · ยุบช่องว่างซ้ำ · **≥ 2 ตัวอักษร** · ไม่ใช่ตัวเลขล้วน · ห้ามอักขระควบคุม/ล่องหน/`<` `>` · ยาว ≤ 40 `[ต้องยืนยันเพดานกับ architect]` · error ในแผ่น ไม่ปิดแผ่น: `ชื่อต้องมีอย่างน้อย 2 ตัวอักษรและไม่ใช่ตัวเลขล้วน`
- a11y: ช่องค้นหา `role="combobox"` + รายการ `role="listbox"` + `role="option"` · แถว "เพิ่มใหม่" เป็น option สุดท้าย · ปุ่ม ≥ 56px

**ตัวดักชื่อคล้าย** — ทำงาน 2 จังหวะ: (1) ระหว่างพิมพ์ รายการ "ใกล้เคียง" ขึ้นบนสุดเป็นคำใบ้เบาๆ (2) **ตอนกด "＋ เพิ่ม … เป็นชนิดใหม่"** ถ้ามีชื่อคล้าย → กล่องยืนยัน (ไม่ใช่ error — เป็นทางแยก):

```
┌ มี "โกเมน" อยู่แล้ว ───────────────┐
│ ที่พิมพ์คือ "โกเมนต์" — ใช่ตัว      │
│ เดียวกันไหม? ถ้าใช่ ให้ใช้ตัวที่มี   │
│ จะได้ไม่เกิดชื่อซ้ำ                 │
│ [   ใช้ "โกเมน"   ]  ← หลัก 56px   │ focus เริ่มที่นี่
│ [ ไม่ใช่ — เพิ่ม "โกเมนต์" ใหม่ ]   │ รอง 56px
└────────────────────────────────────┘
```
- ปุ่มหลัก = **ใช้ตัวที่มี** (ทางที่กันชื่อซ้ำ) · "เพิ่มใหม่" เป็นรอง (ทำได้เสมอ — มติ: ตัวดัก ไม่ใช่ตัวบล็อก)
- คล้ายหลายตัว → รายการ radio (สูงสุด 3) + ปุ่ม "เพิ่มใหม่"
- ใช้กับรูปทรงเหมือนกัน ("หัวใจ" vs "ทรงหัวใจ")
- **กติกาความคล้าย = ฟังก์ชัน pure ตัวเดียว (`lib/jobs/shop-gems.ts`) ที่ server ใช้ตัดสิน "ชื่อซ้ำเป๊ะหลัง normalize" ด้วย** — ขอ architect กำหนดเกณฑ์ (§14.2 A2) · ชุดเคสสำหรับ QA:
  - ต้องเตือน: `โกเมน`↔`โกเมนต์` · `อเมทิสต์`↔`อเมทิส` · `CZ`↔`cz`↔`C Z` (เท่ากันหลัง normalize — ชนิดนี้ **ไม่ต้องถาม** ใช้ตัวเดิมให้เลย) · `ไพลิน`↔`ไพลิน ` (เว้นวรรคท้าย)
  - ต้องไม่เตือน (คนละชนิดจริง): `ทับทิม`↔`ไพลิน` · `ซิทริน`↔`เพอริดอท` · `กลม`↔`หยดน้ำ`
  - ชื่อสั้น ≤ 3 ตัวอักษร: เทียบเฉพาะ "เท่ากันหลัง normalize" (กัน `CZ`↔`AZ` เตือนมั่ว)
  - จับไม่ได้ (รู้และยอมรับ P5): `Blue Topaz`↔`บลูโทแพซ` · `CZ`↔`เพชรรัสเซีย`

**รูปทรงใหม่ — ถาม 1 ค่า/2 ค่า** (หลังตัวดักผ่าน):
```
┌ รูปทรงใหม่: "ทรงใบไม้" ────────────┐
│ ใส่ขนาดกี่ค่า?                     │
│ ┌────────────────────────────────┐ │
│ │ (○) 1 ค่า  เช่น กลม            │ │ แถว 64px · ตัวอย่างช่อง [ 4 ] มม.
│ ├────────────────────────────────┤ │
│ │ (○) 2 ค่า  กว้าง × ยาว เช่น ไข่ │ │ ตัวอย่างช่อง [ 4 ] × [ 6 ] มม.
│ └────────────────────────────────┘ │
│ ⚠ เลือกแล้วแก้ไม่ได้หลังมีคนใช้     │ 15 amber
│ [   ตกลง   ] (aria-disabled จนเลือก)│
└────────────────────────────────────┘
```
เหตุผลที่ถามตอนสร้างรูปทรง ไม่ถามต่อแถว: ช่องขนาดต้องถูกต้องเสมอ ไม่ให้แต่ละแถวเลือกเอง (กัน `4×4` ของทรงกลม)

### 3.5 state ครบ 4 ของ W-4

| state | หน้าตา |
|---|---|
| loading | เข้าขั้นแล้วโหลดรายการชนิด/รูปทรง/ขนาดที่เคยใช้: skeleton ใต้คำถาม (`role="status" aria-label="กำลังโหลดรายการพลอย"`) · **กรอกได้ทันทีไม่รอ** (ปุ่มเปิด sheet ใช้ได้ — sheet แสดง skeleton ในรายการ) |
| empty | (ก) ยังไม่ตอบ — §3.2 · (ข) "ไม่มีพลอย" — สรุป `ไม่มีพลอย — ใบนี้ไม่มีขั้นฝังพลอย` + `เปลี่ยน` · (ค) แคตตาล็อกว่างทั้งระบบ — ข้อความใน sheet §3.4 |
| error | **โหลดรายการไม่ได้**: แถบ amber `role="status"` `โหลดรายการพลอยไม่ได้ — พิมพ์ชื่อเองได้ แต่ระบบยังเช็คชื่อซ้ำให้ไม่ได้` + `[ลองอีกครั้ง]` 48px (ไม่บล็อก) · **ต่อช่อง**: ข้อความแดง+⚠ ใต้ช่อง (ตาราง §3.6) · **ตอนเปิดงานแล้ว server ปฏิเสธพลอย**: กลับ W-4 แถวนั้นขยาย + กล่องแดง `role="alert"` `พลอยแถว {n}: {เหตุผล}` · ฟอร์ม/รูป/แถวอื่นคงอยู่ · session หมด = แผ่น PIN ซ้อนเดิม (ไม่ unmount ฟอร์ม) |
| success | แถวพับ + รวมพลอยทั้งใบ + ถัดไป primary |

| ขนาดว่าง (1 ค่า / 2 ค่า) | `ใส่ขนาด (มม.)` / `ใส่ทั้งกว้างและยาว (มม.)` |
| ขนาดผิด | `ขนาดต้องเป็นตัวเลขมากกว่า 0 ไม่เกิน 100 มม. (ทศนิยมไม่เกิน 2 ตำแหน่ง)` |
| จำนวนผิด | `จำนวนต่อชิ้นต้องเป็นเลข 1–1,000` |
| แถวซ้ำ | `มีพลอยแบบเดียวกันอยู่แล้วที่แถว {n}` · ปุ่ม `รวมเข้าแถว {n}` |
| ตำแหน่งผิด | ข้อความ `name_invalid` เดิม |
| แถวไม่ครบ (aria-disabled) | `แถว {n} ยังไม่ครบ — {ใส่ขนาด / เลือกรูปทรง / …}` |
| ถัดไป (ยังไม่ตอบ) | `เลือกก่อนว่าฝังพลอยไหม` |
| มีพลอยแต่ไม่มีแถว | `เพิ่มพลอยอย่างน้อย 1 รายการ หรือเลือก "ไม่มีพลอย"` |
| ใบถูกเปิดแล้วแต่ชื่อใหม่ตรงของที่มี (race) | W-8: `ชนิด "{ชื่อ}" มีในระบบอยู่แล้ว — ใช้ตัวเดิมให้` (info ไม่ใช่ error) |
| ล็อกหลังช่างรับ | `ช่างรับงานแล้ว แก้พลอยไม่ได้ — แจ้งออฟฟิศ` |
| ใบปิด/ยกเลิก | `ใบนี้ปิดหรือยกเลิกแล้ว — แก้พลอยไม่ได้` |
| ไม่ใช่ผู้เปิด | `แก้พลอยได้เฉพาะคนที่เปิดใบนี้` |
| ส่งถี่ (สร้างชื่อใหม่เกินเพดาน) | `เพิ่มชื่อใหม่ถี่เกินไป — รอสักครู่ หรือใช้ชื่อที่มีในรายการ` `[เพดานให้ architect]` |

### 3.7 a11y / edge ของ W-4

- เปลี่ยนขั้น → focus หัว "พลอย" (ShopOpenFlow ทำอยู่) · แถวขยาย → focus ช่องแรกที่ยังว่าง · เพิ่มแถว → focus "ชนิด" ของแถวใหม่ · ลบแถว → focus ปุ่ม "เพิ่มพลอย" (กัน focus หล่น)
- แถวพับเป็นปุ่ม (`aria-expanded`) · รวมทั้งใบ `aria-live="polite"` เปลี่ยนเมื่อหยุดพิมพ์ ~400ms (ไม่อ่านทุกตัวอักษร) · ป้ายใช้ไอคอน+คำ
- ชื่อยาว/ไม่มีเว้นวรรค: `break-words [overflow-wrap:anywhere]` ทุกที่ · แถวพับตัดได้ 2 บรรทัด
- มีแถวหลายสิบ: เลื่อนปกติ · "รวมพลอยทั้งใบ" อยู่ท้ายรายการ + sticky ปุ่มถัดไป — ไม่ทำ virtualization
- รีเฟรช/ปิดหน้า = ฟอร์มหายทั้งก้อน (เหมือน W2 P3 — **ยังไม่ทำ draft ลง storage** แต่พลอยพิมพ์เยอะกว่ารูป → เป็นตัวชี้วัด validate ข้อ 1/5)
- เปลี่ยนจำนวน (กลับ W-3) แล้วกลับมา W-4: รวมทั้งใบอัปเดตตาม (คำนวณจาก state ไม่ cache)
- เปลี่ยนคนระบุตัว/ "เปิดอีกใบ" → ล้างพร้อมฟอร์ม (กติกาเดิม)

## 7. ออฟฟิศ — แคตตาล็อกพลอย (หน้าใหม่ `/oem/gems`)

### 7.1 ตัดสิน: **หน้าใหม่ ไม่ใช่แท็บใน `/oem/rates`**

`/oem/rates` เป็นหน้ายาวหน้าเดียวเรียงการ์ด (ไม่มีแท็บเลย — ตรวจ `RatesPageClient`) + มีฟอร์มกรอกต้นทุนหลายชุดอยู่แล้ว · แคตตาล็อกพลอยเป็นข้อมูลที่โตเรื่อยๆ (ชนิด×รูปทรง×ขนาด อาจร้อยแถว) + ต้องกรอง/ค้น/รวมชื่อ → ใส่ในหน้าเดิมจะดันการ์ดต้นทุนลงล่างและต้องเพิ่ม pattern แท็บที่ไม่มีใน repo · **หน้าใหม่**: สิทธิ์เหมือน `/oem/rates` (`getEffectiveRole() === 'staff'` → `EmptyState` "หน้านี้จำกัดสิทธิ์") + การ์ดลิงก์ `แคตตาล็อกพลอย →` ท้ายหน้า `/oem/rates` + ใส่ในเมนูข้าง `[ต้องยืนยันตำแหน่งเมนูกับ frontend/เจ้าของ]` · trade-off: เพิ่มหน้า 1 หน้า (นับเป็นที่ที่ต้องจำ) แลกกับหน้าต้นทุนเดิมไม่ขยับ

ภายในหน้ามี 3 แท็บ (`role="tablist"` · เก็บใน `?tab=` ให้ลิงก์/รีเฟรชคงที่): **รายการพลอย** (หลัก — ราคา) · **ชนิด** · **รูปทรง**

### 7.2 แท็บ "รายการพลอย"

```
┌ แคตตาล็อกพลอย ──────────────────────────  [＋ เพิ่มรายการ] (รอง) ┐
│ [รายการพลอย] [ชนิด] [รูปทรง]                                      │
│ ┌ tile ─────────┐┌ tile ──────────────┐┌ tile ─────────────────┐ │
│ │ ทั้งหมด 48    ││ ยังไม่มีราคา 12 ⚠  ││ เพิ่มจากหน้างาน 7 วัน 9 │ │ ← ปุ่มกรอง aria-pressed
│ └───────────────┘└────────────────────┘└───────────────────────┘ │
│ [ค้นหาชื่อ…] [ชนิด ▾] [รูปทรง ▾] ☐ แสดงที่ปิดใช้งาน               │
│ ชนิด    รูปทรง   ขนาด มม.  ราคา/เม็ด (บาท) มีผลตั้งแต่  ใช้ใน      │

│         กลม      2         ⚠ ยังไม่มีราคา   —          0         [ตั้งราคา][รายละเอียด]│
│ CZ      กลม      1.5       ___.__ …                              │

- เรียง: ชนิด → รูปทรง → ขนาด (ชื่อชนิดแสดงเฉพาะแถวแรกของกลุ่ม แต่ทุกแถวมี `aria-label` เต็ม — อ่านด้วย screen reader ได้ทุกแถว)
- ราคา = THB ต่อเม็ด · ตัวเลข `tabular-nums` ชิดขวา · **ยังไม่มีราคา = chip amber + ⚠ "ยังไม่มีราคา" (ไม่ใช่ 0 ไม่ใช่ "—")** (design R6) · ตัวเลขราคาในภาพ wireframe นี้เป็น `___` โดยตั้งใจ
- คอลัมน์ "ใช้ใน" = จำนวนใบงาน (ที่ยังไม่ปิด) + แม่แบบ SKU ที่อ้างอยู่ — ใช้ตัดสิน ลบ/ปิด/รวม
- ป้าย `จากหน้างาน` (เพิ่มโดยผู้จัดการ) ข้างชื่อ เมื่อสร้างภายใน 7 วัน — **ไม่มีสถานะ "รอยืนยัน" ที่ต้องกดอนุมัติ** (มติ: ไม่บังคับรอออฟฟิศ) · ตัวกรอง tile ที่ 3 ใช้หาของใหม่เพื่อไล่ตรวจชื่อซ้ำ
- มือถือ/จอแคบ: ตารางเลื่อนแนวนอน `min-w-[760px]` (pattern `/production` เดิม — ออฟฟิศใช้เดสก์ทอปเป็นหลัก) · ปุ่มแถว ≥ 44px
- `＋ เพิ่มรายการ` (รอง — เจ้าของสั่ง "อย่านั่งสร้างก่อน" รายการส่วนใหญ่มาจากหน้างาน) เปิด `Modal` เดียวกับตัวเลือกใน W-4 (ชนิด/รูปทรง/ขนาด + ราคาเริ่มต้นไม่บังคับ)

**`ตั้งราคา` (Modal)**
```
┌ ตั้งราคา — โกเมน · ไข่ · 4×6 มม. ──────────┐
│ ราคาปัจจุบัน ___ บาท/เม็ด · ตั้งแต่ ___    │ หรือ "ยังไม่เคยตั้งราคา"
│ ราคาใหม่ (บาทต่อเม็ด) *   [ ________ ] บาท │ inputMode=decimal · ทศนิยม ≤ 4

│ ผู้ขาย · ไม่บังคับ        [ ____________ ] │
│ หมายเหตุ · ไม่บังคับ      [ ____________ ] │
│ ⓘ ราคาวันเดียวกันที่ตั้งซ้ำ = แก้ราคาเดิม   │

- ข้อความ error: `ราคาต้องเป็นตัวเลขมากกว่า 0 และไม่เกิน 1,000,000 บาท` · `วันที่มีผลต้องอยู่ระหว่างปี 2020 ถึงไม่เกิน 1 ปีข้างหน้า` · DB ปฏิเสธ = ข้อความผ่าน humanize · ค่าที่กรอกไม่หาย · success toast `ตั้งราคา … แล้ว` + แถวอัปเดต
- ทศนิยมถึง 4 ตำแหน่ง (เม็ดเล็กราคาต่ำกว่า 1 บาทพบบ่อย) `[ต้องยืนยันกับ architect/เจ้าของ]` · หน่วย = เม็ด ทั้งหมด (มติ ง4 ①) — ไม่มีตัวเลือกกะรัต

**`รายละเอียด` (Modal)**: ชื่อเต็ม · ประวัติราคา (ตาราง: มีผลตั้งแต่ · ราคา · ผู้ขาย · ใครตั้ง) · หมายเหตุ · ใช้ใน (n ใบงาน · m แม่แบบ) · ปุ่ม `ปิดใช้งาน`/`เปิดใช้งาน` · ปุ่ม `ลบรายการ` (**แสดงเฉพาะที่ไม่ถูกใช้เลย**; ถูกใช้ = ปุ่มหายแล้วมีข้อความ `ลบไม่ได้ — ถูกใช้ใน {n} ใบงาน/แม่แบบ · ปิดใช้งานแทนได้`) · ลบ = กล่องยืนยัน

|---|---|

### 7.4 แท็บ "ชนิด" และ "รูปทรง" + **รวมชื่อซ้ำ**

```
┌ ข้อเสนอรวมชื่อ (ระบบเดา — ตรวจก่อนรวม) ──────────────────┐ พับได้ · ซ่อนเมื่อ 0
│ "โกเมน" ↔ "โกเมนต์"      ใช้ 12 / 1 ใบงาน      [รวมชื่อ…]  │
└──────────────────────────────────────────────────────────┘
ชื่อ          ขนาดที่มี   ใช้ในใบงาน  เพิ่มเมื่อ      
โกเมน         5           12          —                [เปลี่ยนชื่อ][รวมชื่อ…][ปิดใช้งาน][ลบ]
โกเมนต์ [จากหน้างาน] 1    1           20 ต.ค.          ...
```
- "ข้อเสนอรวมชื่อ" ใช้ฟังก์ชันความคล้ายเดียวกับตัวดักฝั่งหน้างาน (pairwise บนรายการชื่อ — ไม่หนัก) → ออฟฟิศไม่ต้องไล่หาเอง
- แท็บ "รูปทรง": มีคอลัมน์ `ขนาดกี่ค่า` (อ่านอย่างเดียว — **แก้ไม่ได้เมื่อมีรายการใช้แล้ว**) · เปลี่ยนชื่อ/ปิด/ลบ(ที่ไม่ถูกใช้)/รวมชื่อ เหมือนชนิด
- เปลี่ยนชื่อ: `Modal` 1 ช่อง ผ่านกฎชื่อเดียวกัน + ตัวดักชื่อคล้าย (กันเปลี่ยนชื่อไปซ้ำของที่มี) · ใบที่เปิดแล้วยังแสดงชื่อเดิมตอนสั่ง (snapshot)

**`รวมชื่อ…` (Modal) — A → B**
```
┌ รวมชื่อซ้ำ — ชนิดพลอย ──────────────────────────────────┐
│ ชื่อที่จะเลิกใช้ (A)  [ โกเมนต์ ▾ ]  ใช้ใน 1 ใบงาน · 1 แม่แบบ SKU │
│ เปลี่ยนไปใช้ชื่อ (B)  [ โกเมน   ▾ ]  ใช้ใน 12 ใบงาน · 3 แม่แบบ     │
│ ผลที่จะเกิด                                                       │
│  • รายการพลอย 1 ขนาดและแม่แบบ SKU 1 รายการ ย้ายไปอยู่ภายใต้ "โกเมน" │
│  • ขนาดที่ซ้ำกัน (n) รวมเป็นรายการเดียว — ใช้ราคาของ "โกเมน"         │
│    ราคาของ "โกเมนต์" {k} ราคา **จะไม่ถูกย้าย**                      │
│  • ใบงานที่เปิดแล้วยังแสดงชื่อเดิมตอนสั่ง ("โกเมนต์") ไม่เปลี่ยน       │
│  • ย้อนกลับไม่ได้ · บันทึกประวัติว่าใครรวมเมื่อไร                    │
│ [ยกเลิก]                                  [รวมชื่อ]                │
└──────────────────────────────────────────────────────────────────┘
```
- ตัวเลขในกล่อง "ผลที่จะเกิด" มาจาก preview ของ DB (อ่านอย่างเดียว) · loading = skeleton `กำลังตรวจผลกระทบ…` + ปุ่มรวม aria-disabled · error `ตรวจผลกระทบไม่ได้ — ลองอีกครั้ง` · A = B ไม่ได้ (ตัวเลือก B ไม่รวม A)
- A มีราคา แต่ B ไม่มี → บรรทัดแดง/amber เพิ่ม `"โกเมน" ยังไม่มีราคา ส่วนของ "โกเมนต์" มีราคา — ตั้งราคาให้ "โกเมน" หลังรวม` (ไม่บล็อก — ผู้ใช้ตัดสิน)
- ปุ่มรวมเป็น `danger` outline (ไม่ใช่ primary แดง) · focus เริ่มที่ "ยกเลิก" · สำเร็จ toast `รวม "โกเมนต์" เข้ากับ "โกเมน" แล้ว` + แถว A หายจากรายการ (หรือขึ้นป้าย `รวมเข้ากับ …` ใต้ "แสดงที่ปิด")
- ใบหน้างานที่ค้างใช้ id ของ A ระหว่างรวม → server ต้อง resolve ไป B ไม่ล้ม (§14.2 A6)

### 7.5 ลบ / ปิดใช้งาน — กติกาเดียวทั้ง 3 แท็บ
- **ลบได้เฉพาะที่ไม่ถูกใช้เลย** ("ชื่อที่ไม่ถูกใช้ลบได้" — มติ) · ถูกใช้ = ปิดใช้งาน (ซ่อนจาก dropdown หน้างาน แต่ใบ/แม่แบบเก่ายังอ่านได้) หรือรวมชื่อ
- ปิดใช้งานแล้ว: ขึ้นเฉพาะเมื่อติ๊ก "แสดงที่ปิดใช้งาน" · เปิดกลับได้

### 8.2 ใบ A5 — ตารางพลอย

เพิ่มใน `JobSheet` **หลังตารางขั้น ก่อนกล่องหมายเหตุ** (ลำดับการอ่านบนกระดาษ: ใบนี้ทำอะไร → เดินขั้นไหน → ใช้พลอยอะไร → เขียนหมายเหตุ) · `PrintableJob` เพิ่ม `gems: { label; qtyPerPiece; qtyTotal; position }[]` + `gemsState` ประกอบทีละ field (ไม่ spread · ไม่มีราคา/เผื่อแตก — ต้องแก้เทสต์ที่ล็อกรายชื่อ key เหมือนตอนรูป)

```
พลอย (ขั้นฝังพลอย)                              รวมทั้งใบ 1,120 เม็ด
┌──────────────────────────────┬────────┬────────┬───────────────┐
│ ชนิด · รูปทรง · ขนาด          │ /ชิ้น  │ รวม    │ ตำแหน่ง        │
│ โกเมน · ไข่ · 4×6 มม.         │ 2      │ 70     │ บ่าซ้าย-ขวา   │
│ CZ · กลม · 1.5 มม.            │ 30     │ 1,050  │ ล้อมรอบ       │
└──────────────────────────────┴────────┴────────┴───────────────┘
```
- ใบที่**ไม่มีขั้นฝัง** = ไม่มีองค์ประกอบใหม่เลย (layout เดิมเป๊ะ — เทสต์ DOM เดิมต้องไม่พัง)
- ขั้นฝังแต่ไม่ระบุพลอย: บรรทัดเดียว `พลอย: ยังไม่ระบุ — ถามออฟฟิศก่อนฝัง` (กันช่างเดา) + แถบ `print:hidden` บนจอพิมพ์เตือนออฟฟิศก่อนพิมพ์
- ตัวอักษรตาราง 8.5pt (เท่าตารางขั้น) · **ไม่เล็กกว่า 8pt เด็ดขาด** · ตัวเลขชิดขวา `tabular-nums` · เลขเริ่มจากหลักเดียวถึงหลักล้านต้องไม่ตัดบรรทัดกลางตัวเลข

### 8.3 กติกาล้นหน้า A5 — "ตัดอะไรก่อน" (ตัดสินเอง — ต่างจาก Yoda บางส่วน)

งบ (จาก `ux-job-photos.md` §3.6 — **ประมาณ ยังไม่วัดกระดาษ**): พื้นที่พิมพ์ 194 มม. · หัวใบ 47–74 มม. · ตารางขั้น 9 + 9×N · หมายเหตุ ≈ 23 มม. · เหลือ = 194 − หัว − 32 − 9N. ตารางพลอยประมาณ 10.5 มม. (หัวตาราง) + 5.5 มม./แถว (ชื่อไม่ยาว/ตำแหน่งบรรทัดเดียว) ⇒ ที่ว่างพอวางพลอยโดยประมาณ: **7 ขั้นหัวสั้น ≈ 7 แถว · 9 ขั้นหัวสั้น ≈ 4 แถว · 11 ขั้น ≈ 0–1 แถว · หัวยาวสุด ≈ น้อยลงอีก 4–5 แถว** — ใบที่มีพลอยคือใบที่ขั้นเยอะที่สุดอยู่แล้ว (มีฝังพลอย) ⇒ **ล้นจริงและบ่อย ต้องมีกติกาตายตัว ไม่ใช่กรณีขอบ**

บันได (ไล่จากเสียน้อยสุด — ทำทีละขั้นจนพอดี):
1. **ตัดรูปหลักออกจากใบ** (คืน ≤ 12 มม.) — ข้อมูลหาย = ช่างยังเห็นรูปผ่าน QR · แถบ `print:hidden` `ตัดรูปออกเพื่อให้ตารางพลอยพอดี — ช่างดูรูปผ่าน QR`
2. **บีบตารางพลอยเป็นโหมดกระชับ**: 1 แถวต่อพลอย ตำแหน่งต่อท้ายชื่อเป็นตัวรอง (8pt) แถว ≈ 4.5 มม. (คืนได้ ≈ 20% ของตาราง)
3. **ย้ายตารางพลอย "ทั้งก้อน" ไปแผ่นที่ 2** (`break-before: page`) หัวแผ่น `พลอย · JB-0031 · {ชื่อแบบ}` + `แผ่น 2/2` · แผ่นที่ 1 เหลือบรรทัดเดียว `พลอย {n} รายการ · รวม {m} เม็ด — ดูแผ่นที่ 2` + `แผ่น 1/2` · แถบ `print:hidden` `ใบนี้พิมพ์ 2 แผ่น — ติดแผ่น 2 ไว้กับถุงงาน` (แผ่น 2 ไม่มี QR)
4. **ห้ามเด็ดขาด**: ตัดแถวพลอยทิ้งให้พอดี · ใช้ "…และอีก n รายการ" แทนรายการ · ย่อตัวอักษร < 8pt · ย่อ/ตัดตารางขั้น (ช่องเซ็น) · ตัดสินเอง**เงียบๆ**โดยไม่มีแถบบอกบนจอพิมพ์

เหตุผลที่ "ห้ามตัดแถว" แข็งกว่า "ตัดรูป": รูปช่างดูซ้ำได้จากมือถือ แต่ตารางพลอยบนกระดาษคือสิ่งที่ช่างฝังอ่านที่โต๊ะ — ตัดแถวแล้วฝังผิดชนิด = เสียพลอยจริง (ต้นทุน)
- ตัววัดความสูงบนจอ (`print:hidden`) ใช้ตัวเดียวกับที่ `ux-job-photos.md` §3.6 ข้อ 5 เสนอ (วัด `article` เทียบกล่อง 194 มม.) แล้วเลือกขั้นบันไดให้ · **jsdom วัด layout ไม่ได้ → ทดสอบมือบนกระดาษจริง 6 เคส**: (7 ขั้น | 9 ขั้น | 11 ขั้น) × (3 แถวพลอย | 10 แถวพลอย หัวยาว) · วัดรูปจริงด้วยไม้บรรทัด (Chrome อาจย่อใบ ≈ 89% — ข้อ 6 เดิม)
- trade-off ของแผ่น 2: เสี่ยงแผ่นหลุด/ลืมติด · แลก = ข้อมูลครบ · ถ้าเจ้าของไม่ชอบ ทางเลือกคือลดจำนวนขั้นบนใบ (ปรับ profile) ไม่ใช่ตัดพลอย (§14.1 Q6)

## 12. Design decision + trade-off

| # | ตัดสินใจ | ทำไม ไม่ใช่แบบอื่น | แลกกับอะไร |
|---|---|---|---|
| D1 | ชื่อใหม่เข้าแคตตาล็อก**ตอนกดเปิดงาน** (ธุรกรรมเดียวกับใบ) | ฟอร์มทิ้งกลางทางไม่ทิ้งชื่อขยะ (P2) | คนอื่นไม่เห็นชื่อใหม่ระหว่างที่ผู้จัดการยังกรอก |
| D2 | W-4 บังคับตอบ "ฝังพลอยไหม" (ไม่มีค่าเริ่มถ้าไม่มีแม่แบบ) | ขั้นฝังเกิดจากพลอย — ลืมแล้วใบไม่มีขั้นฝังโดยไม่สังเกต | +1 แตะทุกใบ |
| D3 | แถวพลอยเป็น accordion ทีละแถว + sheet เต็มจอเลือกชนิด/รูปทรง | `<select>` ค้นหาไม่ได้ · 360px ใส่ 5 ช่อง × หลายแถวไม่ไหว | แตะเพิ่ม 1–2 ครั้งต่อแถว |
| D4 | ตัวดักชื่อคล้าย: ปุ่มหลัก = "ใช้ตัวที่มี" · เพิ่มใหม่ทำได้เสมอ | กันชื่อซ้ำโดยไม่บล็อกงาน (มติ: ตัวดัก ไม่ใช่ตัวบล็อก) | จับได้ไม่ครบ (P5) ต้องพึ่งรวมชื่อของออฟฟิศ |
| D5 | ถามจำนวนค่าขนาด (1/2) ตอนสร้าง**รูปทรง** ไม่ใช่ต่อแถว | ช่องขนาดถูกต้องเสมอ กัน `4×4` ของทรงกลม | รูปทรงใหม่ต้องตอบ 1 คำถาม · แก้ไม่ได้หลังมีคนใช้ |
| D6 | ขนาดละ 1 แถว ไม่มีช่วง | สรุปสั่งซื้อรวมตามขนาดจริงได้ | fancy cut ไล่ขนาดได้หลายแถว |
| D7 | รวมทั้งใบ คูณจำนวนเต็มใน client (DB ชนะ) · ไม่บวกเผื่อแตกบนหน้างาน/ช่าง/A5 | จำนวนเต็มไม่มีปัดเศษ · ช่างนับตามยอดที่ต้องใช้ | เผื่อแตกไปอยู่ที่หน้าสั่งซื้อฝั่งออฟฟิศเท่านั้น |
| D8 | หน้าต่างแก้ของผู้จัดการ = ขั้นแรกรับ (เหมือนรูป) | กติกาเดียว จำง่าย | ช่วงขั้นแรก→ฝังรับ ผู้จัดการแก้ไม่ได้ ต้องเรียกออฟฟิศ (ออฟฟิศแก้ไม่ต้องเหตุผลในช่วงนี้) |
| D9 | W-10 ขยายเป็น "แก้ใบ" (พลอย + รูป) บันทึกพลอยทั้งชุด | หน้าต่างเดียวกัน · พิมพ์ผิดแล้วไม่ลงทันที | ต้องประสานกับ W2 ที่กำลังทำ |
| D10 | ออฟฟิศแก้หลังขั้นฝังรับ = เหตุผลบังคับ + สรุป +/−/~ | พลอยอาจถูกฝังไปแล้ว | ออฟฟิศพิมพ์เหตุผล 1 บรรทัด |
| D11 | แคตตาล็อก = หน้าใหม่ `/oem/gems` + 3 แท็บ (ไม่ใช่แท็บใน `/oem/rates`) | `/oem/rates` ไม่มีแท็บ ยาวอยู่แล้ว · ข้อมูลพลอยโตเรื่อยๆ | หน้าเพิ่ม 1 หน้า + ต้องสร้างแท็บใหม่ |
| D12 | ไม่มีสถานะ "รอยืนยัน" ต้องกดอนุมัติ — มีป้าย `จากหน้างาน` + ตัวกรอง + ข้อเสนอรวมชื่อ | มติ: ไม่บังคับรอออฟฟิศ | ออฟฟิศต้องหมั่นเปิดดู (วัดผล §13 ข้อ 9) |
| D13 | แม่แบบ SKU: Modal จากแถว + เส้นทางหลักคือ "ตั้งเป็นแม่แบบ" จากใบ | ไม่มี `/catalog/[sku]` · มติทะยอยเติม | แม่แบบโตตามใบที่ผลิตจริงเท่านั้น (SKU ไม่เคยผลิตจะว่าง) |
| D14 | หน้าช่าง: กางเฉพาะขั้นฝัง · ขั้นอื่นพับเป็นบรรทัดเดียว | ลดภาระอ่านต่อจอ | ช่างขั้นอื่นแตะ 1 ครั้งถ้าอยากดู |
| D15 | A5: ห้ามตัดแถวพลอย · ล้น→ตัดรูป→บีบ→แผ่น 2 | ฝังผิดชนิด = เสียพลอย | อาจได้ 2 แผ่น (เสี่ยงแผ่นหลุด) |
| D16 | รวมชื่อ = ย้ายอ้างอิง + ไม่ย้ายราคาของ A · ย้อนกลับไม่ได้ | ราคาสองฝั่งชนกัน ต้องมีผู้ตัดสิน | ต้องตั้งราคา B ใหม่ถ้า B ว่างและ A มี (เตือนในกล่อง) |

## 13. ต้อง validate กับผู้ใช้จริง (design จับ usability ไม่ได้)

ผู้จัดการ/ช่าง ≥ 3 คน (Android รุ่นล่าง 1 · iPhone 1 · สายตาไม่ดี 1) + ช่างฝัง 1 + ออฟฟิศ 1–2 · มือถือของตัวเอง · ไม่อธิบายก่อน · ใช้ใบงานล่าสุดที่มีพลอยจริง
1. 🔴 **พิมพ์พลอยจริง 3 แถว (รวม fancy cut 1 แถว)**: วัดเวลา · พิมพ์ผิดกี่ครั้ง · แป้นพิมพ์บัง sheet/ปุ่มไหม · ถ้าหน้า reload กลางทาง เสียหายแค่ไหน (ตัดสินว่าต้องทำ draft ลง storage ไหม — P3 ของ W2)
2. 🔴 **ตัวดักชื่อคล้าย**: ให้พิมพ์ "โกเมนต์" / "อะเมทิส" ขณะมี "โกเมน"/"อเมทิสต์" อยู่ — กด "ใช้ตัวที่มี" หรือข้าม? อ่านกล่องออกไหม (ถ้าข้ามบ่อย = ปุ่ม/ข้อความไม่ชัด)
3. รูปทรงใหม่ "ใส่ขนาดกี่ค่า" เข้าใจไหม · สลับกว้าง/ยาวผิดไหม · เห็นข้อความ "เรียงเป็น 4×6 ให้" แล้วเข้าใจไหม
4. คำถาม "ฝังพลอยไหม" บังคับ — รำคาญไหม · สัดส่วนใบที่มีพลอยจริง (ถ้าเกือบทุกใบมี ให้เปลี่ยนค่าเริ่มเป็น "มีพลอย")
5. sheet เลือกชนิด/รูปทรง บน iOS Safari กับ Android รุ่นล่าง: คีย์บอร์ดบังรายการ/ปุ่มเพิ่มใหม่ไหม
6. ช่างฝังอ่านการ์ดบนมือถือ + A5: ให้นับพลอยออกจากกล่องตาม "รวม" แล้วเทียบ — นับถูกไหม · ตัวเลขรวมเด่นพอไหม
7. 🔴 **พิมพ์ A5 จริง 6 เคส** (§8.3) บนกระดาษ A5 วัดด้วยไม้บรรทัด: กี่เคสต้องตัดรูป/บีบ/แผ่น 2 · แผ่น 2 หลุดหรือลืมไหม
8. ออฟฟิศ: หาคู่ชื่อซ้ำและรวมได้ภายใน 2 นาทีไหม · เข้าใจ "ราคาของ A จะไม่ถูกย้าย" ไหม · ตั้งราคาได้โดยไม่ถาม
9. 🔴 **หลังใช้ 2 สัปดาห์**: สัดส่วนชื่อซ้ำ/เกือบซ้ำในแคตตาล็อก (ตัวดักได้ผลไหม) · ออฟฟิศเข้าหน้ารวมชื่อบ่อยแค่ไหน · รายการ "ยังไม่มีราคา" ค้างกี่รายการ
10. วิซาร์ดยาวขึ้น (5/6 ขั้น): เวลาเปิดใบเฉลี่ยเทียบก่อนมี W-4 · อัตราที่ผู้จัดการเลิกกลางทาง
11. ผู้จัดการเห็นป้าย "จากแม่แบบ/แก้แล้ว/ใหม่" แล้วเข้าใจความต่างไหม · เข้าใจไหมว่าแก้ในใบ "ไม่เปลี่ยนแม่แบบ"
