# UAT Plan — 3J OMS (oms-3j.vercel.app)

> User Acceptance Test สำหรับเจ้าของร้าน (ไม่ต้องเขียนโค้ด) — ไล่กดตามขั้นตอน ติ๊ก ✅/❌ แล้วส่งกลับให้ทีม dev
> เขียนจากการอ่านโค้ดจริง ณ วันที่ทดสอบ (routes / server actions / schema) — ไม่มีฟีเจอร์ในเอกสารนี้ที่ยังไม่ได้ implement

---

## 1. ภาพรวม

**ระบบคืออะไร:** OMS (Order Management System) MVP ของ 3J Jewelry ใช้:
- รวมออเดอร์จากหลายช่องทาง (Shopee/Lazada/TikTok) มาไว้ที่เดียว
- จดออเดอร์เร็วตอนไลฟ์ขายของ (TikTok Live) แบบ manual
- คุมสต็อกกลาง (central stock) กันของ oversell

**ทดสอบที่ไหน:** `https://oms-3j.vercel.app`

**ใครทดสอบ:** เจ้าของร้าน/ผู้ใช้งานจริง (ไม่ต้องมีความรู้โค้ด แต่ข้อ Webhook อาจต้องขอให้ทีม dev ช่วยยิง request แทน — ระบุไว้ในเคสนั้น)

**Preconditions ทั่วไป:**
- เปิดผ่านมือถือและคอมพิวเตอร์อย่างละ 1 รอบ (จอเล็ก/จอใหญ่ ใช้งานจริงต่างกัน)
- เตรียมสินค้าตัวอย่างไว้ทดสอบ 2-3 SKU (จะได้ไม่ต้องพิมพ์ชื่อ SKU สดๆ หน้างาน)
- บันทึกทุกครั้งที่เจอ "อาการแปลกๆ" แม้ไม่ชัวร์ว่าใช่บั๊ก — ใช้ Bug Report Template ท้ายเอกสาร

| b | **ข้อมูลสินค้า (product) ในระบบตอนนี้มีน้อย/อาจว่างเปล่า** | บาง test case (Stock, Live, Orders) ต้องเพิ่มสินค้าใหม่ก่อนถึงจะเทสต์ flow อื่นได้ — ลำดับการเทสต์ในเอกสารนี้จงใจให้ "เพิ่มสินค้า" อยู่ก่อน |
| c | **หน้า `/shop` (แคตตาล็อกหน้าร้านสาธารณะ) ยังไม่ได้ deploy จริง** | ทดสอบจาก prototype ไฟล์ `docs/3j-jewelry/web/product-catalog.html` (เปิดในเบราว์เซอร์ตรงๆ จากเครื่อง ไม่ใช่ URL ออนไลน์) แทน — ผลทดสอบเป็นเพียง "ตรวจ UX/เนื้อหา" ไม่ใช่ระบบจริงที่เชื่อมฐานข้อมูล |
| d | **ยังไม่ได้ verify ว่า build ล่าสุดขึ้น production เรียบร้อยไม่มี error** | ถ้าเข้า URL แล้วเจอหน้าเว็บพังทันที (500/blank page) ให้หยุดแจ้งทีม dev ก่อน ไม่ต้องไล่เทสต์เคสอื่นต่อ |
| e | **Webhook รับออเดอร์จาก Shopee/Lazada/TikTok จริงยังไม่เปิดใช้งาน (P0 fail-closed โดยตั้งใจ)** — ทุก request จะถูกปฏิเสธ (501) จนกว่าจะมีการเชื่อมต่อจริงแต่ละแพลตฟอร์ม | เทสต์ได้แค่ "ระบบปฏิเสธ request แปลกปลอมถูกต้องหรือไม่" ไม่สามารถเทสต์ "ออเดอร์จาก Shopee เข้ามาอัตโนมัติ" ได้ในตอนนี้ — เคส Webhook ต้องให้ทีม dev ช่วยยิง request ทดสอบให้ (ใช้เครื่องมือเช่น Postman) |
| f | **การแก้ไขข้อมูลสินค้าที่เพิ่มไปแล้ว (แก้ชื่อ/แก้ SKU) ยังไม่มีปุ่มในระบบ** | ถ้าพิมพ์ชื่อ/SKU ผิดตอนเพิ่มสินค้า ตอนนี้ยังแก้ไม่ได้ผ่านหน้าเว็บ (ต้องให้ dev แก้ในฐานข้อมูลตรง) — เทสต์เฉพาะ "เพิ่มสินค้าใหม่" เท่านั้น ไม่มีเคส "แก้ไขสินค้า" ในเอกสารนี้ |
| g | **ไม่มีฟีเจอร์ "วัดขนาด" ระหว่างไลฟ์ในระบบนี้** | ระบบจดออเดอร์ไลฟ์บันทึกได้แค่ ชื่อผู้ซื้อ/สินค้า/จำนวน/ราคา — ไม่มีช่องบันทึกไซส์แหวน/ขนาดข้อมือ ถ้าต้องการฟีเจอร์นี้ให้แจ้งทีม dev แยกเป็น request ใหม่ |

## 3. Test Cases แยกตาม Module

วิธีอ่านตาราง: ทำตามขั้นตอนเรียงตัวเลข แล้วเทียบ "ผลที่คาดหวัง" — ถ้าตรงติ๊ก ✅ ถ้าไม่ตรงติ๊ก ❌ แล้วจดหมายเหตุ/สกรีนช็อต

### Module B — Stock (สต็อกกลาง)

| ID | หัวข้อ | Precondition | ขั้นตอน | ผลที่คาดหวัง | ✅/❌ | หมายเหตุ |

| B8 | ปรับสต็อกเป็นค่าติดลบ | — | 1. พิมพ์จำนวนคงเหลือเป็น `-1` | ระบบไม่ยอมให้บันทึก แจ้งเตือนชัดเจน | | |

### Module C — Live-selling (จดออเดอร์เร็วตอนไลฟ์)

| ID | หัวข้อ | Precondition | ขั้นตอน | ผลที่คาดหวัง | ✅/❌ | หมายเหตุ |
|----|--------|--------------|---------|--------------|-------|----------|
| C1 | เปิดไลฟ์ใหม่ | ไม่มีไลฟ์ที่เปิดค้างอยู่ | 1. เข้าเมนู "ไลฟ์"  2. ตั้งชื่อไลฟ์ (หรือเว้นว่าง)  3. กดเริ่มไลฟ์ | เข้าสู่หน้าจดออเดอร์ของไลฟ์นั้นได้ทันที | | |
| C2 | เปิดไลฟ์ซ้ำขณะมีไลฟ์เปิดอยู่แล้ว | มีไลฟ์เปิดอยู่ 1 อัน (จาก C1) | 1. ลองกดเริ่มไลฟ์ใหม่อีกครั้ง (อาจเปิด 2 แท็บ กดพร้อมกัน) | ระบบต้องปฏิเสธ แจ้งว่ามีไลฟ์เปิดอยู่แล้วให้ปิดก่อน — **ต้องไม่มี 2 ไลฟ์เปิดพร้อมกัน** | | |
| C3 | เพิ่มสินค้าเข้าตะกร้าระหว่างไลฟ์ | มีไลฟ์เปิดอยู่ + มีสินค้าในสต็อก | 1. ค้นหาสินค้าด้วยชื่อ/SKU  2. เลือกสินค้าเข้าตะกร้า  3. ปรับจำนวน  4. ใส่ราคาต่อชิ้น | รายการแสดงในตะกร้า ยอดรวมคำนวณถูกต้อง | | |
| C4 | บันทึกออเดอร์ปกติ (สต็อกพอ) | มีของในสต็อกเพียงพอ | 1. ใส่ชื่อผู้ซื้อ  2. เพิ่มสินค้า จำนวนไม่เกินสต็อกที่มี  3. กดบันทึกออเดอร์ | บันทึกสำเร็จ ยอดขายไลฟ์ (GMV) และจำนวนออเดอร์อัปเดต ตะกร้าเคลียร์พร้อมรับรายการถัดไป | | |
| C5 | บันทึกออเดอร์โดยไม่ใส่ชื่อผู้ซื้อ | — | 1. ไม่กรอกชื่อผู้ซื้อ  2. เพิ่มสินค้า  3. บันทึก | บันทึกได้ (ชื่อผู้ซื้อไม่บังคับ) แสดงเป็น "ไม่ระบุชื่อผู้ซื้อ" ในรายการล่าสุด | | |
| C6 | บันทึกออเดอร์โดยไม่เพิ่มสินค้าเลย | — | 1. ไม่เพิ่มสินค้าในตะกร้า  2. กดบันทึก | ระบบแจ้งเตือน "กรุณาเพิ่มสินค้าอย่างน้อย 1 รายการ" ไม่สร้างออเดอร์เปล่า | | |
| C7 | **สั่งเกินสต็อกที่มี (oversell คนเดียว)** | สินค้าเหลือน้อย เช่น 2 ชิ้น | 1. สั่งจำนวน 5 ชิ้น (มากกว่าที่มี)  2. บันทึก | ระบบยังบันทึกออเดอร์ให้ (ไม่ปฏิเสธ) แต่ขึ้นสถานะ "ของไม่พอ" (oversold) ชัดเจน พร้อมบอกจำนวนที่เหลือจริง | | |
