# Workflow: "ออกแบบแหวนแถวเอง" (Ring Builder) — brief ให้คนออกแบบ UI ภายนอก

> ux-ui (Padmé) · 9 พ.ย. 69 · **ขอบเขต = workflow เท่านั้น** (ไม่มี wireframe/layout/token — เจ้าของออกแบบหน้าจอเองข้างนอกแล้วส่งกลับมาให้ตรวจ)
> ใช้เป็น brief: อ่านจบใน ~10 นาที · ตัวเลขเงินเป็น THB · ตัวเลขในเอกสารนี้เป็น `{ตัวแปร}` หรือตัวอย่างเท่านั้น
> ค่าที่ต้องมาจากเจ้าของแต่ยังไม่มี = `[ต้องยืนยัน: ...]` — **ห้ามผู้ออกแบบ/ผู้พัฒนาเติมเอง**
> หน้าสาธารณะ = มือถือก่อน เปิดใน LINE webview เป็นหลัก · หลังบ้านใช้ component เดิมของ dashboard

## 0. ภาพรวม 6 บรรทัด
1. ลูกค้าเลือกแบบแหวนแถว (3/4/5/6/7 เม็ด) → ทุกเม็ดเริ่มเป็น **CZ ขาว** (รวมในราคาตัวเรือน)
2. ใส่พลอยสีทีละตำแหน่ง คละได้ · สลับตำแหน่งได้ · ราคาเปลี่ยนทันที = ตัวเรือน + Σ พลอยสีแต่ละเม็ด
3. เลือกไซซ์ 45–68 (หรือให้แอดมินช่วย)
4. ได้ **รูปสรุป + รหัสสั่งทำ** → เซฟรูป → ส่งทาง LINE OA (`@3jjewelry` · `https://lin.ee/PzIJl6j`)
5. ไม่มีจ่ายเงินในเว็บ · pre-order ผลิต ≤ 21 วัน · แอดมินรับออเดอร์/ยืนยันราคา-ไซซ์-ชำระเงินในแชท
6. แอดมินตั้งพลอย/ราคา/แบบเอง และตรวจรหัสที่ลูกค้าส่งมา

**ข้อสังเกตจากรูปอ้างอิงของเจ้าของ:** แหวนเรียบ พลอยกลมเม็ดเล็กมาก (~1.5–2.5 มม.) เรียงแถวตรง → เม็ดเล็กเกินกว่าจะแตะบนโมเดลด้วยนิ้ว (ดู §5 ข้อ 6)

## 1. Flow ลูกค้าทีละขั้น

### ขั้น 1 — เลือกแบบ
| | |
|---|---|
| ลูกค้าทำ | เลือกแบบแหวน 1 แบบ |
| ระบบตอบ | พาไปขั้น 2 โดยทุกตำแหน่ง = CZ ขาว · ถ้ามีดราฟต์ค้างในเครื่อง เสนอ "ทำต่อ/เริ่มใหม่" (ไม่ข้ามเอง) |
| ต้องแสดง | รูปแบบ · จำนวนเม็ด · ราคาตัวเรือน · ข้อความว่าทุกเม็ดเริ่มเป็น CZ ขาวรวมในราคาแล้ว |
| กติกา | แสดงเฉพาะแบบที่เปิดขาย · ถ้าแบบเกิน ~6 แบบ ต้องมีตัวกรองจำนวนเม็ด · "แบบละ 3/4/5/6/7 เม็ด" = 1 แบบต่อจำนวนเม็ด หรือหลายแบบ? → Q2 |

### ขั้น 2 — ใส่/สลับพลอย (หน้าหลัก)
| | |
|---|---|
| ลูกค้าทำ | (ก) เลือกตำแหน่ง 1..N (ข) เลือกพลอยให้ตำแหน่งนั้น (ค) ทำซ้ำ · (ง) สลับตำแหน่งพลอย · (จ) หมุนดูโมเดล |
| ระบบตอบ | ภาพแหวน + ราคารวม + รายการอัปเดตทันทีทุกครั้งที่เปลี่ยน |
| ต้องแสดงตลอด | ภาพแหวน · ตำแหน่งทั้งหมดและตำแหน่งที่เลือกอยู่ · **ชื่อพลอยเป็นตัวหนังสือทุกตำแหน่ง** · ราคารวม · ปุ่มไปขั้นถัดไป |
| รายการราคา | ตัวเรือน · พลอยแต่ละชนิด × จำนวน (× ราคาต่อเม็ด = ยอด) · CZ ขาว แสดงเป็น "รวมในตัวเรือน" (ไม่ใช่ 0 บาทที่ดูเหมือนของแถมแยก) · รวม |

**กติกา**
- ตำแหน่งเริ่มต้น: ตำแหน่ง 1 ถูกเลือกไว้แล้ว (ไม่มีสถานะ "ต้องเลือกตำแหน่งก่อน")
- ตัวเลือกพลอย: เฉพาะพลอย **เปิดขาย + มีราคาสำหรับขนาดเม็ดของแบบนี้** — พลอยที่ไม่มีราคาขนาดนั้น **ไม่โผล่เลย** (ไม่ใช่โผล่แล้วเทา) · CZ ขาวอยู่ในตัวเลือกเสมอ (ใช้ย้อนกลับ)
- พลอยทุกเม็ดในวงขนาดเท่ากัน → ลูกค้าไม่เลือกขนาดเม็ด
- ข้อมูลพลอยที่แสดง = **ชื่อ + สี เท่านั้น** (รอบนี้) · ราคาต่อเม็ดแสดงได้
- สลับตำแหน่ง = **สลับ** พลอยของ 2 ตำแหน่ง (ไม่ใช่แทรก) · ต้องมีทางสลับที่ไม่ต้องลาก (ปุ่ม/แตะสองครั้ง) ควบคู่กับลาก
- ทางลัดที่เสนอ (ตัดสินใจเรื่อง UI ให้คนออกแบบ): "ใส่พลอยนี้ทุกเม็ด" · "ล้างกลับเป็น CZ ขาว" — ล้างต้องยืนยัน/เลิกทำได้ (กดพลาดแล้วงานหาย)
- เลือกพลอยแล้วเลื่อนไปตำแหน่งถัดไปเองหรือไม่ = **ให้คนออกแบบเสนอ + ทดสอบ** (ข้อดี: แตะน้อยลง · ข้อเสีย: แตะผิดแก้ยาก/ไม่แน่ใจว่าตำแหน่งไหนถูกเลือก)
- เปลี่ยนแบบกลางทาง: พลอยที่เลือกไว้หาย (จำนวนเม็ด/ขนาดเม็ดต่างกัน) → ต้องเตือนก่อน
- ตำแหน่ง "1..N" = นับซ้าย→ขวาเมื่อมองตรงหน้าแหวน (ใช้นิยามเดียวกันทุกที่: โมเดล · แถบตำแหน่ง · รูปสรุป · รหัส)

### ขั้น 3 — ไซซ์
| | |
|---|---|
| ลูกค้าทำ | เลือกเบอร์ 45–68 · หรือ "ยังไม่รู้ไซซ์ ให้แอดมินช่วย" · หรือไปวัดที่ `/ring-size` |
| ระบบตอบ | เก็บไซซ์ลงดราฟต์ · ไปขั้น 4 |
| ต้องแสดง | ช่วงที่ร้านทำ · ทางไปวัดไซส์ · ผลวัดล่าสุด (ถ้ามี) |
| กติกา | เบอร์เต็มเท่านั้นรอบนี้ (ครึ่งเบอร์ → Q6) · ช่วงอ่านจากค่าเดียวกับเครื่องมือวัดไซส์ (`SHOP_RING_SIZES`) ถ้าเป็น null = ไม่แสดงช่วง ให้เลือกได้แค่ "ให้แอดมินช่วย" (ห้ามแต่งช่วง) · ราคาไม่ขึ้นกับไซซ์ · "ให้แอดมินช่วย" = ตัวเลือกเต็มตัว ไม่ใช่ลิงก์เล็ก (หลายคนซื้อเป็นของขวัญ) · เบอร์ไม่ระบุ มม./ไม่อ้างมาตรฐานสากล (ตามตารางร้าน 3J) |

**ไป-กลับ `/ring-size`:** ก่อนออก บันทึกดราฟต์ (แบบ+พลอย) ในเครื่อง · ไปด้วยลิงก์ปกติ `<a href>` (ไม่ใช่ next/link — header ของหน้านั้นติดเฉพาะโหลดเต็มหน้า) · กลับมา: ดราฟต์ครบ ไม่ต้องเลือกใหม่ · ผลวัดล่าสุด (อ่านจากที่เก็บเดิมของเครื่องมือวัด แบบอ่านอย่างเดียว) เสนอ "ใช้เบอร์นี้" **ไม่เลือกให้เอง** · ผลวัดนอก 45–68 → แจ้งว่านอกช่วงที่ร้านทำ + ทักแอดมินถามได้ ใช้เป็นไซซ์ไม่ได้ · ทางกลับจาก `/ring-size` มาที่นี่ต้องมี (ลิงก์ "กลับไปออกแบบแหวน" หรือปุ่ม Back) → แตะ route ที่ขึ้น prod แล้ว ดู §6 ข้อ 9

### ขั้น 4 — สรุป เซฟรูป ส่ง LINE
| | |
|---|---|
| ลูกค้าทำ | ตรวจรายการ → **บันทึกรูป** → คัดลอกข้อความแล้วเปิด LINE → ส่งรูป+วางข้อความในแชท |
| ระบบตอบ | ตรวจราคา/พลอยกับ server ก่อนออกรหัส · ทำรูปสรุป · ออกรหัสสั่งทำ · คัดลอกข้อความ+เปิดแชท |
| ต้องแสดง | รูปสรุป (§3) · รหัส (คัดลอกได้) · ลำดับขั้นตอน "บันทึกรูปก่อน แล้วค่อยเปิด LINE" · ข้อความว่า **ยังไม่ใช่การสั่งซื้อ** · pre-order ≤ 21 วัน |
| กติกา | **ลำดับสำคัญ:** บันทึกรูปต้องมาก่อนเปิดแชท (หลังเปิดแชทลูกค้ามักไม่กลับมาบันทึก) · ปุ่มหลัก = คัดลอกข้อความแล้วเปิด LINE · **คัดลอกล้ม = ไม่เปิดต่อ** + แสดงข้อความให้กดค้างคัดลอกเอง · ใช้ลิงก์ปกติหน้าเดิม ไม่ใช้ `window.open` (webview บล็อก) · เปิดแชท = ลิงก์ `https://lin.ee/PzIJl6j` ซึ่งฝังข้อความไม่ได้ จึงต้องคัดลอกก่อน (แบบเดียวกับ `copyThenOpen` ของหน้าวัดไซส์) |

**ข้อความที่คัดลอก (ข้อมูลเท่านี้ — ไม่มีข้อมูลส่วนบุคคล/ราคาเนื้อเงิน):** แบบ · ไซซ์ (หรือ "รอแอดมินช่วยเช็ก") · พลอยทุกตำแหน่งเป็นข้อความ · ราคารวม ณ วันที่สร้าง · รหัสสั่งทำ · ประโยคขอให้ยืนยันราคาและขั้นตอนต่อไป (ไม่ใส่คำลงท้ายที่ระบุเพศ)

## 2. State และกรณีพิเศษ (ทุกข้อต้องมีหน้าตา)

| กรณี | ระบบทำ | ลูกค้าเห็น/ทำได้ |
|---|---|---|
| **โหลดรายการแบบ/ราคาไม่ได้** (ขั้น 1) | ไม่ให้เริ่ม | ข้อความผิดพลาดตรงๆ + ลองอีกครั้ง + ทางทักแอดมินทาง LINE · ห้ามขึ้นรหัสข้อผิดพลาด |
| **ไม่มีแบบเปิดขายเลย** | — | "ตอนนี้ยังไม่เปิดให้ออกแบบ" + ทางทักแอดมิน |
| **โหลดราคาไม่ได้กลางทาง** (กลับมาจากพื้นหลัง/รีเฟรชข้อมูล) | แจ้งว่าราคาอาจไม่ใช่ปัจจุบัน | **ห้ามไปขั้นถัดไป** จนกว่าโหลดได้ (ไม่ออกรหัสจากราคาที่ไม่ยืนยัน) |
| **โหลดโมเดล 3D** | เลือกพลอย/ราคาใช้ได้ทันทีโดยไม่รอโมเดล | แสดงภาพชั่วคราว + บอกว่ากำลังโหลด |
| **โมเดลโหลดล้ม** | สลับเป็นภาพ 2D | บอกสั้นๆ + ลองโหลดอีกครั้ง · ไม่บล็อกอะไร |
| **ไม่มี WebGL** | ใช้ภาพ 2D ทันที | ไม่ขึ้นข้อความผิดพลาด (ไม่ใช่ความผิดผู้ใช้) · เลือกพลอยด้วยภาพ 2D ได้เต็มที่ |
| **เครื่องช้า** | วัดความลื่นช่วงแรก | เสนอ "ใช้ภาพ 2D" ให้ผู้ใช้เลือกเอง (ไม่สลับเอง) |
| **พลอยถูกปิดระหว่างเลือก** (ตรวจเมื่อกลับมาที่แท็บ + ก่อนออกรหัส) | ทำเครื่องหมายตำแหน่งที่ใช้พลอยนั้น | แจ้งว่าพลอยไหน ตำแหน่งไหน · ต้องเลือกใหม่ (หรือเปลี่ยนเป็น CZ ขาว) ก่อนไปต่อ · **ไม่สลับให้เงียบๆ** |
| **ราคาเปลี่ยนระหว่างทำ** | ตรวจก่อนออกรหัส | แจ้ง "ก่อน → หลัง" ให้กดรับทราบก่อนเปิดปุ่มส่ง |
| **แบบไม่มีพลอยสีให้เลือกเลย** (ปิดหมด/ไม่มีราคาขนาดนั้น) | — | แจ้งตรงๆ · **ไปต่อได้** ด้วย CZ ขาวทั้งแถวราคาตัวเรือน หรือทักแอดมินถามพลอยสี (ไม่ dead-end) |
| **แบบที่เลือกไว้ถูกปิด/หาย** (ดราฟต์เก่า) | ทิ้งดราฟต์ส่วนที่ใช้ไม่ได้ | แจ้งและพากลับขั้น 1 |
| **LINE webview บล็อกดาวน์โหลด/แชร์ไฟล์** | — | ต้องมีทางสำรองเรียงลำดับ: (1) กดค้างที่รูปเพื่อบันทึก (รูปต้องเป็น `<img>` จริง ไม่ใช่ `blob:` ไม่ใช่ canvas) (2) ปุ่ม "บันทึกรูป" เป็นของแถม ไม่ใช่ทางเดียว (3) คัดลอกข้อความ+เปิด LINE — ข้อความครบ+รหัส แอดมินทำงานต่อได้แม้ไม่มีรูป (4) คัดลอกไม่ได้ → ให้กดค้างเลือกข้อความเอง |
| **ทำรูปไม่สำเร็จ** (ฟอนต์/canvas) | — | ลองใหม่ หรือคัดลอกเป็นข้อความแทน |
| **ตรวจ/ออกรหัสล้ม** | ไม่ทำรูปที่ไม่มีรหัส | แจ้ง + ลองอีกครั้ง + ทักแอดมินเอง |
| **กลับจาก `/ring-size`** | อ่านดราฟต์ | แบบ/พลอย/ตำแหน่งครบ · เสนอใช้ผลวัดล่าสุด · localStorage ถูกล้าง = เริ่มใหม่ได้ ไม่ crash |
| **localStorage ใช้ไม่ได้** | ทำงานต่อไม่จำ | ทำจบได้ ดราฟต์ไม่คงอยู่ (ไป `/ring-size` แล้วกลับ = เริ่มใหม่ — ต้องบอกก่อนออก) |
| **ข้อความยาว/ตัวเลขเยอะ** | — | ชื่อพลอย/แบบยาวต้องไม่ตัดจนอ่านไม่ได้ในรายการ/รูป · ราคาหลักหมื่นไม่ล้น |

## 3. รูปสรุปที่เซฟได้ — **เนื้อหาที่ต้องมี** (layout ให้คนออกแบบ)

**ต้องมี:**
1. แบบ (ชื่อ · จำนวนเม็ด)
2. **ชื่อพลอยทีละตำแหน่งเป็นตัวหนังสือ** (ตำแหน่ง 1..N + นิยาม "นับซ้ายไปขวาเมื่อมองตรงหน้าแหวน") — สีอย่างเดียวไม่พอ (คนตาบอดสี · แอดมินอ่านจากรูปที่ถูกบีบ)
3. ไซซ์ (เบอร์ หรือ "รอแอดมินช่วยเช็ก")
4. ราคา: ตัวเรือน · พลอยแต่ละชนิด × จำนวน · **รวม (THB)** · **วันที่ที่ราคานี้ใช้ (ราคา ณ วันที่สร้าง — ลูกค้าต้องเข้าใจว่าราคาอาจเปลี่ยนภายหลัง และแอดมินเป็นผู้ยืนยัน)**
5. **รหัสสั่งทำ** (ข้อความ พิมพ์/คัดลอกง่าย) + **QR** (บรรจุรหัสล้วน ไม่ใช่ URL)
6. ข้อความ pre-order: **ผลิตไม่เกิน 21 วัน** · แอดมินแจ้งถ้าเสร็จเร็วกว่านี้
7. ข้อความ **"ยังไม่ใช่การสั่งซื้อ — ส่งรูปนี้ให้แอดมินทาง LINE เพื่อยืนยันราคา ไซซ์ และการชำระเงิน"**

## 4. Flow แอดมิน

```
ตั้งพลอย/ราคา ─┐
ตั้งแบบแหวน ───┼─▶ ลูกค้าออกแบบ ─▶ ส่งรูป+ข้อความทาง LINE ─▶ แอดมินวาง/สแกนรหัส ─▶ ดูผลตรวจ
               │                                                                      │
               │            ◀── แจ้งลูกค้า (ราคาเปลี่ยน/พลอยปิด/ถามไซซ์) ◀──────────────┤
               └─ แจ้งวันเสร็จ ≤ 21 วัน ◀─ ยืนยันราคา+ไซซ์+ชำระเงินในแชท ◀─────────────┘
```

### 4.1 เพิ่ม/แก้พลอย (หลังบ้านแยกหน้า — "พลอยสำหรับออกแบบแหวน (ราคาขาย)")
- ข้อมูลต่อพลอย: **ชื่อ · สี (ข้อความที่ลูกค้าเห็น) · สีที่ใช้แสดงในโมเดล · ราคาต่อเม็ดตามขนาดเม็ด (มม. → บาท) · เปิด/ปิด · ลำดับที่แสดง**
- เพิ่มทีละชนิด แยกรายการ (พลอยชนิดเดียวกันสีต่างกัน = คนละรายการ)
- ราคาตามขนาด: ตารางหลายแถว (ขนาด มม. + ราคา) · ขนาดซ้ำห้าม · ราคาต้อง > 0 · พลอยที่ไม่มีราคาขนาดของแบบไหน = ไม่ขึ้นในแบบนั้น → หลังบ้านต้องบอกว่า **พลอยนี้ขายได้ในกี่แบบ/ขาดแบบไหน** (ให้แอดมินรู้ว่าทำไมลูกค้าไม่เห็น)
- ปิดพลอย: เตือนผลก่อน ("ลูกค้าที่กำลังออกแบบอยู่ต้องเลือกใหม่ · รหัสที่ออกแล้วยังตรวจได้")
- แก้ราคา: มีผลกับลูกค้าที่ออกแบบหลังจากนั้น · รหัสเก่าคงราคาเดิม (เทียบกับปัจจุบันได้ที่หน้าตรวจ)
- **ไม่มีช่องความแข็ง/สรรพคุณ** (กฎหน้าลูกค้า) · ไม่มีปุ่มลบรอบนี้ (ปิดอย่างเดียว — Q9)
- ชื่อพลอยที่ตั้งต้อง **ตรงความจริงของวัสดุ** (เช่น CZ สี ไม่ตั้งเป็นชื่อพลอยแท้) — Q4
- **ห้ามปนกับ `/oem/gems`** (นั่นคือ **ต้นทุน** งานผลิต · นี่คือ **ราคาขาย** ที่ขึ้นสาธารณะ — ใช้หน้า/ตารางแยก ป้องกันต้นทุนหลุด)
- สถานะที่ต้องมี: โหลด · ว่าง ("ยังไม่มีพลอย ลูกค้าจะเลือกได้แค่ CZ ขาว") · กรองแล้วไม่เจอ · ผิดพลาด (ค่าที่กรอกไม่หาย) · สำเร็จ

### 4.2 เพิ่ม/แก้แบบแหวน
- ข้อมูลต่อแบบ: **ชื่อ · จำนวนเม็ด (3–7) · ขนาดเม็ด (มม.) · ราคาตัวเรือน (ราคาเดียวทุกไซซ์) · รูป · โมเดล 3D (ไม่บังคับ) · ตำแหน่งเม็ดสำหรับภาพ 2D · เปิด/ปิด**
- **พรีวิว** = ดูเหมือนที่ลูกค้าเห็น (ใช้ตัวเลือกพลอยจริง ไม่ออกรหัส ไม่บันทึก) · ใช้ได้แม้แบบปิดอยู่
- อัปโหลดโมเดลแล้วตรวจว่ามีเม็ดครบตามจำนวน (ตั้งชื่อตามกติกาที่ architect กำหนด) · ไม่มีโมเดล = ลูกค้าเห็นภาพ 2D (ทำงานได้ ไม่ใช่ข้อผิดพลาด)
- **ล็อกหลังเคยออกรหัส:** จำนวนเม็ด/ขนาดเม็ดแก้ไม่ได้ (กระทบความหมายรหัส) → ให้ "ทำสำเนาเป็นแบบใหม่" แทน
- ปิดแบบ: เตือนผลก่อน (ดราฟต์ลูกค้าที่ค้างจะแจ้งว่าแบบปิดแล้ว)
- state เหมือน 4.1

### 4.3 ตรวจรหัสสั่งทำ
| | |
|---|---|
| แอดมินทำ | วางรหัส หรือวางข้อความทั้งก้อนจากแชท (ระบบดึงรหัสเอง · ไม่สนตัวพิมพ์/ช่องว่าง) · หรือสแกน QR (เสริม — เปิดกล้องฝั่งแอดมินเท่านั้น) |
| ระบบแสดง | แบบ · ตำแหน่งพลอยทีละตำแหน่ง · ไซซ์ · **ราคาตอนลูกค้าสร้าง vs ราคาปัจจุบัน** รายบรรทัด+รวม · พลอย/แบบที่ปิดแล้ว · เวลาที่ออกรหัส |
| แอดมินทำต่อ | เทียบตำแหน่งพลอยกับ **รูปที่ลูกค้าส่ง ด้วยตา** · คัดลอกสรุปไปใบงาน/แชท |

**ป้ายผลตรวจ (ต้องแยกกันชัด):**
| กรณี | ความหมาย |
|---|---|
| ไม่พบรหัสในสิ่งที่วาง | ให้ตรวจว่าวางครบ (ไม่ใช่รหัสผิด) |
| รูปแบบผิด / ตรวจเลขท้ายไม่ผ่าน | อาจพิมพ์ผิดหรือถูกแก้ → ขอรหัสใหม่ |
| รูปแบบถูกแต่ระบบไม่เคยออก/ลายเซ็นไม่ตรง | "ระบบไม่ได้ออกรหัสนี้" |
| ถูกต้องแต่เป็นเวอร์ชันเก่า/แบบถูกปิด | แสดงตามที่บันทึกไว้ + บอกว่าไม่ใช้แล้ว |
| ถูกต้อง แต่ราคา/พลอยเปลี่ยนจากตอนสร้าง | แสดงส่วนต่าง **ไม่บล็อก** แอดมินตัดสิน/แจ้งลูกค้า |
| ตรวจล้มทางเทคนิค | **แยกจาก "รหัสผิด" เสมอ** — ห้ามบอกลูกค้าว่ารหัสผิดเพราะระบบพัง |

**ข้อควรรู้ (ต้องบอกบนหน้าตรวจด้วย):** รหัสยืนยันว่า "ระบบออกให้ และแบบ/พลอย/ไซซ์/ราคา ณ ตอนนั้นคือเท่านี้" **ไม่ได้ยืนยันว่ารูปหรือข้อความที่ลูกค้าส่งไม่ถูกแก้** → ต้องเทียบกับรูปด้วยตา · ไม่แสดงข้อมูลส่วนบุคคล/ต้นทุน · ไม่มีประวัติการตรวจรอบนี้

### 4.4 หลังตรวจ → ปิดงาน (นอกระบบในรอบนี้)
รับออเดอร์ทาง LINE → ยืนยันราคา+ไซซ์ (ถ้าไซซ์ยัง "รอแอดมินช่วยเช็ก" ถามในแชท) + ชำระเงินนอกเว็บ → แอดมินแจ้งวันเสร็จ **≤ 21 วัน** (แจ้งให้เร็วกว่านั้นได้) · รอบนี้ไม่มี UI สถานะงาน/แจ้งเตือนอัตโนมัติ

## 5. ข้อห้ามและข้อกำหนดสำหรับคนออกแบบภายนอก (ไม่ต้องวาด — ใส่ในงานให้ครบ)

1. **ห้ามพูดเนื้ออ่อน/เนื้อแข็ง หรือความแข็งของพลอย** ในหน้าลูกค้าทุกจอและรูปสรุป
2. **ห้ามเรียกเพชร/อ้างให้เข้าใจว่าเป็นเพชร** — ใช้ "CZ" เสมอ (ในหน้าลูกค้าเรียก "CZ") · ต้องมีคำว่าไม่ใช่เพชรอย่างน้อยที่จอเลือกพลอย + จอสรุป + รูป
3. **ห้ามราคาเนื้อเงิน/ราคาเงินแท่ง/ส่วนต่างรับซื้อคืน/ต้นทุน อยู่ในจอเดียวกัน** (กฎแบรนด์ 925 — ค่าแรง/ฝังพลอยจะดูแพงเมื่อวางคู่ราคาเงิน) · ห้ามเทียบราคากับคู่แข่ง/ตลาด
4. **ห้ามสรรพคุณ/โชคลาภ/สุขภาพ/พลอยเสก/"ไม่แพ้ผิว"/ความหมายมงคล** · ข้อมูลพลอยที่ขึ้นได้ = ชื่อ + สี
5. **ห้ามขายฝัน** ("เป็นของคุณคนเดียวในโลก" ฯลฯ) · น้ำเสียง: ตรงไปตรงมา ให้ข้อมูลก่อน
6. **Gesture:** ลากสลับตำแหน่งต้อง **ไม่ชนกับการหมุนโมเดล** (และไม่ชนการเลื่อนหน้า) · ข้อกำหนด: (ก) การเลือก/สลับตำแหน่งหลักอยู่ที่ **แถบตำแหน่ง 2D แยกจากโมเดล** ไม่ใช่การลากบนโมเดล (ข) ต้องมีทางสลับที่ไม่ต้องลาก (WCAG 2.5.7) (ค) การแตะเม็ดบนโมเดลเป็นทางเสริมเท่านั้น — เม็ดเล็กมาก (~1.5–2.5 มม.) และบางเม็ดถูกบังเมื่อหมุน (ง) การหมุนโมเดลไม่ทำให้ผู้ใช้เลื่อนหน้าไม่ได้ (ไม่ใช้ `touch-action:none` ทั้งผืน)
7. **มุมมองเริ่มต้นของโมเดล:** หันหน้าพลอยเข้าหาจอ และซูมพอให้เห็นสีทีละเม็ดได้ตั้งแต่แรกเห็น (เม็ดเล็กมาก) · มีมุมมองสำเร็จรูป (หน้า/เฉียง/ข้าง) เป็นทางเลือกแทนการลาก · ไม่ใช้ pinch/scroll-zoom บนมือถือ (ชนการซูมหน้า LINE)
8. **ชื่อพลอยเป็นตัวหนังสือทุกตำแหน่งบนจอ** (ไม่ใช่แค่สี) และใน alt/aria
9. ราคาแสดงเป็น THB · **ราคาเป็นรายการ** (ตัวเรือน · พลอยแต่ละชนิด × จำนวน · รวม) · ห้ามคำนวณสูตรราคาใน client — ตัวเลขมาจาก server
10. ไม่มีจ่ายเงิน/ฟอร์มกรอกชื่อ-เบอร์ในเว็บ · หน้านี้ไม่ใช้กล้อง
11. มือถือก่อน (360px) · เป้าสัมผัส ≥ 44px · ปุ่มหลัก 1 อันต่อจอ · ตัวหนังสือสำคัญ ≥ 15px · contrast WCAG AA · รองรับ `prefers-reduced-motion`
12. **ทุกจอต้องออกแบบครบ 4 state** (โหลด · ผิดพลาด · ว่าง · สำเร็จ) รวมกรณีใน §2
13. ใช้แดงแบรนด์ `#a2191d` เดิม ห้าม re-palette · ภาพโมเดลให้สอดคล้องกับจอโมเดลที่เจ้าของเคยเห็น (`docs/3j-jewelry/cad/wave-embrace-preview.html`, `satin-flow-preview.html`: เวทีโค้งมนพื้นไล่เฉดกลาง · คำใบ้ลอยมุมเวที · ปุ่มแคปซูล · toggle หมุนอัตโนมัติ) — แต่ปรับขนาดตัวอักษร/ปุ่มให้ผ่านข้อ 11
14. ลิงก์หน้านี้ **แจกทาง LINE/เว็บร้านเท่านั้น** (ปุ่ม LINE/QR ในช่อง TikTok/Shopee = พาออกนอกแพลตฟอร์ม) — Q-TL
15. **ส่งมอบกลับมาให้ตรวจ:** ทุกจอ × 4 state · จอรูปสรุป (ขนาดจริงและหลังย่อ) · เคสพิเศษ §2 ทุกแถว · ข้อความทุกจอ (ข้อความที่เกี่ยวกฎ/สัญญาใช้ตาม §3)

## 6. สิ่งที่ขอ architect (ไม่ตัดสินแทน)

1. **รหัสสั่งทำ:** ชนิด (ก) stateless ลายเซ็น หรือ (ข) เก็บฝั่งเซิร์ฟเวอร์ id สั้น · ข้อกำหนดฝั่งผู้ใช้: พิมพ์/วางง่าย (ตัดอักษรกำกวม O/0 I/1 · จัดกลุ่ม · มี check digit) · ยาวพอวางในแชทได้ · มีเวอร์ชัน · ถ้า (ข) = endpoint สาธารณะเขียนข้อมูล → rate limit/กันสแปม/PDPA (ไม่มีข้อมูลส่วนบุคคลใน payload) และกระทบถ้อยคำความเป็นส่วนตัว
2. **ราคา ณ ตอนสร้าง vs ปัจจุบัน:** snapshot/versioning เพื่อเทียบได้หลังแก้ราคา/ปิดพลอย/แก้แบบ · พลอย-แบบที่ปิดแล้วต้องยังอ่านชื่อจากรหัสเก่าได้
3. **เงินคำนวณฝั่ง server/DB เท่านั้น** — ขอ endpoint คืน: พลอยที่ขายได้ต่อแบบ (ตามขนาดเม็ด) + ราคา · และคำตอบว่า client บวกยอดทันทีได้ไหม (บวกเลขที่ server ส่งมาแล้ว) หรือต้องเรียก server ทุกครั้ง · ทศนิยมราคาตามขนาด
4. **แบบแหวน:** โครงข้อมูล · ฟิลด์ที่ล็อกหลังมีรหัส · ทำสำเนา · นิยามตำแหน่ง 1..N ตรงกันทุกที่ (โมเดล `gem_1..gem_N` · แผนภาพ 2D · ข้อความ · รหัส) · ตรวจโมเดลตอนอัปโหลด
5. **ไฟล์โมเดล/รูป:** ที่เก็บ · ขนาดสูงสุด · การบีบอัด · **budget ความเร็วโหลดบน 4G/มือถือเก่า** · ไลบรารีแสดง · วิธี snapshot ภาพนิ่ง · พฤติกรรมใน LINE webview ที่ WebGL บางตัวถูกจำกัด
6. **แยกข้อมูลราคาขายออกจากต้นทุน** (`/oem/gems`) · endpoint สาธารณะคืนเฉพาะ field ที่แสดงได้ (ประกอบทีละ field ห้าม spread) · เปิด-ปิดมีผลทันที
7. **สิทธิ์/middleware:** endpoint สาธารณะ exempt แบบ exact path + เทสต์ must-NOT · role ชั้นเดียว บังคับที่ DB/แอป ไม่ใช่ซ่อนปุ่ม · security ตรวจ
8. **ตรวจรหัส:** แยกสถานะ §4.3 ได้จริง (รูปแบบผิด · check digit · ลายเซ็น/ไม่เคยออก · เวอร์ชันเก่า) · แยก "ตรวจล้ม" จาก "รหัสผิด"
9. **แตะ `/ring-size` (prod แล้ว):** ลิงก์กลับมาที่นี่ (พารามิเตอร์ตายตัว ปลายทาง hardcode ไม่ open redirect) หรือพึ่งปุ่ม Back · อ่านผลวัดล่าสุดแบบ read-only · ผลต่อสถิติ ring-size
10. **สถิติ/ความเป็นส่วนตัวของหน้านี้:** เก็บ event ไหม · ถ้าเก็บ ถ้อยคำต้องตรงจริง
11. **ชื่อ route** (เสนอ: สาธารณะ `/ring-builder` · หลังบ้าน `/ring-design` ไม่ซ้ำกัน) · เทสต์ "ไม่มีกล้อง" ครอบหน้าลูกค้า · สแกน QR อยู่ฝั่งแอดมินเท่านั้น
12. **ขีดจำกัด:** จำนวนพลอยสูงสุด · ราคาสูงสุดต่อเม็ด · จำนวนขนาดต่อพลอย (ตัดสินว่าตัวเลือกพลอยต้องมีค้นหา/จัดกลุ่มเมื่อไร)

## 8. ที่ตัดสินแล้วใน workflow นี้ (พร้อมเหตุผลสั้น)
- **แถบตำแหน่ง 2D เป็นทางหลักของการเลือก/สลับ** ไม่ใช่การแตะ/ลากบนโมเดล — เม็ดเล็กมากแตะไม่ได้จริง · บางเม็ดถูกบัง · ชนการหมุน · ใช้ได้แม้ไม่มี WebGL
- **ตรวจราคากับ server ก่อนออกรหัสทุกครั้ง** — กันพลอยปิด/ราคาเปลี่ยนก่อนส่ง · แลกกับการต้องมีเน็ตในขั้นสุดท้าย (ล้ม = มีทางทักแอดมินเอง)
- **ไซซ์แยกขั้นของตัวเอง** — มีที่ไป-กลับ `/ring-size` ชัด
- **รูปสรุปมีแผนภาพตำแหน่งเป็นข้อความเสมอ** — รอดการบีบของ LINE และไม่พึ่ง WebGL
- **ไม่ทำรอบนี้:** จ่ายเงินในเว็บ · บัญชี/บันทึกข้ามเครื่อง · ข้อมูลพลอยเกินชื่อ+สี · แกะสลัก/ข้อความ · พลอยต่างขนาดในแหวนวงเดียว · ประวัติการตรวจรหัส · ลบถาวร · dark mode
