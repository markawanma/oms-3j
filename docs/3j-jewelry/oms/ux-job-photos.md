## 0. สรุป + ข้อสังเกตต่อโจทย์ (ช่องเหลือที่เจอ)

**สรุป 5 บรรทัด**
1. **ออฟฟิศ:** การ์ด "รูปงาน" ใหม่บนหน้า `/jobs/[id]` (วางในช่องขวาที่ว่างอยู่ข้าง PlanCard) · มือถือ = ปุ่ม "ถ่ายรูป" + "เลือกจากเครื่อง" แยกกัน · PC = ปุ่มเดียว "เพิ่มรูป" · อัปโหลดทีละรูปทันที · แตะรูป = เปิดดูเต็มจอ + แถบจัดการ (ตั้งรูปหลัก · เลื่อน · ลบ)
2. **ตอนสร้างใบงาน:** ไม่ใส่ช่องรูปในฟอร์ม — สร้างเสร็จพาไปหน้าใบงาน (มีอยู่แล้ว) แล้วการ์ดรูปชวนถ่าย + เตือนเบาๆ ที่ปุ่มพิมพ์ถ้ายังไม่มีรูป (§3.5)
3. **ใบ A5:** รูปหลัก **30×30 มม.** ลอยขวาในคอลัมน์ข้อความหัวใบ (ติด QR) — **ไม่เพิ่มแถวใหม่** จึงไม่ดันตารางตกหน้า 2 · ใบไม่มีรูป = layout เดิมทุกประการ (§3.6)
4. **หน้าช่าง:** รูปหลัก 80×80 px มุมขวาบนข้างเลขใบงาน (ความสูงหัวหน้าเพิ่ม ~14 px) · แตะ = เต็มจอ ปัดซ้าย-ขวาดูทุกรูป (§3.7)
5. **Component เดียวใช้ซ้ำ** (หน้างาน W1 ในอนาคตใช้ตัวเดียวกัน) แต่ต้องแยกชั้น "แสดงผลล้วน" ออกจากชั้น "เรียก action" เพราะหน้าช่างห้าม import server action ของออฟฟิศ (§7)

**ช่องเหลือ / สิ่งที่ผมไม่ทำตามที่วาดไว้ตรงๆ**

| # | ข้อสังเกต | ผลต่อ spec |
|---|---|---|
| 1 | **A5 ที่วาดใน `Prints` ไม่ตรงกับใบจริงในโค้ด** — mock มีแถว "รูป 40×40 + ตารางข้อมูล 4 แถว" และตารางขั้นแค่ 5 แถว · ใบจริง (`JobSheet`) ไม่มีแถวนั้น มีหัว (ข้อความซ้าย + QR 42 มม. ขวา) → ตารางขั้น **7–11 แถว** → หมายเหตุ | วางรูปตามโครงใบจริง ไม่ลอกตำแหน่งจาก mock (§3.6) |
| 2 | **40×40 มม. เป็นแถวแยกใหม่ใส่ไม่ได้** — เพิ่มความสูง ~43 มม. · ใบ 9 ขั้นขึ้นไปล้นหน้า (ตารางตัวเลข §3.6) | ลดเป็น 30×30 แบบลอยในหัวใบ — **เจ้าของต้องยืนยัน (§11 Q1)** |
| 3 | **ใบจริงมีความเสี่ยงล้นหน้าอยู่แล้ว** ถ้าขั้นเยอะ + หัวยาว (แบบ + แผนโลหะ + ชื่อ 2 บรรทัด) — ไม่เกี่ยวกับรูป แต่รูปทำให้แย่ลงได้ 0–12 มม. | เสนอ "ตัววัดความสูงบนจอ + คำเตือน print:hidden" (§3.6 ข้อ 5) |

| 5 | **หน้าช่างห้าม import "use server" ใดๆ ยกเว้น `lib/actions/job-worker.ts`** (มี `worker-boundary.test.ts` ตรวจ module graph) | component รูปที่ใช้ร่วมต้อง pure — ห้ามเรียก action ในตัวมัน (§7) |
| 6 | **ใบงานที่พิมพ์ไปแล้ว เพิ่มรูปทีหลัง = กระดาษใบนั้นไม่มีรูป** (พิมพ์ใหม่ = QR ใบเก่าสแกนไม่ได้) | ข้อความบอกออฟฟิศในการ์ด + ช่างดูรูปผ่านมือถือได้ทันที ไม่ต้องพิมพ์ใหม่ (§3.1, §11 Q3) |
| 7 | **"แตะรูปค้าง = ตั้งรูปหลัก" (W-5) ค้นพบเองไม่ได้ + PC ไม่มี long-press + คีย์บอร์ดทำไม่ได้** | เก็บเป็นทางลัดได้ แต่ต้องมีปุ่มที่เห็นชัดเสมอ (อยู่ในแถบจัดการ §3.3) |
| 8 | **`<input capture>` ตรวจไม่ได้ว่าผู้ใช้ปฏิเสธกล้อง** — ที่ review เดิมเสนอ "กล้องไม่ได้ → ปุ่มเลือกจากเครื่องเด่นขึ้น" ทำไม่ได้โดยไม่ทำกล้องเอง (over-design) | ให้ทั้งสองปุ่มเท่ากันเสมอ · ไม่ตรวจ |

## 1. คำถามเจ้าของ: "รูปใส่ตรงไหน · ให้คนเปิดบิลถ่ายตอนไหน"

| สถานการณ์ | ใครถ่าย | **ตอนไหน** | ที่ไหน | กลไกที่ช่วย (ไม่ใช่ด่านบังคับ — มติ จ5 "รูปไม่ใช่ด่าน") |
|---|---|---|---|---|
| ใบที่ออฟฟิศสร้างจากใบผลิต/ใบเสนอราคา (วันนี้) | ออฟฟิศ | **หลังกด "สร้างใบงาน" ก่อนกด "พิมพ์ใบงาน"** | การ์ด "รูปงาน" หน้า `/jobs/[id]` (ระบบพาไปหน้านี้อยู่แล้วหลังสร้าง) | SKU มีรูปแคตตาล็อก = ใส่เป็นรูปหลักให้เองแล้ว (ซ4) ไม่ต้องถ่าย · ไม่มีรูป = ข้อความเตือนที่ปุ่มพิมพ์ |
| ใบที่หน้างานเปิดเอง (W1 — ยังไม่ทำ) | ผู้เปิดงาน | **ตอนเปิดใบ** (จอ W-5) | component เดียวกัน | อัปโหลดทีละรูป เปิดงานได้แม้ส่งไม่ครบ (แต่ต้องยืนยัน ไม่ให้หายเงียบ) |
| ใบที่เดินอยู่แล้วและยังไม่มีรูป (ซ1) | ออฟฟิศ | **เมื่อนึกได้ / ช่างถามว่าชิ้นไหน** | การ์ดเดียวกัน | ช่างเห็นรูปผ่านมือถือทันที ไม่ต้องพิมพ์ใบใหม่ |

คำตอบสั้น: **"รูปอยู่ในการ์ดรูปงานบนหน้าใบงาน — ถ่ายก่อนพิมพ์"** · ถ้าลืมก็เติมทีหลังได้ตลอดจนปิดใบ

## 2. User flow

### F1 ออฟฟิศ: เพิ่มรูปบนหน้าใบงาน (มือถือ/PC)
```
/jobs/[id] ──► การ์ด "รูปงาน" (#job-photos)
  │
  ├─ ว่าง ──► ข้อความ + ปุ่มเพิ่มรูป
  │             ├─ [ถ่ายรูป] ► กล้องหลัง ► ถ่าย ► กลับหน้าเดิม ► ช่องรูปใหม่ "กำลังย่อรูป" ► "กำลังส่ง" ► ขึ้นรูป (รูปแรก = รูปหลัก อัตโนมัติ)
  │             └─ [เลือกจากเครื่อง] ► เลือกได้หลายรูป ► แต่ละรูปเข้าคิวส่งทีละ 2
  │
  ├─ ส่งไม่สำเร็จ ──► ช่องแดง "ส่งไม่สำเร็จ · แตะลองใหม่"
  │             ├─ แตะ = ส่งใหม่ (ข้อผิดพลาดที่ลองใหม่ไม่ช่วย เช่น HEIC/ครบ 5/ใบปิด → ไม่มีปุ่มลองใหม่ มีแต่ "เอาออก")
  │             └─ [×] เอาออก (ยังไม่ถึง server จึงไม่ต้องยืนยัน)
  │
  ├─ มีรูปแล้ว ► แตะรูป ► ดูเต็มจอ (viewer) ► แถบจัดการ:
  │             ├─ ★ ตั้งเป็นรูปหลัก (ย้ายมาเป็นรูปแรก)
  │             ├─ ‹ เลื่อนก่อน / เลื่อนหลัง ›
  │             └─ ลบรูปนี้ ► กล่องยืนยัน ► ลบ (บันทึกว่าใครลบ — มติ จ5)
  │
  ├─ ครบ 5 ► ปุ่มเพิ่มหาย แทนด้วยข้อความ "ครบ 5 รูปแล้ว — ลบรูปก่อนถ้าจะเพิ่ม"
  ├─ ไม่มีเน็ต ► แถบเหลืองด้านบนการ์ด · ส่งไม่ได้ · ช่องที่ถ่ายไว้ค้างแดง (อยู่ในหน้านี้เท่านั้น ปิดหน้า = หาย)
  └─ ใบปิดแล้ว (done/cancelled) ► การ์ดอ่านอย่างเดียว (ดู/ขยายได้ · ไม่มีปุ่มเพิ่ม/จัดการ)
```

### F2 ออฟฟิศ: สร้างใบงาน → ใส่รูป → พิมพ์
`JobCreateDialog` (ไม่เปลี่ยนช่องกรอก) → "สร้างใบงาน" → toast → **`router.push('/jobs/<id>#job-photos')`** (เพิ่ม hash เดียว) → เห็นการ์ดรูป · SKU มีรูปแคตตาล็อก = การ์ดมีรูปหลักแล้ว (ป้าย "จากแคตตาล็อก") → ถ่ายเพิ่ม/เปลี่ยนได้ → กด "พิมพ์ใบงาน (QR)" → หน้า print เห็นสถานะรูปบนใบ (§3.6)

### F3 ออฟฟิศ: ก่อนพิมพ์
หน้าใบงาน: ถ้า **ไม่มีรูป** ใต้บรรทัด "QR ที่ใช้งานอยู่ n ใบ" ขึ้นข้อความ "ใบนี้ยังไม่มีรูป — ใบพิมพ์จะไม่มีรูปหลัก · เพิ่มรูป" (ลิงก์ไป `#job-photos` · ไม่บล็อกการพิมพ์) → หน้า `/jobs/[id]/print` แสดงสถานะรูป (มี/ไม่มี/โหลดไม่ได้) → พิมพ์

### F4 ช่าง: สแกน QR → ดูรูป
`/w/[token]` → (ระบุตัว/PIN ตามเดิม) → จอแรกเห็นรูปหลักข้างเลขใบงาน → แตะ → เต็มจอ → ปัดดูทุกรูป → ปิด (กลับจุดเดิม ไม่โหลดหน้าใหม่) · ไม่มีรูป = ไม่มีอะไรเพิ่ม

## 3. Screen / layout spec

ใช้ token ของ repo (Tailwind: `zinc-*` · `primary-600/700` = `#a2191d` · `red-*` danger · `amber-*` warn · การ์ด `rounded-lg border border-zinc-200 bg-white p-4` · หัวการ์ด `text-lg font-bold`) — **ไม่ใส่ hex ใหม่** · hex ใน handoff (`#B42318` ฯลฯ) ให้แมปเป็น `red-700` / `amber-900` ฯลฯ ตามที่ repo ใช้อยู่

### 3.1 การ์ด "รูปงาน" (ออฟฟิศ) — `JobPhotosCard`

**ตำแหน่งบนหน้า `JobDetailClient`:** ใส่ในกริด `lg:grid-cols-2` ที่มี `PlanCard` อยู่ (comment ในโค้ดเว้นครึ่งขวาไว้ให้การ์ดถัดไป) · `id="job-photos"` · มือถือใส่ `max-lg:order-first` ให้ขึ้นเหนือ PlanCard (หลังแถบปุ่ม) — เหตุผล: รูปเป็นสิ่งที่ต้องทำ **ก่อน** พิมพ์ ไม่ควรอยู่ใต้การ์ดแผนโลหะ

**ลำดับความสำคัญในการ์ด:** (1) รูป (2) ปุ่มเพิ่ม (secondary — หน้านี้มี primary เดียวคือ "พิมพ์ใบงาน (QR)") (3) ตัวนับ "n/5" (4) ข้อความช่วย

มือถือ 390 (การ์ดกว้าง ≈ 326 px · ช่อง 2 คอลัมน์ ≈ 158 px):
```
┌─────────────────────────────────────┐
│ รูปงาน                         3/5 │  h2 + ตัวนับ (text-sm tabular-nums)
│ ช่างเห็นรูปนี้บนมือถือ · รูปแรก     │  text-sm zinc-700
│ พิมพ์บนใบ A5                        │
│ ┌──────────────┐ ┌────────────────┐ │
│ │ 📷  ถ่ายรูป   │ │ 🖼 เลือกจากเครื่อง│ │  2 ปุ่ม min-h-14 (56px) · outline zinc-900
│ └──────────────┘ └────────────────┘ │
│ ┌────────────┐ ┌────────────┐       │
│ │★ รูปหลัก   │ │            │       │  ช่องรูป aspect-square
│ │ จากแคตตาล็อก│ │            │       │
│ └────────────┘ └────────────┘       │

PC (การ์ดครึ่งขวา ≈ 500 px · 3 คอลัมน์ ≈ 160 px):
```
┌─────────────────────────────────────────────┐
│ รูปงาน  3/5                    [ + เพิ่มรูป ] │  ปุ่ม secondary min-h-11 (เลือกไฟล์ได้หลายรูป)
│ ┌────────┐ ┌────────┐ ┌────────┐            │
│ │★ รูปหลัก│ │        │ │        │            │
│ └────────┘ └────────┘ └────────┘            │

```
- **ปุ่มเพิ่มอยู่เหนือตารางรูปเสมอ** (ตำแหน่งนิ่ง ไม่วิ่งหนีเมื่อรูปเพิ่ม) · รูปเรียง: รูปหลักก่อน แล้วตามลำดับ
- ปุ่มสองใบแสดงเมื่อ `@media (pointer: coarse)` (มือถือ/แท็บเล็ตสัมผัส) · อุปกรณ์เมาส์ = ปุ่มเดียว (ไม่เสนอ "ถ่ายรูป" บน PC เพราะ `capture` ไม่มีผล) · ใช้ CSS ล้วน ไม่ตรวจใน JS (กัน hydration mismatch)
- "ถ่ายรูป" = `<input type="file" accept="image/*" capture="environment">` (ครั้งละ 1 รูป) · "เลือกจากเครื่อง" = `accept="image/*" multiple` · ทั้งคู่ `disabled` เมื่อครบ 5
- เลือกเกินที่เหลือ: รับเท่าที่ใส่ได้ + แถบเหลือง "เลือกมา 7 รูป ใส่ได้อีก 3 รูป — ตัด 4 รูปท้ายออก"
- ข้อความช่วยตามบริบท (แสดงทีละบรรทัด ไม่เกิน 1 ข้อต่อครั้ง ลำดับความสำคัญบน→ล่าง):
  1. ไม่มีเน็ต → แถบเหลือง (ดู §5)
  2. `activeTokens > 0` และมีรูป → "ใบกระดาษที่พิมพ์ไปแล้วไม่มีรูปหลัก — ช่างดูรูปจากมือถือ (สแกน QR) ได้ทันที · ถ้าต้องการให้กระดาษมีรูปต้องพิมพ์ใหม่ (QR ใบเก่าจะใช้ไม่ได้)" (`text-sm text-zinc-700`)
  3. ใบ OEM → "รูปนี้ช่างทุกขั้นเห็นผ่าน QR และพิมพ์บนใบงาน" (ให้ออฟฟิศรู้ว่ารูปแบบลูกค้าจะไปถึงไหน — สอดคล้อง §4.4)
- ใบปิดแล้ว: ซ่อนปุ่มเพิ่ม · ช่องรูปกดดู/ขยายได้ · แถบจัดการไม่ขึ้น · ข้อความ "ใบงานปิดแล้ว — แก้รูปไม่ได้"

### 3.2 ช่องรูป (tile) — 7 สถานะ

ช่อง = `<button>` สี่เหลี่ยมจัตุรัส · `object-cover` (ตัดขอบให้เต็มช่อง เฉพาะภาพย่อ) · มุม `rounded-lg` · แท็กเล็กขั้นต่ำ **12 px** `font-bold` (mock ใช้ 11 px — ปรับขึ้นเพื่ออ่านออก) · ห้ามใช้สีอย่างเดียวบอกสถานะ (ต้องมีไอคอน+ข้อความ)

| สถานะ | หน้าตา | แตะแล้ว | a11y label |
|---|---|---|---|
| **รูปปกติ** | รูป `sm` · ไม่มีแท็ก | เปิด viewer ที่รูปนี้ | "รูปที่ 2 จาก 4 · แตะเพื่อดู" |
| **รูปหลัก** | วงแหวนดำ 3 px (`ring-[3px] ring-zinc-900`) + แท็กขาว "★ รูปหลัก" มุมซ้ายบน | เหมือนปกติ | "รูปที่ 1 จาก 4 · รูปหลัก · แตะเพื่อดู" |
| **จากแคตตาล็อก** | แท็กขาว "จากแคตตาล็อก" มุมซ้ายล่าง (ซ้อนกับรูปหลักได้) | เหมือนปกติ | ต่อท้าย "· จากแคตตาล็อก" |
| **กำลังย่อรูป** | พื้น `zinc-200` + spinner + "กำลังย่อรูป…" | ไม่ตอบสนอง (disabled) | `aria-busy` |
| **กำลังส่ง** | ตัวอย่างรูปที่ย่อแล้ว (จางลง) + แถบความคืบหน้า + "กำลังส่ง" (มี % **เฉพาะ**ถ้า transport วัดได้ — ไม่งั้นแถบวิ่ง indeterminate) | ไม่ตอบสนอง | "กำลังส่งรูป" |
| **ส่งไม่สำเร็จ (ลองใหม่ได้)** | กรอบ `border-2 border-red-700` พื้น `red-50` + ไอคอน ⚠ + "ส่งไม่สำเร็จ · แตะลองใหม่" + เหตุผลสั้นบรรทัดล่าง (เช่น "ไม่มีเน็ต") + ปุ่ม [×] มุมขวาบน 44×44 | **แตะช่อง = ส่งใหม่** · [×] = เอาออก | "ส่งรูปไม่สำเร็จ แตะเพื่อลองใหม่" / "เอารูปนี้ออก" |
| **ส่งไม่สำเร็จ (ลองใหม่ไม่ช่วย)** | เหมือนข้างบนแต่ไม่มี "แตะลองใหม่" — แสดงเหตุผล + ปุ่ม "เอาออก" ข้อความชัด (HEIC · ไฟล์ใหญ่ · ใบมีรูปครบ · ใบปิดแล้ว) | [เอาออก] เท่านั้น | — |

ตัวนับ "n/5" นับ: รูปที่อยู่ในใบ + รูปที่กำลังย่อ/ส่ง (ไม่นับที่ล้มเหลว) — ตามพฤติกรรมเดียวกับแคตตาล็อก

ข้อความสรุปสถานะให้ screen reader: `aria-live="polite"` บรรทัดซ่อน "กำลังส่งรูป 2 จาก 3" / "ส่งไม่สำเร็จ 1 รูป" (อัปเดตเมื่อเปลี่ยน ไม่อ่านทุก %)

```

│                            │
│  ★ รูปหลัก                 │  แท็กใต้รูป (ถ้าเป็นรูปแรก)

- รูปในช่องเลื่อนเป็น **`sm` ก่อน** (มีอยู่แล้วในหน้า ไม่กระพริบ) แล้วสลับเป็น `md` (1200 px) เมื่อโหลดเสร็จ · `md` โหลดพลาด = คงรูป `sm` + toast "โหลดภาพละเอียดไม่ได้"
- ขยายด้วยการถ่างนิ้วของเบราว์เซอร์ (`touch-action: pan-x pinch-zoom`) — **ไม่เขียน zoom เอง** (ตัดโค้ด · `md` 1200 px พอดูรายละเอียดพลอย 2–3 เท่า)
- คีย์บอร์ด: `←/→` เปลี่ยนรูป · `Esc` ปิด · `Tab` วนในแผง (focus trap — `Modal` เดิมไม่มี trap เต็ม จึงเขียนในตัว viewer) · เปิดแล้ว focus ที่ปุ่มปิด · ปิดแล้วคืน focus ที่ช่องที่กด · ล็อกการเลื่อนหน้าหลัง · `role="dialog" aria-modal="true" aria-label="รูปงาน JB-0034"`
- `alt` = "รูปงาน JB-0034 รูปที่ 2 จาก 4" (**ห้ามใส่ชื่อลูกค้า/ชื่อไฟล์**) · `referrerPolicy="no-referrer"` · ไม่มีปุ่มดาวน์โหลด/ลิงก์ไป URL
- โหมดช่าง (ไม่มี `actions`): แถบล่างไม่มี · ไม่แสดงแท็ก "จากแคตตาล็อก" (ไม่มีความหมายกับช่าง)
- ไม่มีแอนิเมชันเปลี่ยนรูป (ตัดปัญหา reduced-motion) · ถ้าจะใส่ = `motion-safe:` เท่านั้น

### 3.4 ลบรูป (ยืนยัน) — ใช้ `Modal` เดิม (bottom sheet บนมือถือ)

หัว "ลบรูปนี้ออกจากใบงาน {JB-xxxx}?" · ปุ่ม **[ยกเลิก]** (`variant="secondary"` · focus เริ่มที่นี่) / **[ลบรูป]** (`Button variant="danger"`) · จัดวางเหมือน `JobCreateDialog` ทุกประการ (`flex flex-col-reverse gap-2 sm:flex-row sm:justify-end` — มือถือ: ลบอยู่บน ยกเลิกอยู่ล่าง · PC: ยกเลิกซ้าย ลบขวา) เพื่อให้ทุกกล่องในแอปกดเหมือนกัน · ปุ่ม ≥ 44 px
เนื้อความเปลี่ยนตามกรณี (เลือกบรรทัดเดียวที่เกี่ยวที่สุด):
- รูปหลักและยังมีรูปอื่น → "นี่คือรูปหลัก ลบแล้วรูปถัดไปจะเป็นรูปหลักแทน"
- รูปสุดท้าย → "ลบแล้วใบงานนี้จะไม่มีรูป ใบ A5 ที่พิมพ์ครั้งต่อไปจะไม่มีรูปหลัก"
- รูปจากแคตตาล็อก → "ลบจากใบงานนี้เท่านั้น — รูปในแคตตาล็อกไม่หาย"
- ทุกกรณีต่อท้าย: "กู้คืนไม่ได้ · ระบบจะบันทึกว่าใครลบ" (มติ จ5)
ผลสำเร็จ: ปิดกล่อง + viewer เลื่อนไปรูปถัดไป (หมดรูป = ปิด viewer) + toast "ลบรูปแล้ว" · ล้มเหลว: ข้อความในกล่อง (`ErrorLine`) คงกล่องไว้ให้กดซ้ำ

### 3.5 ตอนสร้างใบงาน (`JobCreateDialog`) — คำตอบ: **ไม่ใส่ช่องรูปในฟอร์ม**

| เหตุผล | รายละเอียด |
|---|---|
| ใบยังไม่มีอยู่จริง | รูปต้องผูกกับ job id — ถ้าอัปโหลดก่อนสร้างต้องมี "ที่พักรูป" (draft) = งาน architect เพิ่ม + ต้องกวาดรูปค้างเมื่อยกเลิกกล่อง (T7 ใน ux-review) |
| ฟอร์มยาวพอแล้ว | จำนวน · เผื่อเสีย · แผนโลหะ · ขั้น · แบบบันทึก · ชื่อ · กำหนดส่ง · มัดจำ — บน modal มือถือเลื่อนยาวอยู่แล้ว · ปุ่ม file input กลางฟอร์มเพิ่ม cognitive load |
| ส่วนใหญ่ไม่ต้องถ่าย | SKU มีรูปแคตตาล็อก = เป็นรูปหลักให้อัตโนมัติ (ซ4) |
| หน้าถัดไปอยู่ห่าง 1 จังหวะ | `router.push` ไปหน้าใบงานอยู่แล้ว — แค่เติม `#job-photos` |

สิ่งที่ทำจริง (เล็ก):
1. `router.push` ไป `/jobs/<id>#job-photos` แทน `/jobs/<id>` (เติม hash ต่อท้ายเท่านั้น)
2. **(P2 ตัดได้)** แถวอ่านอย่างเดียวในฟอร์ม ใต้ "ชื่อเรียกภายใน": ภาพย่อ 48 px + "จะใช้รูปจากแคตตาล็อกเป็นรูปหลัก — เพิ่ม/เปลี่ยนได้ที่หน้าใบงานหลังสร้าง" หรือถ้าไม่มี "ยังไม่มีรูป — ถ่ายได้ที่หน้าใบงานหลังสร้าง" · ต้องให้ `suggestJob` ส่ง `catalogImageUrl` เพิ่ม → ถ้า backend ไม่สะดวก **ตัดทั้งข้อ 2 ไม่กระทบเรื่องอื่น**
- ไม่มีการเตือน/บล็อกเมื่อไม่มีรูป (รูปไม่ใช่ด่าน)

### 3.6 ใบ A5 `JobSheet` + ใบย่อย

**ทำไมไม่ใช่ 40×40 แถวแยก — งบความสูง (ประมาณจากโค้ด ไม่ได้วัดจริง)**
พื้นที่พิมพ์ = 210 − 2×8 (margin ใน `@page`) = **194 มม.** ความสูงที่ใช้ = หัว + ตาราง + หมายเหตุ

| ส่วน | ประมาณ | ที่มา |
|---|---|---|
| หัวใบ (ข้อความซ้าย / QR ขวา) | **47 มม. (เล็กสุด) – 74 มม. (ยาวสุด)** | QR 42 + ป้าย ≈ 46 · ข้อความ: ชื่อใบ 4 + เลข 30pt 11 + ชื่อ 14pt 7–14 + จำนวน 5–10 + กำหนด 6 + แผนโลหะ 0/11 + แบบ 0/4 + 2 บรรทัดเขียนมือ 11 |
| ตาราง | 3 + 6 (หัว) + **9 × N** | `h-[9mm]` ต่อแถว |
| หมายเหตุ+ท้ายตาราง | ≈ 23 | `h-[16mm]` + หมายเหตุ `*` |

เหลือที่ว่าง (มม.) = 194 − หัว − 32 − 9N:

| ขั้น N | ก่อนมีรูป (หัวสั้น / หัวยาว) | **ลอย 30 มม. ในหัว** (หัว +0…12) | แถวแยก 40×40 (+43) |
|---|---|---|---|
| 7 | 52 / 25 | 40–52 / 13 | 9 / −18 |
| 9 | 34 / 7 | 22–34 / −5 | −9 / −36 |
| 11 | 16 / **−11 (ล้นอยู่แล้ว)** | 4–16 / −23 | −27 / −54 |

ข้อสรุป: แถวแยก 40×40 ใช้ได้เฉพาะ ≤ 7 ขั้นหัวสั้น · **ลอยในหัวใบ 30 มม. พอดีทุกจำนวนขั้นเมื่อหัวไม่ยาวสุด** · เคสหัวยาวสุด + ≥ 9 ขั้น ล้นอยู่แล้วก่อนมีรูป (ดูข้อ 5)

**วิธีวาง (ข้อ 1–5 บังคับ)**
```
ไม่มีรูป (เหมือนเดิมทุกประการ)          มีรูป
┌──────────────────────────────┐      ┌──────────────────────────────┐
│ ใบงานผลิต · …       ┌──────┐ │      │ ใบงานผลิต · …  ┌─────┐┌──────┐│
│ JB-0034             │  QR  │ │      │ JB-0034        │ รูป ││  QR  ││
│ ต่างหู…             │ 42mm │ │      │ ต่างหู…        │30×30││ 42mm ││
│ 53 ชิ้น · เงิน       └──────┘ │      │ 53 ชิ้น…       └─────┘└──────┘│
│ กำหนดส่ง …                   │      │ กำหนดส่ง … (บรรทัดใต้รูป        │
│ น้ำหนักตั้งต้น ......        │      │  กลับเป็นเต็มความกว้างเอง)     │
├──────────────────────────────┤      ├──────────────────────────────┤
│ ตารางขั้น 7–11 แถว (เดิม)     │      │ ตารางขั้น (เดิม ไม่ย่อแถว)     │
│ หมายเหตุ                      │      │ หมายเหตุ                      │
```
1. **รูปหลัก 1 รูป ขนาด 30×30 มม. ลอยขวา (`float-right`) ในคอลัมน์ข้อความซ้ายของหัวใบ** ติด QR · ใส่เป็นลูกแรกของ `div.min-w-0` เพื่อให้ข้อความไหลอ้อม · มาร์จิ้น `ml-[3mm]` `mr-[1mm]` (ห่าง QR ≥ 4 มม. กันสแกนสับสน) · ขอบ `border border-zinc-700` พื้นขาว · `<img>` เป็น `object-contain` (**ห้ามตัดขอบ** — ช่างต้องเห็นชิ้นงานครบ) · ใช้ตัวแปร `sm` (480 px ≈ 400 dpi ที่ 30 มม. เกินพอ)
2. **ไม่เพิ่มแถว/ไม่ย่อแถวตาราง/ไม่แตะ QR** · ใบไม่มีรูป = ไม่มีองค์ประกอบใหม่เลย (ไม่เว้นที่ว่าง)
3. **ป้าย "+n รูป · สแกนดู"** (8pt ใต้รูป ภายใน float) เฉพาะเมื่อมีรูปมากกว่า 1 — รูปเดียวไม่มีป้าย
4. **กันพิมพ์กรอบว่าง** (บน `JobPrintClient` — ส่วนหน้าจอ `print:hidden`):
   - บรรทัดสถานะรูปในกล่อง "ออก QR และพิมพ์": ภาพย่อ 48 px + "รูปหลัก: มี — พิมพ์ 30×30 มม." / "ไม่มีรูป — ใบจะไม่มีรูปหลัก · [เพิ่มรูปก่อนพิมพ์]" (ลิงก์ ไม่บล็อก)
   - ปุ่ม "ออก QR และพิมพ์" **ปิดจนรูปโหลดเสร็จ** (`onLoad`) พร้อมข้อความบนปุ่ม "กำลังโหลดรูป…" · รอสูงสุด 8 วินาทีแล้วถือว่าล้มเหลว
   - รูปโหลดไม่ได้ (`onError`/หมดเวลา — ลิงก์อายุ 1 ชม. หรือไม่มีเน็ต): แถบเหลือง `role="alert"` "โหลดรูปหลักไม่ได้ — ใบจะพิมพ์โดยไม่มีรูป · [โหลดหน้าใหม่]" · **ใบพิมพ์ตกกลับเป็น layout ไม่มีรูป** (ถอด float ออก — ไม่พิมพ์ไอคอนรูปแตก) · ยังพิมพ์ได้
5. **ตัววัดความสูง (P1 แนะนำ)**: วัด `article` เทียบกล่องวัดซ่อน `h-[194mm]` (ไม่แปลง mm→px เอง) · เกิน → (ก) ถ้ามีรูป: ถอดรูปออกจากใบ + แถบ `print:hidden` "ขั้นเยอะ/หัวยาว ที่ไม่พอสำหรับรูป — ใบนี้พิมพ์โดยไม่มีรูป ช่างดูรูปผ่าน QR" (ข) ถ้ายังเกินแม้ไม่มีรูป: แถบ "ใบนี้ยาวเกิน 1 หน้า A5 — ลดขั้น/ย่อชื่อเรียกก่อนพิมพ์" · jsdom วัด layout ไม่ได้ → ทดสอบด้วยมือ (3 เคส: 7 ขั้นหัวสั้น · 11 ขั้นหัวสั้น · 11 ขั้นหัวยาว) บน preview หน้ากระดาษจริง
6. ⚠️ **ขนาดจริงบนกระดาษอาจเล็กกว่า 30 มม.**: `JobSheet` กว้าง `148mm` แต่พื้นที่พิมพ์ A5 หลังหัก margin = 132 มม. — ถ้า Chrome ย่อทั้งหน้าให้พอดี (≈ 89%) รูปจะเหลือ ≈ 27 มม. · frontend-dev ต้องพิมพ์ทดสอบแล้ววัดด้วยไม้บรรทัด · ผมไม่ได้ยืนยันว่า Chrome ย่อหรือตัด (เจ้าของพิมพ์ได้อยู่แล้ว จึงไม่ถือเป็นบั๊กที่ยืนยัน)
7. **ข้อมูลที่เพิ่มใน `PrintableJob`** (ด่าน type boundary ของ `lib/jobs/print.ts` — ประกอบทีละ field): `primaryPhotoUrl: string | null` (signed URL อายุสั้น ไม่ใช่ path) · `photoCount: number` · ต้องแก้เทสต์ที่ล็อกรายชื่อ key (`JobPrint0176.test.tsx` บรรทัดตรวจ `Object.keys(p)`) · ห้ามมีชื่อผู้อัปโหลด/ชื่อไฟล์/EXIF
8. ขาวดำ: เครื่องพิมพ์ขาวดำทำรูปเป็นเทา — พอสำหรับ "ดูทรง" (ไม่ใช่ดูสี) · ป้ายสีของงานต้องไม่พึ่งสีจากรูป · ข้อมูลสี/ตำแหน่งพลอยอยู่ในตารางพลอย/ข้อความ ไม่พึ่งรูปบนกระดาษ

**ใบย่อย L1** (`JB-xxxx · ส่วนที่ n`): ยังไม่มีในโค้ด · ใช้ `PrintPhoto` ตัวเดียวกัน ตามที่ `Prints` วาด (ใต้กล่อง "ในถุงนี้" แถวเดียวกับข้อความ QR · ≈ 29–30 มม.) · กฎกรอบว่าง/ตกกลับเหมือนข้างบน · ใบส่งของผู้รับจ้าง (รูป 64 px ในตาราง) นอกขอบเขตรอบนี้ — ใช้ `PrintPhoto size` เล็กได้ภายหลัง

### 3.7 หน้าช่าง `/w/[token]` (มือถือ 390 · ปุ่ม ≥ 56 px)

**ตำแหน่ง:** หัวใบงานเดิม (`ใบงาน` / `JB-0034` / ชื่อ / จำนวน·โลหะ·SKU·กำหนดส่ง) — เปลี่ยนเฉพาะ 2 บรรทัดแรกเป็นแถว flex: ซ้าย "ใบงาน"+เลขใบ · **ขวา = ภาพย่อ 80×80 px**; ชื่อ/จำนวน อยู่ใต้แถวนั้นเต็มความกว้างเหมือนเดิม
```
┌────────────────────────────────┐ 390 (px-4)
│ ใบงาน                  ┌──────┐ │
│ JB-0034                │ รูป  │ │  80×80 · rounded-xl · border-2 zinc-300
│                        │ 80px │ │  ชิป "4 รูป" มุมขวาล่าง (ขาวบนดำ 16px bold) เมื่อ > 1 รูป
│ ต่างหูลายใบไม้…        └──────┘ │
│ 53 ชิ้น · เงิน · EAR-012 · ส่ง… │  ← full width ไม่ถูกรูปบีบ
│ ──────────────────────────────│
│ ขั้นถัดไป: ฝังพลอย              │  ปุ่มหลัก sticky เหมือนเดิม
```
- **ทำไมมุมขวาบน ไม่ใช่แถบแยก:** แถบรูปใหม่ ≥ 96 px ดันปุ่มหลัก · แบบนี้หัวสูงขึ้นแค่ ≈ 14 px (80 − แถวเดิม ~66) · จอ 390×740: ปุ่มรับ/ส่งต่อเดิมอยู่ราว y ≈ 420–500 (ประมาณจากโค้ด `WorkerApp`/`ReceivePanel` ยังไม่ได้วัดบนเครื่อง) → หลังเพิ่มยังอยู่ในจอ · ปุ่มเป็น `sticky bottom` อยู่แล้ว **แต่ sticky ติดได้เฉพาะเมื่อ section ของมันยังอยู่ในจอ** จึงห้ามเพิ่มบล็อกสูงๆ เหนือแผง
- **แตะภาพย่อ = เปิด `JobPhotoViewer` เต็มจอ** (§3.3 โหมดไม่มี actions) · ปัดซ้าย-ขวา · ตัวนับ "2 / 4" · ปิด 56 px กลับจอเดิม ไม่ reload · ไม่มีรูป = **ไม่ render อะไร** (ไม่มีกรอบเปล่า — ช่างทำอะไรกับมันไม่ได้)
- หน้าไม่หนัก: ข้อความ/ปุ่มขึ้นก่อน · ภาพย่อ `sm` `loading="lazy" decoding="async"` ในกล่องขนาดคงที่ (ไม่ขยับ layout) · `md` โหลดเมื่อเปิด viewer เท่านั้น (ตรง §4.3 "รูปโหลดเมื่อแตะ")
- **ไม่มี**: ตัวเลขเงิน · ชื่อลูกค้า · ชื่อผู้อัปโหลด · ป้าย "จากแคตตาล็อก" · ปุ่มอัปโหลด (รอบนี้ช่างดูอย่างเดียว) · ลิงก์ไปหน้าอื่น (กติกาเดิมของหน้า)

## 8. Design decision + trade-off

| # | ตัดสินใจ | ทำไม ไม่ใช่แบบอื่น | แลกกับอะไร |
|---|---|---|---|
| D1 | **รูปหลัก = รูปแรก** ("ตั้งเป็นรูปหลัก" = ย้ายมาเป็นรูปแรก) | แนวคิดเดียว ไม่มีสถานะ "ไม่มีรูปหลัก" · ตรงกับแคตตาล็อกที่ทีมใช้อยู่ ("รูปแรก = รูปหลัก") · ไม่ต้องอธิบายว่าลำดับกับรูปหลักต่างกันยังไง | ถ้า architect เก็บเป็น flag แยก UI เหมือนเดิม ต้องรับประกันว่า "มีรูป ≥ 1 ⇒ มีรูปหลักพอดี 1" |
| D2 | **แตะรูป = viewer เต็มจอที่มีแถบจัดการ** (แทน bottom sheet 3 ปุ่มที่ review เดิมเสนอ + แตะค้าง) | ผู้ใช้อยากดูรูปให้ชัดก่อนตัดสินว่าจะลบ/ตั้งหลัก → รวมสองงานไว้ที่เดียว · ลด pattern ที่ต้องเขียน (sheet + viewer → viewer เดียว) | จัดการต้องแตะ 2 ครั้ง (แตะรูป → ปุ่ม) แต่การลบ/ตั้งหลักเป็นงานไม่บ่อย |
| D3 | **ปุ่มเพิ่มอยู่เหนือตารางรูป** | ปุ่มไม่วิ่งเมื่อรูปเพิ่ม · ตรง W-5 ของเจ้าของ | ตารางรูปอยู่ต่ำลง ~60 px บนมือถือ |
| D4 | **ถ่าย/เลือก แยกปุ่มเฉพาะอุปกรณ์สัมผัส** | PC ไม่มีกล้องที่ใช้ได้จริง · ปุ่มที่ไม่ทำงานตามชื่อ = สับสน | ใช้ `pointer: coarse` — แล็ปท็อปจอสัมผัสที่มีเมาส์อาจได้ปุ่มเดียว (ยังเลือกไฟล์ได้) |
| D5 | **ไม่ตรวจกล้องถูกปฏิเสธ** | ต้องเขียนกล้องเอง (`getUserMedia`) = over-design | ไม่มีปุ่มเน้นพิเศษ — ทั้งสองปุ่มเท่ากันอยู่แล้ว |
| D6 | **ไม่ใส่รูปในฟอร์มสร้างใบงาน** | ดู §3.5 | ต้องไปหน้าถัดไปอีกหน้า (อยู่ห่าง 1 จังหวะ) |
| D7 | **A5: รูป 30×30 ลอยในหัวใบ ไม่ใช่แถวแยก 40×40** | ไม่ดันตาราง (§3.6) · ใบย่อยที่เจ้าของวาดไว้ก็ ~29 มม. อยู่แล้ว | เล็กกว่าที่วาดสำหรับใบ A5 · เจ้าของต้องยืนยัน Q1 |
| D8 | **หน้าช่าง: ภาพย่อมุมขวาบน ไม่ใช่แถบรูป** | ไม่ดันปุ่มหลัก · ผูกภาพกับเลขใบงานตามสายตา | ภาพเล็ก (80 px) · ช่างต้องแตะดูรูปอื่น — ชิป "n รูป" บอกว่ายังมี |
| D9 | **ไม่ทำ zoom เอง · ไม่ทำ drag-drop เรียง** | ใช้ pinch ของเบราว์เซอร์ + `md` 1200 px · เรียงด้วยปุ่ม ‹ › (แคตตาล็อกก็แบบนี้ — ไม่มีไลบรารี dnd ใน repo และมือถือ 360 px ลากพลาดง่าย) | ปัดนิ้วเรียงไม่ได้ |
| D10 | **ใบปิดแล้ว = รูปอ่านอย่างเดียว** | รูปคือหลักฐานของงานที่ปิด · ต้องไม่เปลี่ยนหลังปิด | ถ้าลืมถ่ายก่อนปิด เติมไม่ได้ (Q4) |

## 9. ต้อง validate กับผู้ใช้จริง (design จับไม่ได้)

1. **ช่าง 1–2 คน ดูใบ A5 ที่พิมพ์จริง 30×30 มม. ขาวดำ** — "รู้ไหมว่าชิ้นไหน ตำแหน่งพลอยตรงไหน" (ถ้าไม่พอ = ต้องคิดใหม่ ไม่ใช่แค่ขยาย) · พิมพ์ 3 เคสความสูง (§3.6 ข้อ 5)
2. ช่างเห็นภาพย่อ 80 px มุมขวาบนบนมือถือเครื่องจริง — **ค้นพบเองไหมว่าแตะได้** (ชิป "n รูป" พอหรือไม่)
3. ออฟฟิศถ่ายบนมือถือจริง: ปุ่ม 2 ปุ่มเข้าใจไหม · กล้อง iPhone/Android ส่งไฟล์กลับเร็วพอ (ย่อรูปมือถือรุ่นล่างอาจ 2–5 วินาที/รูป)
4. **ออฟฟิศจะ "ลืมถ่าย" บ่อยแค่ไหน** — ถ้าบ่อย พิจารณาเตือนแรงขึ้น (แต่มติ จ5 รูปไม่ใช่ด่าน — ให้เจ้าของตัดสิน ผมไม่เพิ่มเอง)
5. ขนาดจริงของรูปบนกระดาษ (ข้อ 6 §3.6)
6. ลำดับ "รูปหลักก่อน" ตรงกับที่ช่างอยากเห็นก่อนไหม (รูปตำแหน่งพลอยอาจสำคัญกว่ารูปทรงรวมในบางขั้น)
